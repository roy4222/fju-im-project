### 3.2 密碼與 storageState（放報告目錄外）

```
~/.fju-acceptance/<runId>/            0700；orchestrator 建；跑完（正常結束或 --purge）整個刪
  secrets/night.pw                    0600；一行，24 字元隨機英數（openssl rand -base64 24 | tr -dc 'A-Za-z0-9' | head -c 24）
  state/<session>.json                0600；playwright-cli state-save 存的 storageState；session＝角色工作階段名（admin、s1、t1、v1…）
```

- **誰建**：orchestrator 建目錄與 `night.pw`；codex 在清單要求的時機 `state-save`。
- **誰刪**：orchestrator 在整夜結束時 `rm -rf ~/.fju-acceptance/<runId>`；若中途人為停掉，下次啟動 `--purge` 或超過 48 小時的舊目錄自動刪。
- **怎麼交給 codex**：和 `E2E_ADMIN_PASSWORD` 走**完全同一條路**——環境白名單加 `ACCEPT_PASSWORD`、`ACCEPT_STATE_DIR`、`PLAYWRIGHT_CLI_SESSION`、`ACCEPT_ITEM`；清單寫「填密碼欄用 `"$PWCLI" fill <ref> "$ACCEPT_PASSWORD"`，讓 shell 展開」；洩漏掃描多 grep 這個值（出現就遮蔽、整夜結果標「密碼外洩」並換掉）。
- **報告不寫密碼**；臨時密碼（老師）仍由畫面讀取、當場用掉、不寫報告；若工具重連後遺失，清單規定「回系辦工作階段對那位老師再發一次臨時密碼」（系辦本來就可以做，不算 UX 問題）。
- **session 名稱一律帶項目前綴**（並行時不帶就會兩個 codex 驅動同一個瀏覽器）：每個 `-s=` 名稱與 state 檔名寫成 `${ACCEPT_ITEM}-<角色>`（例如 `story-1-admin`、`story-1-v1`、`ux-visitor-highschool-main`）；`state-save` 存 `$ACCEPT_STATE_DIR/${ACCEPT_ITEM}-<角色>.json`。`ACCEPT_ITEM` 由 orchestrator 以環境給（值＝項目 id）。orchestrator 在每個項目結束後對該前綴的 session 逐一 `"$PWCLI" -s=<名> close`，新手系辦才不會接到第 1 章還沒關掉的瀏覽器。
- **storageState 的用法**：每個角色第一次登入成功後立刻 `"$PWCLI" state-save "$ACCEPT_STATE_DIR/${ACCEPT_ITEM}-<角色>.json"`。之後任何時候 session 死了（playwright-cli 無頭 session **閒置一小時自動關**；第 1 章 `v1` 第 1 步開了、第 37 步才再用，一定已死）就 `open <網址> --idle-timeout=10800000` 再 `state-load`，不重新登入（避免登入限速、避免再依賴密碼）。`open` 是 codex 自己下的指令，orchestrator 碰不到，所以 idle-timeout 是**清單規則**（§7 共通②），不是腳本參數。

### 3.3 orchestrator ↔ `ops/codex-e2e.sh` 的旋鈕（票 A；全部可不設、不設就是舊行為）

| 環境變數 | 意思 |
|---|---|
| `CODEX_E2E_RUN_DIR` | 指定輸出目錄（不再自己用時間戳建）；orchestrator 傳 `RUN_DIR/<item>` |
| `CODEX_E2E_KEEP_SESSION=1` | 不帶 `--ephemeral`，並從 codex 的輸出取得 session id 寫到 `CODEX_E2E_RUN_DIR/codex-session.txt`（實作者查 `codex exec` 開頭的 header 行或 `--json` 事件；兩者都取不到就寫 `unknown`） |
| `CODEX_E2E_RESUME=<session id>` | 改跑 `codex exec resume <id> "<續跑提示>"`（提示固定：「讀 progress.md 最後一行，從下一步繼續；不要重做已完成的步驟；最後一則訊息仍是完整報告」）。**不接受 `last`**：群 1 有三個 codex 並行，`--last` 會接到別人的 session |
| `CODEX_E2E_EXTRA_ENV="ACCEPT_PASSWORD ACCEPT_STATE_DIR PLAYWRIGHT_CLI_SESSION ACCEPT_ITEM"` | 追加進白名單並原值轉交的變數名（值由 orchestrator 以環境給 codex-e2e.sh） |
| `CODEX_E2E_EXTRA_SECRET_FILE=<path>` | 洩漏掃描多掃這個檔的內容（`night.pw`）；命中＝遮蔽＋非 0 結束 |
| `CODEX_E2E_PROMPT_FILE=<path>` | 以這個檔取代內建的「報告格式」段（人設卡與改寫後的劇本自帶格式，內建的那段會和它打架） |
| `CODEX_E2E_MODEL` | 既有；今晚建議 `gpt-6.1-sol`（見待 Roy 決定 R-1） |

逾時、續跑、並行都在 `ops/acceptance-night.sh`，不進 `codex-e2e.sh`。

| 權限提示 | `-s danger-full-access` 非互動，不會有要人按的提示 | full-access 也不提示，但 Paseo daemon 重啟、權限佇列是另一層風險 |
| 逾時／續跑 | 自己做看門狗；`codex exec resume` 可續 | 要靠 agent 自覺或主腦盯 |
| 秘密 | 已有網址白名單、環境白名單、洩漏掃描三道（`codex-e2e.sh:28-37,235-271`） | 要重做一遍 |
| Roy 早上看 | 檔案＋Vault | 要進 Paseo 看對話 |
| 並行 | N 個行程、N 個 session，shell 就能做 | 可以，但每個 agent 都要另外派工 |

結論：今晚**不用 Paseo**；全套由 `launchd` 排程（Mac 睡著錯過會補跑，和備份拉取一樣）。Paseo 的用處只剩「Roy 想在手機上看 run.log」——可以在 Paseo 開一個 terminal 跑同一行指令，不另做整合。

### 6.4 重置測試站的專用 ssh 金鑰（比照 `fjubackup` 的 rrsync 做法）

設計：VM 新帳號 `fjureset`，`authorized_keys` 用 `restrict,command=` 強制只能跑**不帶參數**的 `/usr/local/sbin/fju-test-reset-gate`（和 rrsync 一樣：`command=` 不展開任何東西，由程式自己讀 `SSH_ORIGINAL_COMMAND`）。

- `fju-test-reset-gate`（fjureset 身分、不需 sudo）只做一件事：把 `$SSH_ORIGINAL_COMMAND` 切成字，第一個字必須是 `status|pause-deploy|resume-deploy|reset|snapshot|restore`，`snapshot`／`restore` 的第二個字只准 `[a-z0-9-]{1,32}`，其他一律 `exit 1`；通過後 `exec sudo -n /usr/local/sbin/fju-test-reset "$@"`（切好的字當獨立參數，不再經過 shell，所以 `status; id` 這種寫法進不來）。
- `fju-test-reset`（root 側實際做事）要動 `docker volume rm`、`/srv/fju/test/files`、`sudo -u deploy …`，所以 sudoers **只放行這一支**；gate 不進 sudoers。站名寫死 `test`，任何參數裡出現 `prod` 就拒絕。

子命令（每個＝一次 ssh 連線；VM ufw 限速是 30 秒內第 6 次新連線被拒，所以 30 秒內不超過 5 次）：

| 子命令 | 做什麼 | 對應 README 步驟 |
|---|---|---|
| `status` | 印 commit、auto-deploy 是否暫停、有哪些快照、`/api/health` | — |
| `pause-deploy`／`resume-deploy` | touch／rm `auto-deploy.paused` | 1、收尾 |
| `reset` | backup → down → `docker volume rm fju-test-pgdata` → 清 `/srv/fju/test/files` → 保留 `demo-seed.off` → `deploy.sh --site test <auto-deploy.last 的 SHA> --execute` → `seed-admin.sh test` → 等 health ok | 3、5–10 |
| `snapshot <名稱>` | `backup.sh --site test`＋附件 tar → `/srv/fju/test/snapshots/<名稱>/` | — |
| `restore <名稱>` | 同 reset 但不跑 deploy 的 migrate 後空庫，改灌 dump＋解 tar | — |

> 安裝指令以 `ops/README.md`「重置測試站專用金鑰：安裝與使用」為準（含 visudo 先驗、sshd 5 分鐘還原保險）；下面的區塊是設計草稿，只看結構。

Roy 要貼的（🖥️ VM，sudo 一次；`<PUBKEY>` 換成 Mac 上 `cat ~/.ssh/fju_reset.pub` 的內容）：

```bash
# 💻 Mac 先產金鑰（無密碼；只用來跑重置）
ssh-keygen -t ed25519 -N '' -f ~/.ssh/fju_reset -C fju-reset
cat ~/.ssh/fju_reset.pub

# 🖥️ VM
sudo useradd --system --create-home --home-dir /home/fjureset --shell /bin/sh fjureset
sudo install -d -m 700 -o fjureset -g fjureset /home/fjureset/.ssh
printf 'restrict,command="/usr/local/sbin/fju-test-reset-gate" %s\n' '<PUBKEY>' \
  | sudo tee /home/fjureset/.ssh/authorized_keys >/dev/null
sudo chown root:fjureset /home/fjureset/.ssh/authorized_keys && sudo chmod 640 /home/fjureset/.ssh/authorized_keys
# 兩支腳本進 repo ops/ 後 rsync 上來（gate 給 fjureset 跑、reset 只由 sudo 跑）
sudo install -m 755 -o root -g root /srv/fju/app/ops/fju-test-reset-gate /usr/local/sbin/fju-test-reset-gate
sudo install -m 755 -o root -g root /srv/fju/app/ops/fju-test-reset /usr/local/sbin/fju-test-reset
echo 'fjureset ALL=(root) NOPASSWD: /usr/local/sbin/fju-test-reset' | sudo tee /etc/sudoers.d/60-fju-reset >/dev/null
sudo chmod 440 /etc/sudoers.d/60-fju-reset && sudo visudo -cf /etc/sudoers.d/60-fju-reset
sudo sed -i 's/^AllowUsers gtuser fjubackup$/AllowUsers gtuser fjubackup fjureset/' /etc/ssh/sshd_config.d/10-fju.conf && sudo systemctl reload ssh
```

