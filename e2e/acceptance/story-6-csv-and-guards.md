### 共用規則：工作階段、登入狀態、進度檔（整章都照做）

- **開工前檢查（只檢查、不印值）**：`[ -n "$ACCEPT_PASSWORD" ] && [ -n "$ACCEPT_ITEM" ] && [ -d "$ACCEPT_STATE_DIR" ] && echo ok`。不是 `ok` 就在報告「做不到（環境）」記「缺環境變數」並停止。
- **每個角色一個瀏覽器工作階段**，名稱一律 `${ACCEPT_ITEM}-<角色>`，指令一律用 `-s=` 寫在最前面：
  - 開：`"$PWCLI" -s="${ACCEPT_ITEM}-<角色>" open <網址> --idle-timeout=10800000`——**每次 `open` 都帶 `--idle-timeout=10800000`**。
  - 其他指令：`"$PWCLI" -s="${ACCEPT_ITEM}-<角色>" <指令> …`（例如 `snapshot`、`click <ref>`、`goto <網址>`、`screenshot`、`run-code`）。
- **存登入狀態**：每個角色**第一次登入成功後立刻**存一次：`"$PWCLI" -s="${ACCEPT_ITEM}-<角色>" state-save "$ACCEPT_STATE_DIR/${ACCEPT_ITEM}-<角色>.json"`。
- **工作階段沒有回應就 open 再 state-load，不重新登入**：指令回 `Browser '…' is not open`、逾時、或畫面變成登入頁時：
  1. `"$PWCLI" -s="${ACCEPT_ITEM}-<角色>" open https://test.fju.roy422.dev/ --idle-timeout=10800000`
  2. `"$PWCLI" -s="${ACCEPT_ITEM}-<角色>" state-load "$ACCEPT_STATE_DIR/${ACCEPT_ITEM}-<角色>.json"`
  3. `"$PWCLI" -s="${ACCEPT_ITEM}-<角色>" goto <原本要去的網址>`，接著做原本那一步。
  這是測試環境的事，不算網站問題。state-load 後仍是登入頁：學生可以用自己的 Email＋`$ACCEPT_PASSWORD` 重新登入一次並 state-save；**系辦是唯一例外**，只准用 `E2E_ADMIN_EMAIL`／`E2E_ADMIN_PASSWORD` 再登入一次（整章最多兩次），再失敗就照「失敗時」第一條停止。**例外：第 15 步 s7 被停用後變成登入頁是預期，不要 state-load。**
- **進度檔 `progress.md`**（在目前目錄）：**每做完一步，先 append 一行再做下一步**，格式照「報告格式」的進度檔段。被中斷後續跑時：先讀最後一行，從下一步繼續，不重做已完成的步驟。**第 7、8、14、16 步會改資料：續跑時先看畫面現況再決定要不要做**（例如 `<G2>` 已經是陳建宏就不要再執行第 7 步）。
- **截圖**：每一步做完截圖存 `screenshots/NN-<英文短名>.png`（NN＝兩位數步驟號）。
- **環境問題**（網路斷、逾時、被限速、工具當掉）：**重試一次**；仍失敗就那一步記 `做不到（環境：原因）`、在「做不到（環境）」清單寫一行，**繼續下一步**。不要把環境問題寫進問題清單。

### 下載檔案並打開核對（本章的重點）

網站的匯出按鈕是「按了就下載」。不要只看畫面上的成功訊息：**每個匯出檔都要存下來、用小工具打開**。

1. 存檔：在系辦工作階段用 `run-code` 等下載、按按鈕、存到 `downloads/`（`<按鈕字>` 換成那一步寫的字；`exact: true` 照抄）：
   ```
   "$PWCLI" -s="${ACCEPT_ITEM}-admin" run-code "async page => { const [d] = await Promise.all([page.waitForEvent('download', { timeout: 60000 }), page.getByRole('button', { name: '<按鈕字>', exact: true }).click()]); const p = '$PWD/downloads/' + d.suggestedFilename(); await d.saveAs(p); return p }"
   ```
   回傳值是存好的完整路徑；在「看到什麼」寫檔名（不寫路徑）。按鈕字有變動的數字（例如「匯出全部篩選結果（12 筆）」）時，把 `name: '<按鈕字>', exact: true` 換成 `name: /^匯出全部篩選結果/`。
2. 打開（`inspect` 是「範例檔在哪裡」那三行定義的 shell 函式，同一個指令裡先貼那三行）：`inspect "<上一步回傳的路徑>" --show <欄名,欄名>`。它會印：格式、有沒有 BOM、是不是 UTF-8、欄數與欄名、資料筆數（不含表頭）、每列欄數、有沒有亂碼跡象；`--show` 逐列印出指定欄的值。
3. 判斷照每一步的「預期」：欄名、筆數、指定欄的值。**共通的通過條件**（每個匯出檔都看）：CSV 要有 BOM、是 UTF-8、「每列欄數」只有一個數字而且等於欄數、「亂碼跡象：沒有」；XLSX 要打得開、欄名與筆數和同一份資料的 CSV 一樣、「亂碼跡象：沒有」。學號要是完整九碼（`411000101`，不是 `4.11E+08` 或掉了前面的字），而且「文字欄（學號）不是文字的格：沒有」——XLSX 裡學號存成數字或公式，畫面看起來一樣，但 Excel 會吃掉前導零；工具會列出是哪幾格、最後印「判定：不通過」並以 1 結束，那一步就記 `不通過`（問題清單 `要修`）。
4. 工具印出的內容可能有姓名、學號：「看到什麼」只寫欄數、筆數、你核對的值對不對，**不要把 email 寫進報告**。
5. 下載等不到（逾時）：重試一次；仍不行記 `做不到（環境：下載）`，那一步其餘照判（例如畫面成功訊息）。**每按一次匯出，網站都可能已經產生檔案並留一筆匯出紀錄**（下載沒接到不代表沒匯出）：在「看到什麼」寫「按了幾次匯出」，簽核那兩步的次數第 25 步要用。
