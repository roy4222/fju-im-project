# 驗收清單（給 Codex 在測試站跑）

> **站驗收現在改用 Playwright 直接跑**（Codex 在沙盒裡開不起瀏覽器）。程式在
> [`web/acceptance/`](../../web/acceptance/)，下面「如何在 Mac 跑站驗收」。這裡的白話清單留著當步驟說明。

## 如何在 Mac 跑站驗收（Playwright）

第一次先裝好 Doppler CLI 並 `doppler login`（見 [ops/README.md](../../ops/README.md)「測試站自動驗收」A、D），
再在 repo 根目錄 `pnpm install`、`pnpm -C web exec playwright install chromium`。之後每次（repo 根目錄）：

```bash
doppler run -p fju-im-capstone -c stg --only-secrets E2E_ADMIN_EMAIL,E2E_ADMIN_PASSWORD -- pnpm -C web acceptance
```

只跑某一站：最後加檔名，例如 `... -- pnpm -C web acceptance station-1`。

- **只打測試站** `https://test.fju.roy422.dev`。`ACCEPTANCE_BASE_URL` 可以不設；設成別的網域（包括正式站
  `fju.roy422.dev`）會在設定檔載入時直接失敗，一個請求都不送。
- 帳密只從 `doppler run` 注入的環境變數讀：不印、不寫檔、不進截圖檔名。不開 trace、不錄影、只用 list 報告
  （trace 與 HTML 報告會存下填表的值）。密碼欄一律用 `fillSecret` 填：先確認欄位看得到，填失敗時丟一個不含值的錯誤
  （Playwright 的 call log 會把 fill 的值印出來）。跑完會掃一遍輸出資料夾，出現密碼就刪檔並報錯。
- 每一步的截圖在 `web/acceptance/.out/<時間>/station-N/NN-*.png`（gitignore）。每張截圖都把畫面上的 email
  （帳號列表的 Email 欄、下拉選單、Email 輸入框）塗掉；截圖仍然別貼到公開的地方（姓名、學號看得到）。
- 終端機的 list 報告就是結果：每一行一步，✓ 通過、✘ 失敗；失敗的那一步後面同一站的步驟會跳過。

**跑一次會在測試站留下什麼**

- 第 2 站：一個屆別 `ACC<時間戳>`（含一份 2 人名單）、一個學生、一個老師（姓名以「驗收<數字>」開頭）。
- 第 3 站：一個屆別 `ACC3<時間戳>`（含名單、階段、一個活動、一個組別與繳交紀錄）、4 個學生、2 個老師（姓名以「驗收三<數字>」開頭），
  三個專題事務（標題含屆別代碼）、一個合作案（公司名「驗收三<數字>科技」）。
- 收尾（不論成敗，只認這一輪的前綴）：先還全站狀態（業務鐘、旗標；管理員分頁掛了會重登再還），再收掉這一輪的東西——
  還在待審的申請用「退回」收掉、已核准的學生與老師停用；第 3 站再下架專題事務與合作案（公告與合作案一發布就記下，
  後面哪一步失敗都會下架，公開公告不會留在前台）。後台沒有刪除屆別、組別、繳交紀錄的功能，這些留著；帳號是停用不是刪除。
- 開放註冊與預設工作屆別會暫時移到新屆別；跑完會還給原本的屆別（原本沒有就留在新屆別上）。
- 模擬業務鐘是全站狀態：第 3 站開始時撥回真實時間，跑完還原成跑之前的樣子（原本有模擬偏移就還原偏移，沒有就撥回真實時間；
  紀錄只增不刪，會多幾筆「站驗收」的設定紀錄）。
- 全跑一次註冊 **5 個**帳號（第 2 站 1、第 3 站 4；註冊限速每 IP 每小時 30 次），管理員每站只登入一次
  （登入限速同 IP 同帳號 10 分鐘 10 次）。一小時內最多連跑五次。

## Codex 白話清單（ops/codex-e2e.sh）

這個資料夾也放**給 Codex 看的驗收清單**。每一站做完，照下面的格式寫一份 `station-<N>-<主題>.md`，
在 Mac 上跑：

```bash
ops/codex-e2e.sh e2e/acceptance/station-1-login.md
```

Codex 會用 Playwright skill 在 **https://test.fju.roy422.dev**（測試站）一步一步照做、每步截圖，
最後在 `e2e/acceptance/.out/<時間>-<清單名>/` 留下：

- `report.md`：每一步「通過／不通過」、看到什麼、截圖路徑，最後一行 `總結：通過 N、不通過 M`
- `screenshots/NN-*.png`：每一步的截圖

`.out/` 已經 gitignore，不會進 repo。怎麼設定帳密見 [ops/README.md](../../ops/README.md) 的「測試站自動驗收」。

注意：腳本只會掃出並遮掉**密碼**；E2E 帳號的 **email 會出現在登入頁的截圖裡**（測試專用信箱，可接受，但截圖別貼到公開的地方）。
第一次實跑後，也請照 ops/README.md 看一眼 `~/.codex/log/` 有沒有帶到密碼。

> 跟 `web/e2e/` 不一樣：那裡是 CI 跑的 Playwright 測試程式；這裡是寫給 Codex 看的**白話步驟**，
> 對著真的測試站跑，用來取代 Roy 手動點一遍。

## 清單格式

```markdown
# 第 N 站：<主題>

- 前提：<跑之前測試站要是什麼狀態，例如「已部署含第 N 站的版本」>
- 帳號：E2E 管理員（帳密在環境變數，不要寫在這裡）

## 步驟

1. **<步驟名稱>**
   - 做：<要做什麼，寫到不會誤解：打開哪個網址、點哪個按鈕、填什麼>
   - 預期：<看到什麼才算通過：網址、標題、訊息文字、有沒有某個按鈕>
2. ……

## 失敗時

<某一步不通過要不要繼續；沒寫就是繼續下一步>
```

## 寫清單的規則

- **只寫相對路徑或測試站網址**（`/login`、`https://test.fju.roy422.dev/login`）。
  清單裡出現正式站網址，`ops/codex-e2e.sh` 會直接拒絕執行。
- **不寫帳密**。要登入就寫「用 E2E 管理員登入」；Codex 從環境變數 `E2E_ADMIN_EMAIL`、`E2E_ADMIN_PASSWORD` 取值。
  要測「錯誤密碼」就寫「用錯誤密碼」，Codex 會自己編一個。
- **預期要看得見**：寫畫面上會出現的字（例如標題「系辦首頁」）或網址，不寫「應該正常」這種判斷不了的話。
- **一步一件事**：一步只做一個動作、看一個結果，截圖才對得起來。
- **會改資料的步驟要寫清楚**：Codex 預設不改密碼、不建／停用／刪帳號、不改資料；清單要它做才會做。
  E2E 管理員是測試站共用的帳號，不要在清單裡改它的密碼或停用它。
