## 方法與可信範圍

先讀 Vault 完整產品規格、專案 MOC、0715 會議、0909 相關會議段落與 2026-09-10 三角色分家與畫布評選，再操作瀏覽器。使用原型身分切換和角色路由；桌面 1280×720／1440×900，手機 360×800，抽查淺色與深色。透過點擊、輸入、預覽、送出、回列表及切換組別檢查流程；必要時讀對應原始碼確認空入口。截圖與 DOM 文字保存在 evidence/。

這是操作式探索審查，並非每個路由、欄位排列、瀏覽器與輔助科技的全矩陣驗收。fixtures、cookie 模擬及元件內狀態不能證明 DB 持久化、跨使用者同步、真正 RBAC、郵件送達或正式上線品質。沒有執行 build、效能量測、讀屏器全測、實際附件上傳、正式匯入、刪除、寄信或真實同意。報告中的「送出成功」指原型呈現成功畫面。

優先級：P1＝阻斷核心工作或造成錯誤接受；P2＝明顯影響理解、效率或可操作性；P3＝視覺精修。這是下一輪原型／正式切片的排序，不把假資料問題當作正式服務事故。

## 建議修正順序

先統一一組可串接的 fixture 情境 → 擋下無效送出與分數 → 接通快速建立與完整編輯 → 補齊系辦操作入口 → 改善手機與內容編輯 → 最後調整時間軸及細微動畫。每一輪都用同一個學生組別、同一位老師與同一件事務跨角色核對。
