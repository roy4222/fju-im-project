## 步驟與預期（v3 兩站版）

1. **送檔（Roy 的電腦）**：在最新 main 的 repo 根目錄 `rsync` `docker-compose.yml`、`docker-compose.vm.yml`、`docker-compose.edge.yml`、`ops/` 到 VM 的 `/tmp/fju-app/`。
2. **先看現況**：`sudo bash /tmp/fju-app/ops/vm-setup.sh --check`；預期只印現況與「會執行什麼」，**不寫入任何東西**。
3. **實際設定**：`sudo bash /tmp/fju-app/ops/vm-setup.sh`，做：
   - 套件：Ubuntu 來源的 `docker.io docker-compose-v2 ufw nodejs rsync`；**唯一例外**是 Doppler CLI，加官方簽章 apt 來源（`packages.doppler.com`，金鑰指紋尾碼 `DE2A7741A397C129` 下載後核對，不符即停）。Compose 需 ≥ 2.24（覆蓋檔用 `!reset`），腳本會檢查。
   - `deploy` 帳號加入 docker 群組（不再建 SSH `authorized_keys`：部署不經 GitHub SSH）。
   - 目錄（`install -d`，只設目錄本身、不遞迴）：`/srv/fju/app`（deploy 755）、`/srv/fju/secrets`（deploy 700）、每站 `/srv/fju/<test|prod>/{files（1001:1001 750）,backups（deploy 700）,deploy（deploy 700）}`。資料庫用 named volume `fju-test-pgdata`／`fju-prod-pgdata`，沒有 bind mount，所以不涉及 postgres 映像 uid 70。
   - 防火牆：`ufw limit 22/tcp`、`allow 80/tcp`、`allow 443/tcp`、enable（全部 TCP，與 compose 只發布 TCP 一致）。
   - Docker 網路 `fju-edge`（Caddy 與兩站 app 共用）。
4. **放 app 檔再跑一次**：`sudo rsync -a --delete --chown=deploy:deploy /tmp/fju-app/ /srv/fju/app/`，再 `sudo bash /srv/fju/app/ops/vm-setup.sh`；第二次會安裝並啟用 `fju-auto-deploy.timer`（SOP 03 §自動部署），並用**假值**解析兩站與 edge 的 compose：預期兩站都「沒有發布任何 port」、volume 分別是 `fju-test-pgdata`／`fju-prod-pgdata`，edge「只發布 80、443（TCP）」。
5. **秘密與 GHCR 登入**：依 SOP 02 貼兩把 Doppler token、`deploy` 登入 GHCR、核對鍵值形狀；`vm-setup.sh --check` 的步驟 6、7 變 ✓。
6. **起共用 Caddy**：`sudo -u deploy docker compose -f /srv/fju/app/docker-compose.edge.yml up -d`；預期 log 兩行 `certificate obtained`（`fju.roy422.dev`、`test.fju.roy422.dev`），兩個網址此時回 502（app 尚未部署，正常）。取不到憑證＝停止條件，多半是校方 80／443 未開，存 log 問校方。
7. 記錄 `df -h`、`free -m`、`nproc` 與上列證據；更新 📍 目前進度的 VM 列與查證日期。
