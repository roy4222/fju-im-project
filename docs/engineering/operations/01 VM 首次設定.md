## 步驟與預期

1. `sudo apt update && sudo apt install -y docker.io docker-compose-v2 ufw`；預期 `docker --version` 與 `docker compose version` 都有輸出。**（2026-09-16 修正：原本寫的 `docker-compose-plugin` 是 Docker 官方 repo 的套件名，Ubuntu 24.04 的來源裡叫 `docker-compose-v2`；照原文在乾淨機器上會裝不起來。兩種來源都可行，本專案選「只用 Ubuntu 自己的來源」，不額外加 repo 與 GPG 金鑰。）**
2. `sudo usermod -aG docker $USER` 後重新登入；預期 `docker ps` 不需 sudo。
3. 建目錄 `sudo mkdir -p /srv/fju/{files,tmp,backups,postgres,app,branches}`；擁有者分兩種：`files`／`tmp`／`postgres` 給容器裡的 app 使用者（`web/Dockerfile` 是 **1001:1001**），`app`／`backups`／`branches` 給 `deploy`。**（2026-09-16 修正：原本寫 `chown -R 1000:1000 /srv/fju`——uid 寫錯，而且會把 `deploy` 擁有的 mode-600 `.env` 改成別人的，重跑一次就讓 deploy 讀不到自己的秘密。）**
4. `sudo ufw allow 22,80,443/tcp && sudo ufw enable`；預期只開三個 port。
5. 建 `/srv/fju/app/.env`（600 權限）依 SOP 02 清單填值；`docker login ghcr.io`（只讀 PAT `read:packages`，只存在 VM 的 docker 設定；不放 GitHub Secrets）。
6. 放 `docker-compose.yml`、**`docker-compose.vm.yml`**、`Caddyfile`、`deploy.sh`（來自 repo）；`chmod +x deploy.sh`。放好後先跑一次 `docker compose -f docker-compose.yml -f docker-compose.vm.yml config | grep published`，預期只有 80／443／443（udp），看到 8080 就是覆蓋檔沒被帶上。**（2026-09-16 補：原本的檔案清單漏了 `docker-compose.vm.yml`，照著放會讓步驟 7 沒有覆蓋檔可帶。）**
7. `docker compose -f docker-compose.yml -f docker-compose.vm.yml up -d --no-deps postgres caddy`；預期 Caddy 取得憑證（`docker compose logs caddy` 顯示 certificate obtained）。**（2026-09-16 補：基礎 `docker-compose.yml` 的 caddy 只發布 `8080:80`，那是本機用的；VM 要對外 HTTPS 必須帶 `docker-compose.vm.yml`，它把 ports 取代成 `80:80`、`443:443`。先跑 `docker compose … config` 確認 resolved 結果真的有發布這兩個 port。`--no-deps` 是必要的：caddy 的 `depends_on` 有 app，不加會把 app 與 migrate 一起拉起來，而那時 `.env` 還沒填（SOP 02）。）**
8. 記錄 `df -h`、`free -m`、`nproc` 到證據；更新 📍 目前進度的 VM 列與查證日期。
