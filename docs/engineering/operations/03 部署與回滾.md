# SOP 03｜部署（migrate 先於新程式）與回滾

## 步驟與預期

1. `./deploy.sh <tag>`：取 `flock /var/lock/fju-deploy`（失敗即結束，不排隊）。
2. 記錄目前 app 映像 tag 與 digest 到 `.deploy/previous_tag`。
3. `docker compose pull app worker migrate`。
4. `docker compose run --rm migrate`（新映像、`.env.migrate` 的 owner 連線，執行純 SQL migration）；預期輸出套用的 migration 清單與最後一支名稱（＝預期 `schemaVersion`）；失敗則腳本退出碼非 0，舊 app 仍在服務，不進入步驟 5。
5. `docker compose up -d app worker`（新映像）；停機窗口 10–30 秒。
6. 健康判定迴圈：每 5 秒 `curl -fsS https://fju.roy422.dev/api/health`，60 秒內須同時滿足：HTTP 200；`commit` 等於本次 git sha；`imageDigest` 等於本次 pull 的 digest；`schemaVersion` 等於步驟 4 的最後 migration 名稱；`worker.version` 等於本次；`worker.lastTickAt` 在 60 秒內。任一不符視為失敗（只回 200 不算成功）。
7. 失敗：`docker compose up -d app worker` 回 previous_tag（以 digest 拉）；再跑同樣的健康判定（此時預期 commit／digest 為前一版、schemaVersion 為新值，因 DB 不回滾）；記錄失敗原因與判定輸出；通知 Roy。
8. 成功：寫 `deploy_log`；釋放鎖。
9. 首次部署（空庫）：步驟 4 之後執行 `docker compose run --rm app pnpm seed:a1`（只建 A1，一次性密碼從環境變數，登入後強制改密）。第一次 staging 部署的時點待 Roy（預設 S01 出場後）；在那之前 `cd.yml` 只能 `workflow_dispatch` 且預設 `--dry-run`，不接 Secrets。
10. CD 觸發：合併到 `main` 後由 `cd.yml` build → 推 GHCR → SSH 執行本腳本；本腳本也可由 Roy／Fable 手動執行同樣步驟。
