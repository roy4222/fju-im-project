## 步驟與預期

**每日備份（自動）**：03:00 真實時間 `backup` 服務以 `.env.backup` 的 `fju_backup` 連線 `pg_dump -Fc` → `age`（`AGE_RECIPIENTS` 每個公鑰一個 `-r`）→ `rclone copy` 到 R2（lifecycle 30 天）→ 以 `fju_backup` 連線 INSERT `backup_runs`（唯一寫入通道；成功／失敗、大小、耗時、object_key、收件者數）；本機 `/srv/fju/backups` 保留 7 天（`find -mtime +7 -delete`）。附件只在 volume、不進備份。失敗 → 站內通知管理員＋Roy Email；連續兩日失敗為停止條件。

**還原演練（正式 Gate G6 前至少一次；FIL-05 的最終證據）**：
1. 隔離 override `docker-compose.drill.yml`（演練副本的附件目錄複本與備份時點不一致屬預期：附件無異地備份，既定；報告寫明）：專案名 `fju-drill`、獨立 `PGDATA` 目錄、獨立 DB 名與 port、附件目錄改為副本路徑（`rsync -a files/ /srv/fju/drill-files/`）、`worker` 服務 `profiles: [off]`（不啟動）、`BUSINESS_CLOCK_OVERRIDE_ENABLED` 沿用、通知不指真實通道（Email 延後，本輪無外部通道）。
2. 隔離核對（restore 前）：`docker inspect fju-drill-postgres-1 | jq '.[0].Mounts'` 列出的 mount 不含正式 `PGDATA`／`files`；`psql -c 'SELECT current_database(), inet_server_port()'` 為 drill 值；把輸出存入 `restore_drills.isolation_check`。
3. 從 R2 下載最新備份，`age -d` 解密，`pg_restore` 到 drill 資料庫（owner 連線的 drill 版本）。
4. 以 drill 資料庫啟動 app（不同 port），抽查：A1 可登入、學生帳號關聯、G1 成員、MID1 版本數與 hash、評分採計、簽核 approvals；在 drill 內做一次寫入與一次刪除，然後核對**來源樣本 hash**（正式 DB 的 `submission_versions` 抽樣 hash 與 `files/` manifest）不變。
5. 以 `pnpm ops:record-drill`（app 容器、app 連線）寫 `restore_drills`（時間、備份 object_key、隔離核對、抽查結果、來源樣本 hash 不變、結果）；報告明寫附件只在 volume、不在此備份。
6. `docker compose -p fju-drill down -v`；刪除 drill 附件副本。

**隔離副本（供 Codex 分支 B01–B08；契約 04 §6）**：
1. **checkpoint 與寫入暫停窗口**（v2.1，RR11）：主線 Codex 在指定階段結束後停止操作；Fable `docker compose stop app worker`（staging 主線暫停）；確認 `SELECT count(*) FROM stored_files WHERE status='uploading' AND uploaded_real_at > now() - interval '10 minutes'` 為 0（否則等待或標記為殘留）；記錄業務鐘值與窗口開始時間。
2. **取樣（順序固定）**：`pg_dump -Fc` staging DB 到 `/srv/fju/branches/<runId>.dump` → `rsync -a files/ /srv/fju/branches/<runId>-files/` → 產生 `manifest.json`（dump sha256、檔案清單與 sha256、業務鐘值、commit／digest、窗口起訖時間）。
3. **逐檔核對**：以 dump 內全部 `file_references.released_at IS NULL` 對應的 `stored_files.storage_key`、`checksum`，逐一核對副本目錄檔案存在且 sha256 相符（`pnpm ops:verify-files --dump <dump> --files <dir>`）；任一不符即副本無效、重取；核對結果寫入 manifest。
4. **恢復主線**：`docker compose start app worker`；核對 `/api/health`；主線繼續。
5. 以 `docker-compose.branch.yml`（專案名 `fju-branch-<id>`、獨立 DB 名／port／`PGDATA`、附件目錄指向副本、worker 依劇本需要開關並指向副本、`BUSINESS_CLOCK_OVERRIDE_ENABLED=true`）`pg_restore` 後啟動；啟動後再跑一次逐檔核對；把 URL、port、manifest 交給 Codex。
6. 分支結束：`down -v`、刪副本；核對主線來源樣本 hash 不變並記入 run manifest；分支結果不回填主線。

**worker 停擺**：`/api/health` 的 `worker.lastTickAt` 超過 5 分鐘 → `docker compose logs worker` → `restart`；仍失敗看 advisory lock 是否被殘留連線持有（`pg_locks`）。

**投影失敗（毒事件）**：管理端「投影失敗」列 → 檢視 `last_error` → 修正資料或程式 → 重設 pending → 確認通知出現且不重複。

**磁碟 80%**：清理 `tmp/`（超過 24 小時）與本機備份；檢查 GC 是否運作；仍不足 → 通知 Roy 評估容量（FIL-01b）。

**服務重啟（FIL-06 的最終證據）**：`docker compose restart app worker`；重啟後核對 `/api/health` 四項版本與 `worker.lastTickAt`、上傳目錄權限、最近一筆正式版本可下載、pending 到期工作在重啟後被處理；輸出存為證據。
