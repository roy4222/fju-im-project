## 4. 主線、分支與隔離副本

- 主線 P00–P09：一個 runId、一個版本、只 seed A1，115-TEST 與所有帳號、組別、項目、版本由 UI 產生，最後建 116-TEST；不可中途換 fixture 或塞入已完成資料。
- 分支 B01–B08：各自從主線指定階段的**隔離副本**起算（契約 04 §6）；由 Fable 依 SOP 04「隔離副本」製作：`pg_dump` 副本＋附件目錄複本（manifest hash 相符）＋獨立 Compose override（不同 DB 名、port、附件目錄、worker 指向副本、通知不指真實通道）。結束後丟棄，不回填主線；來源樣本 hash 必須不變。
- 每個分支的 checkpoint 固定：B01←P02、B03←P05、B08←P06、B02／B04／B05←P08、B06／B07←P09；副本製作依 SOP 04「隔離副本」v2.1 的寫入暫停窗口與逐檔核對，manifest 記窗口時間；分支劇本 §2 列出副本內必須新建的帳號與資料（SG1／SG2／TG1、SX1–SX6、FX、C2 發布等），操作人不得臨時補 fixture 或直接改 DB。分支對外入口是插槽 host（`b1`／`b2.fju.roy422.dev`，SOP 04 步驟 5），不是 port；Google 登入（B01）在插槽 host 完成 callback；每個分支、每個角色用獨立瀏覽器 profile；封存後的副本（B06、B07）先解封再做寫入。
- 局部重跑：修復後只重跑受影響案例並記新版本；完整年度通過必須同一版本一次走完。

## 5. 業務鐘操作（staging）

管理員→屆別管理→模擬業務日期：輸入到秒、填原因→儲存（記操作者、真實時間、前後值）。主線持續往前；回撥只在分支 B06。重置：設回真實時間（仍留紀錄）。正式環境沒有此頁（SOP 06 預演證明）。

## 6. worker 與投影操作

管理端「維運」頁：worker 最後 tick、pending／failed 投影數、重設 failed 為 pending。停／啟 worker 與故障注入由 Fable 以 `docker compose stop|start worker` 與測試鉤執行（B06、B07、B08 需要）；Codex 在劇本標記「Fable」的步驟只核對輸出。

## 9. 四欄證據怎麼取

| 欄 | 做法 |
|---|---|
| UI | 截圖＋頁面文字（`innerText`）存 `evidence/<CASE>/ui/` |
| 操作邏輯 | Server Action 回傳 JSON（開發者工具或測試腳本）存 `logic/` |
| 持久化 | 固定五步：儲存→離開頁面→重新載入→另一角色讀取→查歷史；唯讀 SQL 帳號查 `submission_versions` 等並存輸出；檔案 `sha256sum` |
| 授權 | 六種適用者都測：直接請求、跨人、跨組、跨屆、失權、舊版本（`curl` 帶對方 cookie 或缺 cookie）；前後資料 hash |

缺哪一欄寫 NOT_RUN 不寫 PASS。

## 10. 缺陷與重跑

缺陷分級與重跑規則見契約 04 §6–§7；失敗先記案例 ID、版本、業務日期、最後成功步驟、實際結果與證據；分支副本可整個丟棄重建；主線失敗依各劇本第 10 段處理，換版本則主線重新開始。
