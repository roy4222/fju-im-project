# 實作票草稿｜第一批 S00–S02（v0.1，2026-09-13）

> **這是什麼**：spec 基準已定（母 spec v3.6、模組 01 v2.4、02–10 v2.3，PR #7 commit `f974bce`，Codex 判 D1 閉合、無阻止拆票的文件問題）。本文是**票草稿**，給 Roy 與 Codex 審：每張票能否獨立完成、前置是否具備、測試與證據是否足夠。審過並確認對應進場條件後，才在 GitHub 正式開票；開票不等於開工。**不是 ticket 本身**，也不改任何 spec；需求以十份子 spec 與五份契約為準，本文只引用段落。149 案 145 NOT_RUN、4 DEFERRED 不變。
>
> **拆法**：按切片拆、按批次審；十份 spec 用來核對有沒有漏需求，不按模組各做一包（S01 本身就跨模組 01、02 最小屆別、10 最小檔案）。票數依工作大小，不湊配額。共用的 migration／骨架獨立成前置票，避免功能票各自建表；其餘每張票＝一個可觀察結果＋它自己的 schema 增量、用例、入口與測試。

## 0. 完成層次、票欄位、編號

**三個完成層次**（契約 04 §5、切片總圖「切片出場與年度案例 PASS 的分界」）：

| 層 | 意思 | 誰關 |
|---|---|---|
| 單票完成 | 該票的行為做出來、票列的自動測試綠、Fable review、票列的操作證據齊（`steps/<切片>/<票>/`） | Fable 關票；Codex 可抽查 |

**編號**：`E00`–`E14` 是切片 epic；票是 `S00-01`…；依賴寫「前置」欄；同一切片內順序＝建議開工順序。
