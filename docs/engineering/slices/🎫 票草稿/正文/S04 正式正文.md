# S04 正式正文｜專題事務建立與發布、收件名單表（歸 05）、公開前台內容頁

> 本檔是 S04 每張票的「可讀正文層」，票號、順序與 BLOCKED 標記照票草稿；技術九欄由產生器自動附在折疊區，這裡不重貼。環境依切片卡為 staging（未就緒時可用 local 並標明）。測試帳號只寫角色代號：A1 管理員、S01–S05 第一組 G1 成員、T1／T3 老師、訪客（未登入）。本切片用到的項目：N1（公開公告）、R1（登入者資源）、F1（成組前的個人收件，劇本 P03）、MID1（期中組別收件，劇本 P05）。S03 若尚未出場，「指定組別」相關步驟以無組別驗證。

### S04-01 [模組04 專題事務發布與編輯] 建立專題事務六張資料表與收件名單表
- **票型**：foundation
- **這張做什麼**：工程在屆別、業務鐘的資料表之上，再加專題事務用的六張表（項目主檔、指定組別、內容版本、收件欄位版本、附件、發布紀錄）與模組 05 擁有的「收件名單」表。這些表是公告、資源、收件項目從建立到發布、到後面學生填答與名單管理的地基；其中內容版本、欄位版本、發布紀錄三張寫入後不能改、不能刪，之後才能追溯「學生當時看到的是哪一版」。
- **做到哪裡**：本票交付一支建表腳本、三張不可變表的保護、資料庫角色權限與對應的角色測試；空資料庫從頭逐切片升級要成功，資料庫規則要擋掉不合理的組合（例如收件項目卻把受眾設成公開、截止早於開放）。任何畫面與操作都不在本票（頁面殼由 S04-02 起）；學生草稿與正式版本表由 S05 建；截止快照、指定重開等表由 S07／S08 建。本票目前是「工程基礎」。
- **Roy 如何確認**：本票由工程驗證；Roy 在 E04 整體展示確認 CI 的「空庫升級」與「舊資料升版」兩條工作都是綠燈，並看到工程附的七張表結構輸出與「不合理組合被擋下」的反例輸出。Roy 不需要讀 SQL。
- **誰確認**：工程核對。
- **原型畫面**：無原型畫面（待實作畫面）。

### S04-02 [模組04 專題事務發布與編輯] 掛上管理員的專題事務後台與前台公告、規則、資源頁殼
- **票型**：feature
- **這張做什麼**：管理員 A1 登入後，導覽多出「專題事務」：列表頁、新增項目（三步驟對話框的位置）、項目詳情與編輯器的位置；訪客不用登入就能打開前台的「公告」「規則」頁（先是空狀態），「資源」頁要登入才看得到。這張票只把頁面與入口做出來並釘死權限邊界：學生、老師打不開管理員後台，未登入的人被送去登入頁。
- **做到哪裡**：本票交付後台三個路由與導覽項、前台三個路由與公開導覽列、403 帶下一步、空狀態、資源頁的登入邊界。任何項目功能都不在本票：建立與編輯由 S04-03、附件由 S04-04、發布由 S04-05、前台真正顯示已發布內容由 S04-08。公開首頁改版與共用 403 元件統一由 S12。本票目前是「介面預留」。

### S04-03 [模組04 專題事務發布與編輯] 管理員三步驟快速建立項目，或在完整編輯器編輯正文、欄位、受眾與時間
- **票型**：feature
- **這張做什麼**：管理員 A1 要發一則公告或開一個收件，可以用三步驟（選類型→填內容→設發布條件）快速建成草稿；要細調時進完整編輯器：富文字正文、標題摘要、放在哪個區（公告／資源／規則）、給誰看（公開、登入者、本屆學生、老師、指定組別）、是否收件與收件單位（個人或組別）、要學生填的欄位、綁定的屆別與階段、開放與截止時間（到分鐘）。每次儲存都是一個新的草稿內容版本；兩個管理員同時編輯同一項目時，後儲存的人會被要求重新載入，而不是默默覆蓋。貼進正文的危險內容（腳本、外掛框架）會被自動清掉。
- **做到哪裡**：本票交付三步驟對話框、完整編輯器、欄位編輯區、草稿的建立與儲存、列表與詳情可看草稿、富文字清理。附件與封面由 S04-04；發布由 S04-05；已有人作答後改欄位結構或改受眾由 S08-09／S08-10。建收件時受眾選項不出現「全部老師」。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與 S01；要先有測試屆別（本屆，狀態進行中）與至少一個階段；從管理員後台 → 專題事務 → 新增項目。

  | 操作 | 預期看到 |
  |---|---|
  | A1 用三步驟建公告 N1：類型「公告」、標題、受眾「公開」、第三步不發布只存草稿 | 回到列表，N1 出現且狀態「草稿」 |
  | A1 進 N1 完整編輯器，正文貼入含 `<script>` 的 HTML 後儲存 | 儲存成功；重新打開時腳本不見了，一般段落與粗體保留 |
  | A1 用三步驟建收件 MID1：類型「收件」、收件單位「組別」、受眾只列本屆學生／指定組別（沒有「全部老師」）、加兩個欄位、綁階段、設開放與截止 | 儲存成功；詳情顯示欄位、階段與時間 |
  | 把 MID1 截止改成早於開放時間後儲存 | 被拒（VALIDATION_FAILED），提示截止不可早於開放；原設定保留 |
  | 兩個欄位用同一個 key 儲存 | 被拒（VALIDATION_FAILED），提示欄位重複 |
  | A1 在兩個分頁各開一次 MID1 編輯器，第一個儲存後第二個再儲存 | 第二個被拒（CONFLICT），要求重新載入 |
  | 離開頁面再回來，或 A1 重新登入 | N1 與 MID1 的草稿內容與設定仍是最後一次儲存的樣子 |
  | 換 S01 登入，直接對建立項目的請求送出 | 被拒（FORBIDDEN） |
- **誰確認**：工程核對／Roy 畫面操作確認。

### S04-04 [模組10 檔案與服務維運] 管理員在編輯器上傳附件與封面，並依受眾決定誰能下載
- **票型**：feature
- **這張做什麼**：A1 在編輯器裡上傳附件（例如公告的 PDF、正文裡的圖片、封面圖），可以調整順序、移除，移除後想再附回也可以。下載規則跟著項目的受眾走：已發布且受眾公開的附件任何人可下載；登入者、本屆學生、指定組別、老師的附件只有符合身分的人能下；草稿與已下架項目的附件只有管理員能開。下載時瀏覽器一律以「附件」方式接收，不會被當成網頁執行。
- **做到哪裡**：本票交付編輯器附件區（上傳、排序、移除、再附回）、封面與正文圖片、附件下載授權。上傳的類型與大小限制沿用 S01-07 已做好的檔案能力；附件的鎖定與未引用檔案回收由 S07／S12；精選素材的個資核閱由 S12。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1、S01 與訪客；要先有 S04-03 建好的草稿 N1（受眾公開）與一個測試 PDF、一張 PNG；從管理員後台 → 專題事務 → N1 → 編輯器 → 附件區。

  | 操作 | 預期看到 |
  |---|---|
  | A1 上傳 PDF 與 PNG 到 N1 附件區 | 兩個附件出現在列表，可以拖動或按鈕換順序 |
  | 移除 PDF，再從已上傳的檔案把它附回 | 列表恢復兩個附件；離開再回來仍是兩個 |
  | 訪客直接開 N1（仍是草稿）附件的下載網址 | 被拒（401），沒有拿到檔案 |
  | A1 發布 N1 後（S04-05）訪客再開同一下載網址 | 下載成功；回應是「附件」方式，不是在瀏覽器裡當網頁打開 |
  | 把另一項目 R1 受眾設為「登入者」並發布，訪客開其附件 | 被拒（401）；換 S01 登入後可下載 |
  | A1 嘗試把別人上傳、尚未完成的檔案附到 N1 | 被拒（FILE_NOT_READY 或 FILE_NOT_OWNED），附件列表不變 |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：
  ![管理員｜新增項目 第 2 步｜說明、附件、勾要學生交的欄位](<../../../../product/assets/prototype-2026-09-11/admin--affairs-new-step2.png>)
  原型 2026-09-11；正式版差異：附件真的上傳並保存、可排序與移除再附回，下載每次依受眾授權。

### S04-05 [模組04 專題事務發布與編輯] 管理員發布項目：先過發布檢查，發布時同時建好收件名單、排截止並通知
- **票型**：feature
- **這張做什麼**：A1 在項目詳情按「發布」時，系統先做發布檢查（有沒有選放置區、受眾是否為空、收件項目至少要有一個欄位或上傳要求、截止不早於開放、屆別狀態允許、階段存在、指定組別已選），不過就回明確文案而不發布。通過後在同一次處理裡：固定這次發布的內容與欄位版本、記下實際開放時間、建立收件名單（個人收件＝本屆已核准未停用的學生；組別收件＝受眾組別的有效組）、排好截止時的快照工作、發通知（公告給受眾、收件給名單成員）。發布前可以先展開看名單預覽，回執上會寫實際開放時間與名單人數。
- **做到哪裡**：本票交付發布檢查、發布本身、名單建立的最小實作（只建名單列；名單頁與完成率由 S05）、截止快照的排程（真正到期去拍快照由 S08-05）、通知、名單預覽與回執。撤回、下架、重新發布由 S04-06；小幅修改由 S04-07；核准新學生自動進名單由 S08-03。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與 S01；要先有本屆 13 位已核准學生（含 S01）、草稿 F1（個人收件，已有欄位）與草稿 N1（公開公告）；從管理員後台 → 專題事務 → F1 → 詳情。

  | 操作 | 預期看到 |
  |---|---|
  | A1 先把 F1 的欄位全刪掉再按「發布」 | 被拒，文案「新增填寫欄位或上傳要求，或改用公告／資源」；狀態仍是草稿 |
  | 補回欄位、把截止設成早於開放再按發布 | 被拒（VALIDATION_FAILED），提示截止不可早於開放 |
  | 修正時間，展開「名單預覽」 | 列出 13 位本屆已核准學生；已停用者不在裡面 |
  | 按「發布」 | 回執顯示實際開放時間與名單 13 人；狀態變「已發布」 |
  | 換 S01 登入 | 通知匣有一則「新收件 F1」；首頁待辦出現 F1 |
  | 換一位不在本屆的帳號（或未核准者）登入 | 通知匣沒有 F1 |
  | A1 再對 N1 按發布 | 回執成功；受眾收到「公告發布」通知 |
  | A1 離開再回來、重新登入 | F1 與 N1 都是已發布，實際開放時間沒有變 |

### S04-06 [模組04 專題事務發布與編輯] 管理員撤回、下架或重新發布項目，開放時間不因重新發布而重設
- **票型**：feature
- **這張做什麼**：A1 發布後發現弄錯，在還沒有任何人作答前可以「撤回」回草稿修改；已經不需要的項目可以「下架」；下架後又要用時「重新發布」，實際開放時間仍是第一次發布的那一刻，不會被重設。每個動作都留一筆發布紀錄並發事件；學生的列表與前台會立刻看不到（或恢復看到）。已經有人作答的項目不能撤回，只能下架。
- **做到哪裡**：本票交付撤回、下架、重新發布三個動作、詳情頁按鈕與回執、發布紀錄、事件。前台下架後打開網址的 404／403 帶下一步、以及快取失效的呈現由 S04-08；「是否有人作答」在本切片先用固定值驗證（S05 才有真實回答）。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與 S01；要先有已發布的 N1（公告）與已發布、尚無回答的 F1；從管理員後台 → 專題事務 → 項目詳情。

  | 操作 | 預期看到 |
  |---|---|
  | A1 在 F1 詳情按「撤回」 | 回執；狀態回「草稿」；換 S01 登入時作業區看不到 F1 |
  | A1 再對 F1 按發布 | 狀態「已發布」；詳情上的實際開放時間與第一次相同 |
  | A1 在 N1 詳情按「下架」 | 狀態「已下架」；前台公告列表不再有 N1 |
  | A1 對 N1 按「重新發布」 | 狀態「已發布」；實際開放時間仍是第一次的時間；發布紀錄依序有發布、下架、重新發布三筆 |
  | 對草稿狀態的項目按「下架」，或對已發布的項目再按「重新發布」 | 被拒（VALIDATION_FAILED） |
  | 工程用測試把 F1 標成「已有回答」後 A1 按撤回 | 被拒（ITEM_HAS_RESPONSES），只能下架 |
  | 離開再回來 | 狀態與三筆紀錄不變 |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：無原型畫面（待實作畫面）。

### S04-07 [模組04 專題事務發布與編輯] 管理員小幅修改已發布內容並自選是否通知；有人作答後收件單位鎖定
- **票型**：feature
- **這張做什麼**：已發布的公告或收件要改錯字、補一句說明，A1 在編輯器修改後儲存，系統產生新的內容版本並留一筆修改紀錄；儲存時 A1 自己勾要不要通知受眾，勾了才發一則通知，沒勾就安靜更新。另外，一旦有人作答，「收件單位」（個人或組別）就不能再改，編輯器會顯示鎖定，直接送請求改值也會被擋。
- **做到哪裡**：本票交付已發布項目的修改分支、通知勾選、修改紀錄、內容版本可切換檢視、收件單位鎖定的顯示與判定。有人作答後改欄位結構或改受眾的影響預覽由 S08-09／S08-10；改期由 S08-08。「是否有人作答」在本切片先用固定值驗證。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與 S01；要先有已發布的 MID1；從管理員後台 → 專題事務 → MID1 → 編輯器。

  | 操作 | 預期看到 |
  |---|---|
  | A1 改正文一個錯字，不勾「通知」，儲存 | 回執；詳情顯示新的內容版本；換 S01 登入時通知匣沒有新通知 |
  | A1 再改一次，勾「通知受眾」，儲存 | 回執；S01 通知匣多一則「內容更新」 |
  | 在詳情切換內容版本 | 可以看到修改前後兩個版本的正文 |
  | 工程把 MID1 標成「已有回答」後 A1 打開編輯器 | 「收件單位」欄位顯示鎖定，不能改 |
  | 直接送請求把收件單位從組別改成個人 | 被拒（VALIDATION_FAILED） |
  | 用舊資料再儲存一次 | 被拒（CONFLICT），要求重新載入 |
  | 離開再回來 | 最新內容版本與兩筆修改紀錄仍在 |
- **誰確認**：工程核對／Roy 畫面操作確認。

### S04-08 [模組09 公開展示與共用介面] 訪客在前台看到已發布的公告與規則，登入者看到資源；下架後打開網址會被告知下一步
- **票型**：feature
- **這張做什麼**：訪客不用登入就能在前台「公告」看到已發布的公告（分類、置頂、搜尋沿原型）、點進去看全文與附件，也能看「規則」頁；登入的人多看到「資源」頁。頁面內容有快取，發布、撤回、下架、重新發布、小幅修改之後，下一次造訪就會更新。已下架或撤回的公告如果有人還留著網址，打開會看到「找不到／無法存取」並附「回公告列表」；訪客打開收件項目的網址會被導去登入。公開頁面裡不會出現任何人的 Email、手機或學號。
- **做到哪裡**：本票交付公告列表與內文、規則頁、資源頁、快取與失效、404／403 帶下一步、訪客邊界、公開頁個資掃描測試。精選作品、OG、sitemap、公開首頁改版由 S12；產學頁由 S06。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用訪客（不登入）、S01 與 A1；要先有已發布的 N1（公開公告，有附件）、R1（登入者資源）、已發布的 F1（個人收件）；前台從公開導覽列 → 公告。

  | 訪客開「公告」列表 | 看到 N1；草稿與已下架的項目不在列表 |

### S04-09 [模組08 站內通知與日曆] 學生首頁行事曆顯示屆別活動與收件截止
- **票型**：feature
- **這張做什麼**：學生 S01 打開首頁時，行事曆上同時看到本屆的活動（例如說明會、期中發表）與自己看得到的收件項目截止日（顯示到分鐘），一眼知道接下來要做什麼；不是給他看的項目（受眾外）不會出現，已下架的也不會出現。手機上先顯示近期三筆、可展開整月。原型的「訂閱到 Google 日曆」按鈕拿掉。
