# S07 正式正文｜組別共用草稿、上傳／下載、正式送出、歷史、老師矩陣（主線終點）

> 本檔是 S07 每張票的「可讀正文層」，票號、順序與 BLOCKED 標記照票草稿；技術九欄由產生器自動附在折疊區，這裡不重貼。環境依切片卡為 staging（未就緒時可用 local 並標明）。測試帳號只寫角色代號：A1 管理員、S01–S05 第一組 G1 成員（主指導 T1）、S06／S07 第二組 G2 成員（主指導 T2）、G3（主指導 T3）、SU1 尚未成組的學生、T1／T2／T3 老師、訪客（未登入）。收件項目：MID1（E04 發布的期中組別收件，附件規則 PDF 不超過 20 MiB）、F1（E05 的個人收件）。G1／G2／G3 與主指導由 E03、E06 產生。

### S07-01 [模組05 個人與組別繳交] 建立繳交附件表、主指導閱覽設定表與檔案回收用索引
- **票型**：foundation
- **這張做什麼**：工程在 S05 的草稿與正式版本表之上，再加兩張只寫不改的表：「繳交附件」（某個正式版本當時附了哪些檔、檔案校驗值）與「主指導閱覽設定」（某個個人收件從第幾版起開放主指導看，S08 才會用到）；另外替檔案表加上之後回收未引用檔案要用的索引。這些是組別繳交附件、下載授權鏈與檔案回收的地基。
- **做到哪裡**：本票交付一支建表腳本、索引、不可變保護、資料庫角色權限與對應的角色測試；空資料庫從頭逐切片升級要成功。任何畫面與操作都不在本票（頁殼由 S07-02 起）；截止快照、指定重開等表由 S08-01；主指導閱覽設定的操作由 S08-13。本票目前是「工程基礎」。
- **Roy 如何確認**：本票由工程驗證；Roy 在 E07 整體展示確認 CI 的「空庫升級」與「舊資料升版」兩條工作都是綠燈，並看到工程附的兩張表結構輸出與「寫入後不能改」的反例輸出。Roy 不需要讀 SQL。
- **誰確認**：工程核對。
- **原型畫面**：無原型畫面（待實作畫面）。

### S07-02 [模組05 個人與組別繳交] 掛上組別繳交頁的四個區塊與老師繳交矩陣的頁殼
- **票型**：feature
- **這張做什麼**：G1 組員打開組別收件 MID1 時，看到組別版內容頁：共用草稿表單區、上傳區、收件章回執區、繳交歷史分頁四個區塊的位置，以及「本項目由全組共用一份草稿，任何組員正式送出即代表全組」的告知；老師導覽多出「繳交矩陣」（先是空狀態）。這張票只把頁面與入口做出來並釘死權限邊界：他組學生打開會看到「無法存取，回到你的組別」；還沒成組的學生看到「需先成立組別」且沒有送出入口；未登入的人被送去登入頁。
- **做到哪裡**：本票交付組別版頁殼（依項目的收件單位自動分流，個人版沿用 S05）、四個掛載點、老師矩陣路由與導覽項、三種空狀態與 403 文案。草稿由 S07-03、上傳由 S07-04、送出由 S07-05、矩陣內容由 S07-08；矩陣的個人收件欄由 S08-13。本票目前是「介面預留」。
- **Roy 如何確認**：staging（或 local）；用 S01（G1）、S06（G2）、SU1（未成組）、T1、A1 與訪客；要先有 E04 發布的 MID1 與 E03／E06 的組別與主指導；從學生後台 → 作業區 → MID1。

  | 操作 | 預期看到 |
  |---|---|
  | S01 打開 MID1 | 組別版頁：四個區塊的殼與「全組共用一份草稿…」告知 |
  | 換 S06 登入，直接開 G1 的 MID1 網址 | 「無法存取，回到你的組別」並有回自己組別的連結（FORBIDDEN） |
  | 換 SU1 登入打開 MID1 | 空狀態「需先成立組別」，沒有送出入口 |
  | 登出，直接開 MID1 網址 | 被導到登入頁，登入後回到原網址 |
  | 換 T1 登入 → 導覽「繳交矩陣」 | 頁面打開，空狀態「尚無指導組別」 |
  | 換 S01 登入，直接開繳交矩陣網址 | 被拒（FORBIDDEN） |
  | 換 A1 登入打開 MID1 | 只讀的組別版殼 |
- **誰確認**：工程核對／Roy 畫面操作確認。

### S07-03 [模組05 個人與組別繳交] 全組共用一份草稿，任一組員儲存其他人都看得到；兩人同時改會被要求重新載入
- **票型**：feature
- **這張做什麼**：G1 的 S01 在 MID1 填寫後按「儲存草稿」，右下顯示「已儲存 hh:mm:ss（伺服器時間）」；S02 打開同一頁看到的就是 S01 剛存的內容——整組只有一份草稿。S01 與 S02 同時各改一版，先存的成功，後存的看到「別人已更新，你的輸入保留在本機」並顯示差異，重新載入後可以合併再存。不是本組的人（例如 G2 的 S06）直接送請求會被拒。
- **做到哪裡**：本票交付組別版儲存草稿與讀取（此刻有效組員可寫、管理員可讀）、表單區、衝突差異顯示、伺服器時間顯示。上傳由 S07-04；送出由 S07-05；欄位結構改版後的需檢視差異畫面由 S08-09；個人版草稿是 S05 做的。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01、S02（G1）、S06（G2）；要先有已發布且開放中的 MID1；從作業區 → MID1。

  | 操作 | 預期看到 |
  |---|---|
  | S01 填兩個欄位（必填留一個空）按「儲存草稿」 | 右下「已儲存 hh:mm:ss（伺服器時間）」；沒有因必填空而被擋 |
  | 換 S02 登入打開 MID1 | 看到 S01 剛存的內容 |
  | S01 與 S02 各開一個視窗，S01 先存，S02 再存 | S02 看到「別人已更新，你的輸入保留在本機」（CONFLICT）與差異；S02 重新載入後把自己的內容補上再存成功 |
  | 換 S06（G2）登入，直接送請求儲存 G1 的 MID1 草稿 | 被拒（NOT_MEMBER）；G1 的草稿不變 |
  | S06 直接請求讀取 G1 的草稿 | 被拒（FORBIDDEN） |
  | S01 打開尚未開放的項目直接請求儲存 | 被拒（ITEM_NOT_OPEN） |
  | S01 登出再登入，打開 MID1 | 內容與最後一次儲存相同 |
- **誰確認**：工程核對／Roy 畫面操作確認（兩人同版恰一成功由整合測試證明）。
- **原型畫面**：
  ![學生｜儲存草稿後｜右下狀態變已儲存](<../../../../product/assets/prototype-2026-09-11/student--affairs-draft-saved.png>)
  原型 2026-09-11；正式版差異：草稿真的全組共用、儲存帶伺服器時間、同版競爭回 CONFLICT 並顯示差異保留輸入。

### S07-04 [模組10 檔案與服務維運] 組員上傳繳交檔案並附到草稿：合法的收、偽裝與超限的擋、中斷的留給回收
- **票型**：feature
- **這張做什麼**：組員在 MID1 上傳區選 PDF，看得到進度條，完成後得到含校驗值的回執，檔案附到全組草稿上；可以移除，移除後再附回也可以。傳 25 MiB 的檔會被擋「檔案過大」；把 EXE 改名成 .pdf 會被擋「檔案類型不符」並清掉暫存；傳到一半斷線顯示「上傳中斷，請重新上傳」，殘留檔之後由回收工作清（本切片只排程、不真的清）。別組成員上傳的檔、還沒傳完的檔，都不能附到本組草稿。
- **做到哪裡**：本票交付繳交用途的上傳票證與上傳區、三種錯誤提示、附掛與移除（含再附回）、回收與附掛同時發生時的正確順序、回收工作的排程用例。真正的回收處理由 S12；送出時把附件釘到正式版本由 S07-05；下載由 S07-06；管理員的公告附件是 S04-04 做的。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01（G1）、S06（G2）；要先有 MID1（PDF ≤ 20 MiB）與 G1 草稿；準備一個 20 MiB 以內的 PDF、一個 25 MiB 的 PDF、一個改名成 .pdf 的 EXE；從作業區 → MID1 → 上傳區。

  | 操作 | 預期看到 |
  |---|---|
  | S01 上傳合法 PDF | 進度條跑完；回執顯示檔名、大小、校驗值；附件出現在草稿上 |
  | S01 上傳 25 MiB 的 PDF | 被拒「檔案過大」（FILE_TOO_LARGE）；草稿附件不變 |
  | S01 上傳改名成 .pdf 的 EXE | 被拒「檔案類型不符」（FILE_TYPE_REJECTED） |
  | 上傳到一半中斷網路 | 顯示「上傳中斷，請重新上傳」；重新上傳可成功 |
  | S01 移除附件，再從已上傳的檔案附回 | 附件列表恢復；離開再回來仍在 |
  | 換 S06 上傳一個檔，再換 S01 直接請求把 S06 的檔附到 G1 草稿 | 被拒（FILE_NOT_OWNED） |
  | S01 直接請求附掛一個還在上傳中的檔 | 被拒（FILE_NOT_READY） |
- **誰確認**：工程核對／Roy 畫面操作確認（回收與附掛對撞由整合測試證明）。
- **原型畫面**：無原型畫面（待實作畫面）。

### S07-05 [模組05 個人與組別繳交] 任一組員代表全組正式送出，拿到收件章回執，其他組員收到通知
- **票型**：feature
- **這張做什麼**：G1 的 S03 按「正式送出」，系統依固定順序把關：是不是有效組員、屆別與組別是否仍有效、項目是否開放且未截止、草稿是否需要檢視、必填是否填齊、附件是否都是本組且已上傳完成、草稿版本是否最新；任一關沒過就回明確原因。通過後留下不可變的「版本 1」——連當時的成員名單、主指導、附件校驗值一起釘住——並給收件章回執（版本、接收時間、送出者、操作編號）；其他有效組員各收到一則「已繳交」通知（送出者本人與老師不收）。連點只算一次；斷線後顯示「結果尚未確認」可查回執。
- **做到哪裡**：本票交付組別版正式送出、版本與附件紀錄、收件章回執區、通知事件、截止後對帳工作的排程（真正對帳由 S08-06）、結果未知與查回執。重送與歷史由 S07-07；下載由 S07-06；解散時凍結由 S09；指定重開的個別期限由 S08-07（本票先以「沒有個別期限」實作介面）。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S03、S01（G1）、S06（G2）、T1；要先有 G1 已儲存草稿並附好 PDF 的 MID1（截止設在 23:59）；推鐘由工程提供的業務鐘工具；從作業區 → MID1。

  | 操作 | 預期看到 |
  |---|---|
  | S03 必填留空按「正式送出」 | 被拒，提示必填未填（VALIDATION_FAILED）；沒有版本產生 |
  | 補齊後按「正式送出」 | 收件章回執：版本 1、接收時間、送出者 S03、操作編號；作業區狀態「已送出 v1」 |
  | 換 S01 登入 | 通知匣有一則「MID1 已由 S03 繳交」；作業區同樣顯示已送出 v1 |
  | 換 T1 登入 | 通知匣沒有繳交通知（老師用矩陣看） |
  | 換 S06（G2）登入，直接送請求以 G1 身分送出 | 被拒（NOT_MEMBER） |
  | S03 快速連點「正式送出」兩下（有新草稿時） | 只多一個版本；兩次回執相同 |
  | 工程模擬送出後回應中斷，S03 按「查詢結果」 | 顯示原本的收件章回執 |
  | 推鐘到 00:00:00（截止分鐘已過），S03 用舊頁再送 | 被拒「截止 …23:59 已過」（DEADLINE_PASSED） |
- **誰確認**：工程核對／Roy 畫面操作確認（epic 項：Roy 看繳交與回執）。
- **原型畫面**：
  ![學生｜已繳 v1 可重送｜以最後一次為準](<../../../../product/assets/prototype-2026-09-11/student--dashboard-student-affairs-mi-013.png>)
  原型 2026-09-11；正式版差異：收件章回執含版本、接收時間、送出者、操作編號；守門固定順序；送出時釘住成員名單、主指導與附件校驗值；其他組員收站內通知。

### S07-06 [模組10 檔案與服務維運] 繳交附件只有本組有效組員、目前主指導與系辦能下載
- **票型**：feature
- **這張做什麼**：G1 送出的 PDF，S02（本組組員）、T1（目前主指導）、A1 都能下載，下載時瀏覽器以「附件」方式接收、內容與送出時的校驗值一致。訪客會得到 401；不是主指導的 T3、他組的 S06 就算猜到網址也只會看到「無法存取」。被移出的人只能下載自己還在組裡時送出的版本附件。主指導換人後，原老師立刻下載不到，新老師立刻可以。每次下載都重新確認身分並留紀錄。
- **做到哪裡**：本票交付繳交用途檔案的下載授權規則、下載處理分支、校驗值驗證、下載紀錄。受指派評分老師的下載由 S10；解散後閱覽由 S09；公告與資源附件是 S04-04 做的。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S02、S06、T1、T3、A1 與訪客；要先有 G1 已送出版本 1（含 PDF）的 MID1；從作業區 → MID1 → 繳交歷史 → 附件。

  | 操作 | 預期看到 |
  |---|---|
  | S02 點附件下載 | 下載成功，以附件方式接收；工程比對校驗值與送出時一致 |
  | 換 T1 登入 → 繳交矩陣（或直接開同一下載網址） | 下載成功 |
  | 換 A1 登入開同一下載網址 | 下載成功 |
  | 登出，直接開下載網址 | 被拒（401） |
  | 換 T3 登入，直接開下載網址 | 「無法存取」（FORBIDDEN） |
  | 換 S06（G2）登入，直接開下載網址 | 「無法存取」（FORBIDDEN） |
  | A1 把 G1 重派給 T3（S06-06）後，T1 與 T3 各開下載網址 | T1 被拒；T3 下載成功 |
  | 工程把 S05 模擬為已移出後，S05 開版本 1 附件與移出後新版本的附件 | 版本 1 可下載；新版本被拒 |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：無原型畫面（待實作畫面）。

### S07-07 [模組05 個人與組別繳交] 組員重送新版本，版本 1 不動；全組、主指導、系辦看到同一份歷史，名單頁算組別完成率
- **票型**：feature
- **這張做什麼**：S01 改內容、換附件後再正式送出，就是版本 2；版本 1 的內容與附件原封不動。繳交歷史分頁列出第幾次、送出者、接收時間、欄位版本、附件（可看內容、可下載）；S02、T1、A1 各自打開看到同樣的兩版。管理員在項目詳情可以「檢視某組 vN」。名單頁對組別收件以「符合資格的組別」為單位算完成率（G1、G2 送出後顯示 2／3，同組五人送出不算五份）。每次正式送出，其他有效組員通知匣多一則「已繳交」。
- **做到哪裡**：本票交付重送（沿用 S07-05）、學生與管理員的歷史與版本檢視、組別完成率、通知投影的驗證。老師矩陣頁由 S07-08；本人唯讀頁由 S07-09；完成率徽章與首頁待辦數字一致由 S08；評分老師檢視由 S10。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01、S02（G1）、S06（G2）、T1、T3、A1；要先有 G1 已送出版本 1 的 MID1，G2 尚未送出，G3 不送；從作業區 → MID1。

  | 操作 | 預期看到 |
  |---|---|
  | S01 改一個欄位、換一個 PDF 後「正式送出」 | 回執版本 2；繳交歷史列出版本 1、2，版本 1 內容與附件沒變 |
  | 換 S02 登入 → MID1 繳交歷史 | 同樣兩版；通知匣多一則「已由 S01 繳交（v2）」 |
  | 換 T1 登入 → 繳交矩陣 → G1 | 同樣兩版與附件 |
