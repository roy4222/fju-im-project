# S05 正式正文｜個人收件：草稿、送出、版本、名單頁、完成率

> 本檔是 S05 每張票的「可讀正文層」，票號、順序與 BLOCKED 標記照票草稿；技術九欄由產生器自動附在折疊區，這裡不重貼。環境依切片卡為 staging（未就緒時可用 local 並標明）。測試帳號只寫角色代號：A1 管理員、S01–S13 本屆 13 位已核准學生（S09 為劇本 P03 的個人收件者）、T1 老師、他屆學生 SY1、訪客（未登入）。本切片用到的項目：F1（E04 已發布的個人收件，名單 13 人）、FINAL1（開放時間設在未來的測試項目）。免填與移出的「寫入」在 S08，本切片只驗顯示（出場時由工程直接設旗標）。

### S05-01 [模組05 個人與組別繳交] 建立學生草稿與正式送出版本兩張資料表
- **票型**：foundation
- **這張做什麼**：工程在 S04 的專題事務表之上，再加兩張表：「草稿」（每人每項目一份、可以一直改）與「正式送出版本」（每次正式送出留一筆，寫入後不能改、不能刪）。這兩張表是學生填答、送出、重送、歷史、以及管理員看完成率的地基；正式版本不可變，之後才說得清「學生第幾次送了什麼」。
- **做到哪裡**：本票交付一支建表腳本、正式版本表的不可變保護、資料庫角色權限與對應的角色測試；空資料庫從頭逐切片升級要成功，資料庫規則要擋掉同一人同一項目第二份草稿、重複的版本號。任何畫面與操作都不在本票（頁殼由 S05-02 起）；組別附件表由 S07 建；截止快照、指定重開等表由 S07／S08 建。本票目前是「工程基礎」。
- **Roy 如何確認**：本票由工程驗證；Roy 在 E05 整體展示確認 CI 的「空庫升級」與「舊資料升版」兩條工作都是綠燈，並看到工程附的兩張表結構輸出與「正式版本不能被改」的反例輸出。Roy 不需要讀 SQL。
- **誰確認**：工程核對。
- **原型畫面**：無原型畫面（待實作畫面）。

### S05-02 [模組05 個人與組別繳交] 掛上學生作業區、個人內容頁、本人繳交歷史與管理員名單分頁的頁殼
- **票型**：feature
- **這張做什麼**：學生 S01 登入後，導覽多出「作業區」與「我的繳交」，作業區裡每個項目有自己的內容頁（表單區、儲存與送出按鈕區、繳交歷史分頁的位置）；管理員 A1 的項目詳情多一個「名單」分頁的位置。這張票只把頁面與入口做出來並釘死權限邊界：未登入的人被送去登入頁，老師打不開學生的作業區，管理員可以看內容頁。
- **做到哪裡**：本票交付三個學生路由與導覽項、內容頁三個掛載點、管理員名單分頁掛載點、授權導向、空狀態文案。任何資料讀寫都不在本票：清單與內容讀取由 S05-03、儲存由 S05-04、送出由 S05-05、歷史由 S05-07、名單頁本體由 S05-08；組別版內容頁與老師矩陣由 S07。本票目前是「介面預留」。
- **Roy 如何確認**：staging（或 local）；用 S01、T1、A1 與訪客（不登入）；要先有 E04 出場的資料（已發布的 F1）；從學生後台導覽 → 作業區。

  | 操作 | 預期看到 |

  | S01 登入，導覽點「作業區」 | 頁面打開，顯示空狀態文案（尚未接資料） |

### S05-03 [模組05 個人與組別繳交] 學生在作業區看到自己該交的項目與狀態，打開內容頁看到要填的欄位

### S05-04 [模組05 個人與組別繳交] 學生儲存草稿，重新登入後還在；兩邊同時改會被要求重新載入
- **票型**：feature
- **這張做什麼**：S01 在 F1 內容頁填到一半按「儲存草稿」，右下角顯示「已儲存 hh:mm:ss（伺服器時間）」；登出再登入、或重新整理，填的內容都還在。儲存時系統會檢查答案型別（例如單選不能選不存在的選項），但必填空著可以先存，只有正式送出才擋。如果同一份草稿在兩個視窗各改一次，後儲存的那個會被告知「別人已更新，你的輸入保留在本機」，不會默默覆蓋。儲存失敗會顯示錯誤，不會假裝成功。
- **做到哪裡**：本票交付儲存草稿的用例與守門（本人、名單內非免填、屆別進行中、項目已開放且未截止）、答案型別驗證、草稿表單的儲存狀態與衝突顯示。正式送出由 S05-05；附件由 S07；欄位結構改版後的草稿遷移由 S08。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01 與 S02；要先有已發布且開放中的 F1；從作業區 → F1。

  | 操作 | 預期看到 |
  |---|---|
  | S01 填兩個欄位（必填留一個空）按「儲存草稿」 | 右下角「已儲存 hh:mm:ss（伺服器時間）」；沒有因必填空而被擋 |
  | S01 登出再登入，打開 F1 | 剛才填的內容都在 |
  | S01 在兩個分頁各開 F1，分頁一改後儲存，分頁二再改後儲存 | 分頁二顯示「別人已更新，你的輸入保留在本機」（CONFLICT）；分頁二的輸入還留在畫面上 |
  | 用直接請求送一個不存在的單選選項 | 被拒（SCHEMA_INVALID），草稿不變 |
  | 換 S02 登入，直接請求以 S01 的身分儲存 F1 草稿 | 被拒（FORBIDDEN）；S01 的草稿內容不變 |
  | S01 打開尚未開放的 FINAL1 直接請求儲存 | 被拒（ITEM_NOT_OPEN） |
  | 工程模擬儲存失敗（斷線） | 畫面顯示錯誤，不顯示「已儲存」 |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：

### S05-05 [模組05 個人與組別繳交] 學生正式送出個人收件，拿到收件章回執；有回答後項目不能再撤回
- **票型**：feature
- **這張做什麼**：S01 填完後按「正式送出」，系統依固定順序把關：是不是本人且在名單內、屆別是否仍進行中、項目是否已開放且未截止、草稿是否需要檢視、必填是否都有填、草稿版本是否最新；任何一關沒過就回明確原因，過了就留下不可變的「版本 1」並給收件章回執（版本、接收時間、送出者、操作編號）。截止時間「含此分鐘」：23:59:59 送到算準時，00:00:00 就算逾期，以伺服器收到的時間為準。同時，項目一旦有人送出，管理員在 S04 做的「撤回」與「改收件單位」就會真的被擋下來。
- **做到哪裡**：本票交付正式送出用例、版本紀錄、收件章回執、送出後清單狀態變「已送出 v1」、截止後對帳工作的排程（真正對帳由 S08-06）、以及讓 S04 的「是否有回答」判斷改讀真實資料。重送、連點與結果未知由 S05-06；歷史由 S05-07；附件與組別版由 S07；快照與指定重開由 S08。個人送出不發通知（沒有其他組員可收）。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01、S02、A1；要先有已發布、開放中、截止設在 23:59 的 F1，S01 有已儲存草稿；推鐘由工程提供的業務鐘工具；從作業區 → F1。

  | 操作 | 預期看到 |
  |---|---|
  | S01 必填留空按「正式送出」 | 被拒，提示必填未填（VALIDATION_FAILED）；沒有產生版本 |
  | 補齊後按「正式送出」 | 收件章回執：版本 1、接收時間、送出者 S01、操作編號；作業區狀態變「已送出 v1」 |
  | S01 登出再登入，打開 F1 | 仍顯示已送出 v1，內容與剛才相同 |
  | 換 A1 登入 → F1 詳情按「撤回」 | 被拒（ITEM_HAS_RESPONSES）；「收件單位」在編輯器顯示鎖定 |
  | 換 S02 登入，直接請求以 S01 的身分送出 | 被拒（FORBIDDEN） |
  | S01 打開尚未開放的 FINAL1 直接請求送出 | 被拒（ITEM_NOT_OPEN），沒有產生版本 |
  | 推鐘到 F1 截止分鐘的 23:59:59，S03 送出 | 成功，算準時 |
  | 推鐘到 00:00:00，S04 送出 | 被拒，顯示「截止 …23:59 已過」（DEADLINE_PASSED） |
- **誰確認**：工程核對／Roy 畫面操作確認。

### S05-06 [模組05 個人與組別繳交] 學生截止前可以重送，連點只算一次，斷線後可查結果不會誤以為沒送出
- **票型**：feature
- **這張做什麼**：S01 送出後發現要改，截止前再送一次就是版本 2，版本 1 原封不動保留，畫面與名單頁顯示最新的版本 2。送出時手抖連點兩下，系統只會留一個版本、第二次回同一張回執。網路中斷、送出後沒收到回應時，畫面顯示「結果尚未確認」和「查詢結果」按鈕：查到回執就顯示原本的收件章；查不到才允許用同一個操作編號重送；回執已過期就顯示結果參照。畫面永遠不會誤說「未送出」。
- **做到哪裡**：本票交付重送（沿用 S05-05 的送出用例，版本加一）、送出按鈕的操作編號生命週期與連點處理、「結果尚未確認」與查詢結果的三種分支、內容變了卻沿用舊操作編號的「這筆操作已用不同內容送出過」提示。截止後重送與指定重開由 S08；組別版由 S07；回執 30 天清除的到期工作由 S12。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01 與 S02；要先有 S01 已送出版本 1 的 F1（截止未到）；從作業區 → F1。

  | 操作 | 預期看到 |
  |---|---|
  | S01 修改一個欄位後再按「正式送出」 | 回執顯示版本 2；作業區狀態「已送出 v2」；繳交歷史仍看得到版本 1 且內容沒變 |
  | S01 再改一次，快速連點「正式送出」兩下 | 只多一個版本 3；兩次回執內容相同 |
  | 工程模擬送出後回應中斷 | 畫面顯示「結果尚未確認」與「查詢結果」按鈕，沒有「未送出」字樣 |
  | 按「查詢結果」（伺服器其實已收到） | 顯示原本的收件章回執 |
  | 工程模擬伺服器沒收到，按「查詢結果」 | 顯示查無結果，允許再按一次送出（用同一操作編號） |
  | 工程模擬回執已過期，按「查詢結果」 | 顯示「結果參照」而不是收件章 |
  | 換 S02 登入，用 S01 的操作編號查詢結果 | 查無結果（不洩漏 S01 的資料） |
  | S01 登出再登入 → 繳交歷史 | 版本 1、2、3 都在 |
- **誰確認**：工程核對／Roy 畫面操作確認。
