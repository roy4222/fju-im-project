# S13 正式正文｜封存／解封、多屆並行、下一屆、跨屆隔離、通知匣跨屆

> 本檔是 S13 每張票的「可讀正文層」，票號、順序與 BLOCKED 標記照票草稿；技術九欄由產生器自動附在折疊區，這裡不重貼。環境依切片卡為 staging（未就緒時可用 local 並標明）。測試帳號只寫角色代號：A1 管理員、S01–S05 第一組 G1 成員、SX1 分支帳號（新註冊）、T1 老師。屆別：115-TEST（主線）、116-TEST（本切片建立的下一屆）；收件項目：MID1（期中組別收件）、FX（隔離副本內的個人收件）。停、啟背景工作與推業務鐘由工程在旁執行。

### S13-01 [模組02 屆別與年度流程] 老師與管理員在側欄切換工作屆別，進入任一屆都看到該屆狀態橫幅
- **票型**：feature
- **這張做什麼**：老師 T1 與管理員 A1 的側欄多一個「工作屆別」切換器，切換後各頁預設以那一屆篩選，重新整理也記得；學生固定只看自己那一屆，沒有切換器。進入任何一屆的頁面時，頂部橫幅明確寫出這屆現在是「籌備中」「進行中」「已封存」還是「已解封」（已解封會附最近一次解封理由）。切換器只是換畫面，不是權限：就算把它指到不該看的屆別，系統仍會擋。
- **做到哪裡**：本票交付切換器元件、可見屆別清單、狀態橫幅、各頁預設篩選跟著切換器。封存與解封動作由 S13-03／04；屆別列表頁 S01-06 已有；學生待辦的伺服端隔離驗證由 S13-06。本票目前是「介面預留」（殼），不等任何功能票。
- **Roy 如何確認**：staging（或 local）；用 A1、T1、S01；要先有兩個屆別（115-TEST 與另一屆，其中一屆已封存或由工程先造好狀態）；從老師或管理員後台側欄。

  | 操作 | 預期看到 |
  |---|---|
  | A1 看側欄 | 有「工作屆別」切換器，列出全部屆別 |
  | A1 切到已封存那一屆 | 頁面頂部橫幅「已封存」；各清單預設篩選成該屆 |
  | 重新整理頁面 | 仍停在那一屆，橫幅不變 |
  | 切回 115-TEST | 橫幅「進行中」 |
  | 換 T1 登入看側欄 | 切換器只列 T1 有指導或指派關係的屆別＋預設工作屆別 |
  | 換 S01 登入 | 側欄沒有切換器；頁面橫幅顯示自己屆別的狀態 |
  | 工程把 T1 的切換器 cookie 改成 T1 不可見的屆別後 T1 重新整理 | 自動回到預設工作屆別，不報錯；直接請求那一屆的資料仍被拒（FORBIDDEN） |
- **誰確認**：工程核對／Roy 畫面操作確認（切換器放側欄或頂列由 Roy 看畫面定）。
- **原型畫面**：無原型畫面（待實作畫面；「兩屆並行的屆別切換」列於模組 02 §7.2 缺口）。

### S13-02 [模組02 屆別與年度流程] 管理員封存前先看「還有哪些沒做完」的預覽清單
- **票型**：feature
- **這張做什麼**：A1 在屆別管理頁對進行中的屆別按「封存預覽」，系統跨三個模組把未完成的事情列出來：還沒送出或份數不夠的收件與進行中草稿、還沒送出的評分與沒走完的評分階段、還在收集同意或等老師簽的簽核版本；每項寫類型、對象、數量與校方採認狀態。預覽純粹是看，不改任何資料；全部完成時顯示「無未完成項」仍可封存。這是封存前的最後一道提醒，避免把還在進行的東西一起鎖住。
- **做到哪裡**：本票交付模組 05 的未完成清單實作、06／07 實作的接入與合併、預覽對話框、未完成摘要的資料結構（供 S13-03 寫進封存紀錄）。封存本身由 S13-03；06／07 的清單本體由 E10、E11 交付。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與 T1；要先有主線 P08 完成後的 115-TEST（有一組還沒交期末、一位老師還沒送分、一個簽核版本還在收集中）；從管理員後台 → 屆別（`/dashboard/admin/cohorts`）→ 115-TEST → 「封存預覽」。

  | 操作 | 預期看到 |
  |---|---|
  | A1 對 115-TEST 按「封存預覽」 | 對話框分三段列出：未完成收件、未送出評分、進行中簽核；每項有對象、數量與採認狀態 |
  | 關掉對話框，去收件名單頁看那一組 | 資料沒有被改動（仍是未交） |
  | 讓那一組補交後再按一次「封存預覽」 | 該項從清單消失；其他項不變 |
  | 對「籌備中」的屆別找封存預覽 | 沒有這個入口 |
  | 對已封存的屆別看 | 入口變成「解封」 |
  | 換 T1 登入，直接開預覽的網址 | 被拒（FORBIDDEN） |
- **誰確認**：工程核對／Roy 畫面操作確認（Roy 看封存預覽對話框）。
- **原型畫面**：無原型畫面（待實作畫面；「封存預覽」列於模組 02 §7.2 缺口）。

### S13-03 [模組02 屆別與年度流程] 管理員填理由封存一屆，該屆從此唯讀，排程中的到期工作一併取消
- **票型**：feature
- **這張做什麼**：A1 看完預覽、填上理由後按「封存」：屆別狀態變成「已封存」，系統記下誰、什麼時候、為什麼、當時還有哪些沒做完（預覽摘要）；這一屆還沒跑的到期工作（截止快照、逾期彙整等）全部取消，其他屆的不受影響。封存不發任何通知——進入該屆的人會從橫幅看到「已封存」。回執顯示封存時間與未完成摘要。從此這一屆只能讀不能寫（各模組的拒絕在 S13-05 全站驗證）。
- **做到哪裡**：本票交付封存動作、對話框（理由必填、先顯示預覽摘要再確認）、到期工作取消、封存紀錄、回執、稽核。解封由 S13-04；各模組寫入被拒的驗證由 S13-05；通知匣的封存遮罩由 S13-08。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與 S01；要先有進行中的 115-TEST 與 S13-02 的預覽資料；從管理員後台 → 屆別 → 115-TEST → 「封存預覽」→ 「封存」。

  | 操作 | 預期看到 |
  |---|---|
  | A1 在對話框理由留空按「封存」 | 被拒，提示理由必填；屆別仍是進行中 |
  | 填理由後按「封存」 | 回執含封存時間與未完成摘要；列表上 115-TEST 變「已封存」 |
  | 離開頁面再回來，或重新登入 | 仍是已封存；點開可看到封存紀錄（誰、何時、理由、摘要） |
  | 在兩個分頁同時開預覽，一個先封存，另一個再按封存 | 第二個被拒（CONFLICT），提示重新載入預覽 |
  | 對「籌備中」的屆別嘗試封存 | 被拒（VALIDATION_FAILED） |
  | 換 S01 登入 | 通知匣沒有多出「封存」通知；進入 115 頁面頂部橫幅「已封存」 |
  | 換 T1 登入，直接開封存動作的網址 | 被拒（FORBIDDEN） |
- **誰確認**：工程核對／Roy 畫面操作確認；到期工作取消的前後對照由工程核對。
- **原型畫面**：無原型畫面（待實作畫面；「封存回執」列於模組 02 §7.2 缺口）。

### S13-04 [模組02 屆別與年度流程] [BLOCKED D-07] 管理員填理由解封已封存的屆，之後可再封存
- **票型**：decision
- **這張做什麼**：A1 對已封存的屆填理由按「解封」，該屆回到進行中，可以再寫入；但不延長任何期限、不恢復已撤銷的成員或名單關係、不重送通知，原本的封存紀錄留著，橫幅改顯示「已解封」並附理由。之後再封存會留第三筆紀錄，解封次數只增不減。目前卡住的是：封存時被取消的到期工作（快照、對帳、彙整），解封後要不要補跑或重排。
- **做到哪裡**：本票交付解封動作、對話框、回執、稽核與「已解封」橫幅資料；再封存走 S13-03。解封後舊截止仍拒送出的行為由 S13-05 驗證。本票目前是「決策草案」：D-07 未決前不施工。
- **Roy 如何確認**：等 D-07 決定；決定後補確認步驟。這個決定影響的是：一屆解封之後，之前排好但被取消的「截止快照」「逾期彙整」會不會自動再跑一次——會影響解封後名單頁的快照分頁與系辦收到的逾期通知。
- **誰確認**：Roy 畫面操作確認（決定後）／工程核對。
- **原型畫面**：無原型畫面（待實作畫面；「解封」列於模組 02 §7.2 缺口）。

### S13-05 [模組02 屆別與年度流程] [BLOCKED D-08] 證明封存後全站只能讀不能寫，且封存與送出撞在一起時只有一方成功
- **票型**：decision
- **這張做什麼**：用自動測試逐一證明：封存後每個模組的寫入動作（提案、發布、送出、評分、簽核、精選草稿等）都回「屆別已封存」且資料不變；封存與學生正在送出撞在同一瞬間時只有一方成功、順序合理；封存後讀取、歷史、成績與簽核匯出仍可用；封存前的操作回執在封存後重播只會得到「屆別已封存」；解封後過期項目送出被拒的理由是「截止已過」而不是「已封存」。不新增功能，發現漏擋就回原切片開缺陷。目前卡住的是：匯出會新增檔案紀錄，這算不算封存後允許的寫入例外。
- **做到哪裡**：本票交付表驅動的寫入拒絕測試、競態測試、讀取與匯出測試、劇本 P09 步驟 13–14 與 B06 步驟 2、7 的操作證據。修各模組不在本票。本票目前是「決策草案」：D-08 未決前匯出部分不施工。
- **Roy 如何確認**：等 D-08 決定；決定後補確認步驟。這個決定影響的是：屆別封存後，系辦還能不能按「匯出成績」「匯出簽核」拿到檔案（P09 步驟 14 目前預期「可查可匯出」）。決定後 Roy 會實際做的是：用 S01 在封存前開著的舊頁按儲存草稿，看到「屆別已封存」與回首頁／重新載入的下一步；用 A1 查 115 成績並匯出。
- **誰確認**：工程核對（競態與表驅動測試）／Roy 畫面操作確認（決定後）。
- **原型畫面**：無原型畫面（待實作畫面）。

- **做到哪裡**：本票交付屆別管理頁上的完整流程（沿用 S01-06 的建立／啟用／旗標、S02-04 的階段、S13-01 的切換器）、跨屆隔離與佇列分開的測試與操作證據。跨屆調整由 S13-07；通知匣篩選由 S13-08。本票目前是「可操作功能」。

### S13-07 [模組02 屆別與年度流程] [BLOCKED D-02] 管理員把學生從一屆調到另一屆，待辦跟著換、舊屆歷史保留
- **票型**：decision
- **這張做什麼**：有學生登記錯屆（例如 SX1 註冊到 116 但其實是 115），A1 在帳號頁填理由「調整屆別」：學生所屬屆別改掉、同屆同學號不能重複、原屆的收件名單把他移出、新屆截止前的名單依規則加入；原屆待辦消失、新屆待辦出現；原屆的回答與版本留著可查；之後他直接請求原屆的項目會被拒。目前卡住的是：已經在有效組別裡的學生能不能換屆、這個動作歸哪個模組、用什麼介面。
- **做到哪裡**：本票交付調整屆別動作、帳號頁對話框、名單同步、稽核與隔離測試。名單移除本體由 E08 交付。本票目前是「決策草案」：D-02 未決前不施工。
- **Roy 如何確認**：等 D-02 決定；決定後補確認步驟。這個決定影響的是：系辦能不能把已經分好組的學生換到別屆，以及換屆後他原本那組怎麼處理。決定後 Roy 會實際做的是：用 A1 對 SX1 按「調整屆別」（116→115）填理由，換 SX1 登入看待辦只剩 115、116 的項目打不開；用 A1 查 SX1 在 116 的舊回答仍在。
- **誰確認**：Roy 畫面操作確認（決定後）／工程核對。
- **原型畫面**：無原型畫面（待實作畫面）。

### S13-08 [模組08 站內通知與日曆] 通知匣可依屆別篩選，已封存屆的通知標「已封存（唯讀）」但仍可標已讀
- **票型**：feature
- **這張做什麼**：跨過一屆的人（例如同時有 115 與 116 通知的 S01）打開通知匣，預設看到自己所有屆別的通知加上全站通知，可以用屆別篩選（預設跟側欄切換器，也能改回「全部」）。來自已封存屆的通知列顯示「已封存（唯讀）」遮罩、點進去導向該屆的唯讀頁，但還是可以標已讀，讓未讀數歸零。
- **做到哪裡**：本票交付屆別篩選、篩選介面、封存屆的遮罩態、封存屆已讀的測試。「此項目目前無法存取」「來源已撤回」兩態由 S12-10；已讀本體 S02-08 已做。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01；要先有 S01 在 115（已封存）與 116 各有幾則通知（B06 步驟 8 的資料）；從學生後台 → 通知匣。

  | 操作 | 預期看到 |
  |---|---|
  | S01 開通知匣 | 115、116 與全站通知都在；上方有屆別篩選 |
  | 篩選 115 | 只剩 115 與全站通知 |
  | 篩選 116 | 只剩 116 與全站通知 |
  | 看 115 那幾則 | 摘要顯示「已封存（唯讀）」；點進去到該屆的唯讀頁 |
  | 對一則 115 通知標已讀 | 未讀數減一 |
  | 登出再登入 | 那則仍是已讀；篩選回到預設 |
  | 直接開別人通知的網址標已讀 | 被拒，對方通知不變 |

### S13-09 [模組02 屆別與年度流程] 把 staging 的業務鐘往回撥，證明已作廢的提案不復活、已拍的快照不重拍
- **票型**：feature
- **這張做什麼**：測試環境的業務鐘可以推前也可以往回撥。這張票證明回撥之後系統不會「倒帶」：已經因到期作廢的提案不會復活、已經拍過的截止快照與已發過的逾期彙整不會再做一次；但截止判定用的是「現在」的業務時間，所以回撥到截止前，學生可以再送出，期限版本不變。每次調鐘都記下誰、為什麼、調前調後的時間；重置回真實時間也留紀錄。這是維運手冊 §5 調鐘與重置的依據。
- **做到哪裡**：本票交付跨模組的整合測試（提案作廢、截止快照、逾期彙整）、回撥後再送出的行為測試、劇本 B06 步驟 4–5 與手冊 §5 的操作證據。模擬鐘頁與調鐘寫入 S02-02 已做；正式環境沒有這個頁面由 S14-11 預演證明。本票目前是「可操作功能」（停、啟背景工作由工程在旁執行）。
- **Roy 如何確認**：staging；用 A1 與 S09（個人收件者）；要先有一個已到期作廢的提案、隔離副本內截止 11/16 23:59 的個人收件 FX；從管理員後台 → 屆別 → 模擬鐘（僅 staging）。
