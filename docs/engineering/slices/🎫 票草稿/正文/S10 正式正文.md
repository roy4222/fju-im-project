# S10 正式正文｜評分：方案、要求份數、指派、暫存／正式、計算、退回、更正

> 本檔是 S10 每張票的「可讀正文層」，票號、順序與 BLOCKED 標記照票草稿；技術九欄由產生器自動附在折疊區，這裡不重貼。環境依切片卡為 staging（未就緒時可用 local 並標明）。測試帳號只寫角色代號：A1、A2 管理員；S01–S05 第一組 G1 成員；G2、G3 另兩組；T1、T2、T3 老師（主線由 T1、T2 評 G1 期中，T3 供改派與停用情境）。分數用劇本的數字：T1 給 80、T2 給 84.29，期中平均 82.145 顯示 82.15；最終 85.287 顯示 85.29。

### S10-01 [模組06 評分與成績] 建立評分模組的九張資料表、不可變保護與角色權限
- **票型**：foundation
- **這張做什麼**：工程把評分要用的全部資料表一次建好：評分方案與版本、每組每階段要幾份、老師指派、老師輸入的分數、分數的採計狀態與狀態紀錄、最終結果的更正與復核狀態。其中「老師輸入的分數」「狀態紀錄」「更正」三張寫入後不能改也不能刪，方案版本只能往前走（發布→鎖定）不能倒退。這是後面全部評分功能的地基。
- **做到哪裡**：本票交付建表腳本、不可變保護、欄位級的權限限制、逐表權限測試、與程式端資料結構的對照；空資料庫從頭逐切片升級要成功。任何畫面與操作都不在本票（從 S10-02 起）。本票目前是「工程基礎」。
- **Roy 如何確認**：本票由工程驗證；Roy 在 E10 整體展示確認 CI 的「空庫升級」與「舊資料升版」兩條工作都是綠燈，並看到工程附的九張表結構輸出與權限測試輸出。Roy 不需要讀 SQL。
- **誰確認**：工程核對。
- **原型畫面**：無原型畫面（待實作畫面）。

### S10-02 [模組06 評分與成績] 管理員建立評分方案版本並發布，權重不合 100 被擋
- **票型**：feature
- **這張做什麼**：每屆開始評分前，A1 在評分管理頁建立方案第一版：有哪些階段（期中、期末）、各占多少比重、每階段有哪些項目與滿分。階段比重要合計 100，每階段的項目比重也要合計 100，不合就存不進去並指出哪一層不對。建好是草稿，按發布後老師才用得到。
- **做到哪裡**：本票交付建方案表單、權重驗證、發布、方案版本清單與狀態，以及評分管理頁的殼（後面的指派、成績表都掛在這裡）。第一筆正式評分後自動鎖定由 S10-05；鎖定後改權重走新版本由 S10-10；要求份數與指派由 S10-03。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1；要先有本屆（例如 115）與已核准的老師；從管理員後台 → 評分。

  | 操作 | 預期看到 |
  |---|---|
  | A1 建方案：期中 60、期末 50 | 被拒，提示階段權重合計不是 100；沒有建立任何版本 |
  | 改成期中 60、期末 40，期中內項目 50／50 | 回執含版本號 v1，清單顯示 v1「草稿」 |
  | 按發布 | 狀態變「已發布」 |
  | 離開頁面再回來，或重新登入 | v1 仍在、仍是已發布 |
  | 換 T1 登入直接開建方案的網址或請求 | 顯示「無法存取」 |
  | 對已封存的舊屆別建方案 | 被拒，提示屆別已封存 |
- **誰確認**：工程核對／Roy 畫面操作確認。

### S10-03 [模組06 評分與成績] 管理員設定每組每階段要幾份評分並指派老師，老師收到通知

### S10-05 [模組06 評分與成績] 老師正式送出分數，同一指派只採計一份，方案自此鎖定
- **票型**：feature

- **做到哪裡**：本票交付正式送出、同指派一筆採計、方案鎖定、回執與重送查詢。平均與最終由 S10-06；退回由 S10-08。本票目前是「可操作功能」。

### S10-07 [模組06 評分與成績] 管理員更正最終結果，原值保留並列，需要復核時進待復核清單
- **票型**：feature
- **這張做什麼**：A1 對某組已完成的最終結果建立更正（例如 84.80 改 85.00）並填理由；老師原本的輸入不會被蓋掉，成績表同時顯示原值、新值與理由。最終還沒完成（份數不足）不能更正。更正綁定當時的採計組合；之後若採計組合變了（退回、改派、換方案），這筆更正會自動轉「待復核」並通知管理員一次，A1 在待復核清單決定「沿用」或「建新更正」。
- **做到哪裡**：本票交付更正對話框、原值新值並列、未完成拒絕、待復核清單與復核。真正把更正轉待復核的動作由 S10-08（退回）、S10-09（改派）、S10-10（換方案）觸發。本票目前是「可操作功能」。

### S10-09 [模組06 評分與成績] 管理員移除評分指派時預覽三選一，預覽過期就要重做
- **票型**：feature
- **這張做什麼**：A1 要把某位老師從某組某階段的評分拿掉時，先預覽三種做法的結果：「保留」（他的採計分留著、只結束指派）、「替換給另一位老師」（他的分數轉歷史、新老師補評）、「新增一位老師」（要求份數加一）。預覽顯示前後採計名單、份數、平均與最終的變化，以及會受影響的更正。若預覽開著期間有人送出正式分、被退回或方案變了，執行會被擋並要求重新預覽。三種做法都會讓該老師未送出的草稿失效。同時提供給 S09 重派主指導時逐筆套用的同交易版本。
- **做到哪裡**：本票交付三選一預覽對話框、執行、預覽過期拒絕、草稿失效、更正轉待復核、給 S09 用的內部指令。重派主指導本身與對話框勾選由 S09-02；換方案造成的預覽過期由 S10-10。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1、T1、T2、T3；要先有 G1 期中 T1、T2 兩份採計、T3 未指派 G1、G1 有一筆生效中的更正；從管理員後台 → 評分 → 指派 → G1 期中 → T2 → 移除。

  | 操作 | 預期看到 |
  |---|---|
  | A1 選「保留」按預覽 | 前後採計名單相同、份數 2／2、平均不變、列出受影響更正（無） |
  | 改選「替換給 T3」按預覽 | 後採計名單只剩 T1、變 1／2、平均改為 80、更正列為受影響 |
  | 開著預覽，另開 T1 對 G1 期中做退回再重送（或由 A2 退回 T1 那份） | 回到 A1 按執行 → 被拒，提示「評分狀態已變更，請重新預覽」 |
  | 重新預覽「替換給 T3」並執行 | 回執；指派頁 T2 結束、T3 新增；待復核清單出現 G1 的更正 |
  | 換 T2 登入工作台 | G1 不見了，直接對 G1 暫存被拒（未受指派） |
  | 換 T3 登入 | 通知匣有指派通知，工作台出現 G1 期中 |
  | A1 再對 G1 期中另一位試「替換給 T3」 | 被拒，提示 T3 已受指派 |
  | 離開再回來 | 指派與份數狀態保存 |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：無原型畫面（待實作畫面）。
