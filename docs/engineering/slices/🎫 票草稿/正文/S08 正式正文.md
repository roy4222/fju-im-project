# S08 正式正文｜名單變動、截止快照、指定重開、改期、改結構、逾期彙整、到期工作全套

> 本檔是 S08 每張票的「可讀正文層」，票號、順序與 BLOCKED 標記照票草稿；技術九欄由產生器自動附在折疊區，這裡不重貼。環境依切片卡為 staging（未就緒時可用 local 並標明）。測試帳號只寫角色代號：A1 管理員、S01–S05 第一組 G1 成員、S09 個人收件者、S11／S12 第三組 G3 成員、SX1／SX2 分支帳號、T1／T2／T3 老師。收件項目：MID1（期中組別收件）、F1（個人收件）、FX（隔離副本內的個人收件）。

### S08-01 [模組05 個人與組別繳交] 建立截止快照、快照註記與指定重開三張資料表
- **票型**：foundation
- **這張做什麼**：工程在 S07 的資料表之上，再加三張只寫不改的表：「截止快照」（截止那一刻的名單與完成率）、「快照註記」（截止後對帳補記的準時版本）、「指定重開」（系辦對某組或某人另給的期限）。這三張表是後面截止鎖定、指定重開、逾期彙整全部功能的地基；沒有它們，截止當下發生了什麼就無從追溯。
- **做到哪裡**：本票交付三張表的建表腳本、不可變保護（寫入後不能改、不能刪）、資料庫角色權限與對應的角色測試；空資料庫從頭逐切片升級要成功。任何畫面與操作都不在本票（名單頁動作由 S08-02 起）；逾期彙整用的 `digest_events` 已由 S02-01 建好，本票不重建；主指導閱覽設定表由 S07-01 建。本票目前是「工程基礎」。
- **Roy 如何確認**：本票由工程驗證；Roy 在 E08 整體展示確認 CI 的「空庫升級」與「舊資料升版」兩條工作都是綠燈，並看到工程附的三張表結構輸出。Roy 不需要讀 SQL。
- **誰確認**：工程核對。
- **原型畫面**：無原型畫面（待實作畫面）。

### S08-02 [模組05 個人與組別繳交] 在名單頁掛上免填、移出、加回、重開等動作的入口與對話框
- **票型**：feature
- **這張做什麼**：管理員 A1 打開某個收件項目的名單頁時，多出一列動作按鈕（免填／恢復應填、移出、加回、加入名單、指定重開、主指導閱覽設定）和一個「截止快照」分頁；項目詳情多出「改期」「改結構」入口。這張票只把入口和對話框的殼做出來（含必填標示與空狀態），讓後面每張功能票各自把真正的處理接上去；同時把權限邊界釘死：學生和老師按不到、直接打請求也會被拒。
- **做到哪裡**：本票交付動作列、六個對話框殼、快照分頁殼（空狀態「尚未截止」）、每列的「逾期／已重開至…」欄位位置、改期與改結構的入口與預覽頁殼、重開對話框固定四欄（原截止、目前採計版本、會通知誰、範圍只有這一組／這個人）。任何實際寫入都留給後面：自動同步名單由 S08-03、免填與移出由 S08-04、快照內容由 S08-05、指定重開由 S08-07、改期由 S08-08、改結構由 S08-09、加回由 S08-10。名單頁的讀取與分類本體是 S05 建的，本票只加欄位位。本票目前是「介面預留」。
- **Roy 如何確認**：staging（或 local）；用 A1 登入；要先有 E07 出場的資料（已發布的 MID1、已有幾組送出）；從管理員後台 → 專題事務 → 點 MID1 → 名單頁。

  | 點「截止快照」分頁 | 顯示空狀態「尚未截止」 |

  | 回到項目詳情 | 有「改期」「改結構」兩個入口，點改結構進到預覽頁殼 |

### S08-03 [模組05 個人與組別繳交] 截止前核准的學生自動進名單，截止後不追加，停用時自動移出
- **票型**：feature
- **這張做什麼**：管理員核准一個新學生帳號時，系統在同一次處理裡把他加進本屆所有「已發布、給本屆學生、還沒截止」的個人收件名單，並發一則「新收件」通知給他；名單頁上那一列標「發布後加入」和時間。若核准時該項目已經截止，就不加、不通知——截止後想補收要走 S08-07 的「加入名單並重開」。反過來，管理員停用一個學生時，他在所有名單中的資格同時結束，完成率的分母也跟著減一。
- **做到哪裡**：本票把 S01-10 核准用例裡預留的空方法換成真的實作，並在 S01-11 停用用例上接「移出名單」；交付事件與名單頁「發布後加入」標示。管理員手動加入由 S08-07；跨屆調整由 S13；組別收件在成組後是否自動進名單由 S08-17（BLOCKED D-13）決定，本票不做。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與分支帳號 SX1、SX2；要先有隔離副本裡已發布且未截止的個人收件 FX（依劇本 B03）；從管理員後台 → 帳號 → 待核准。

  | 操作 | 預期看到 |
  |---|---|
  | A1 在 FX 截止前核准 SX1 | 回執成功；打開 FX 名單頁，SX1 出現在名單，該列標「發布後加入」與時間，分母多一人 |
  | 換 SX1 登入 | 通知匣有一則 FX 的「新收件」；首頁待辦出現 FX |
  | 推業務鐘越過 FX 截止後，A1 核准 SX2 | 回執成功，但 FX 名單沒有 SX2；SX2 通知匣沒有 FX 的通知 |
  | SX2 直接對 FX 送出（用舊頁或直接請求） | 被拒，錯誤是 NOT_IN_ROSTER |
  | A1 停用 S01 | F1 名單頁 S01 列標已移出、時間；完成率分母減一 |
  | 離開名單頁再回來，或 A1 重新登入 | 上述名單狀態與分母不變 |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：無原型畫面（待實作畫面）。

### S08-04 [模組05 個人與組別繳交] 管理員把人設為免填、恢復應填或移出名單，完成率跟著重算
- **票型**：feature
- **這張做什麼**：有人因故不用交（例如休學中），A1 在名單頁把他設為「免填」並填理由，他就不算在分母裡、也不算已完成；之後恢復應填，他就回到分母。要把人整個移出名單時同樣必填理由，分子分母一起依資格重算（例如 8／10 移出一位已交者變 7／9，再移出一位未交者變 7／8）。被移出者原本的回答保留，但打開項目只看得到「已移出，回答保留」的唯讀頁，不能再送。每個動作都給當事人一則通知。
- **做到哪裡**：本票交付免填、恢復、移出三個動作與對話框、名單頁分類、通知、完成率依免填與移出重算。加回由 S08-10；停用引起的移出由 S08-03；受眾變更引起的移出由 S08-10；解散由 S09。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與 S01；要先有 13 人名單、部分已交的個人收件 F1（依劇本 B03）；從管理員後台 → 專題事務 → F1 → 名單頁。

  | 操作 | 預期看到 |
  |---|---|
  | A1 對一位未交者按「免填」，理由留空按確定 | 被拒，提示理由必填；名單不變 |
  | 填理由後確定 | 該人移到「免填」分類；完成率從 12／13 變 12／12 |
  | 對同一人按「恢復應填」 | 回到「未交」分類；完成率回 12／13 |
  | 離開頁面再回來 | 分類與完成率仍是剛才的結果 |
  | 對一位已交者按「移出」並填理由 | 該人移到「已移出」分類；分子分母同時減一（例如 8／10 → 7／9） |
  | 換被移出的學生登入，打開 F1 | 只看到「已移出，回答保留」唯讀頁，沒有送出按鈕；通知匣有一則本人的移出說明 |
  | 換 T1 登入，嘗試對 F1 名單設免填 | 被拒（FORBIDDEN） |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：無原型畫面（待實作畫面）。

### S08-05 [模組05 個人與組別繳交] 截止一到自動拍下名單快照，並把學生頁鎖成唯讀
- **票型**：feature
- **這張做什麼**：收件截止的那一分鐘結束後再等 60 秒，背景工作自動把當時的名單與每人最新版本「拍照」存起來，成為之後查核的依據；名單頁多一個「截止快照」分頁可以看。同時學生頁變成「已截止・唯讀，需系辦重新開放」，沒有送出按鈕；就算學生停在舊頁面按送出，也會被擋下並告知「截止 11/16 23:59 已過」。快照拍過一次就不會重拍，之後名單再變也只會另列、不覆寫。
- **做到哪裡**：本票交付快照工作、快照分頁、截止後鎖定畫面與文案、送出守門順序的最終驗證；指定重開到期的個別快照也走同一支工作。截止後的對帳註記由 S08-06；指定重開的排程由 S08-07；逾期彙整由 S08-11。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與 S01；要先有截止設在 23:59 的 MID1 與已送出的組別（依劇本 P07）；從管理員後台 → 專題事務 → MID1 → 名單頁；推鐘由工程提供的業務鐘工具。

  | 操作 | 預期看到 |
  |---|---|
  | 推業務鐘到 00:00:30（截止分鐘剛過） | 名單頁「截止快照」分頁仍是「尚未截止」（60 秒寬限內還沒拍） |
  | 推到 00:01:00 並等背景工作跑一輪 | 快照分頁出現一筆快照：時間、名單、完成數／分母 |
  | 換 S01 登入打開 MID1 | 頁面標「已截止・唯讀，需系辦重新開放」，沒有送出按鈕 |
  | S01 用截止前就開著的舊頁按送出 | 被拒，顯示「截止 11/16 23:59 已過」（DEADLINE_PASSED） |
  | A1 在截止後把某人移出名單，再看快照分頁 | 快照內容不變；變動另列在快照之後 |
  | 離開再回來 | 快照仍只有一筆，不重複 |
- **誰確認**：工程核對／Roy 畫面操作確認。

### S08-06 [模組05 個人與組別繳交] 截止當下剛好在送出的版本，事後自動對帳補記
- **票型**：foundation
- **這張做什麼**：截止那一秒可能有學生正在按送出：請求在截止前已收到、但寫入完成時快照已經拍了。這張票讓背景工作在每次正式送出後自動核對：如果版本準時卻沒進快照，就在快照旁補一筆「晚 commit 的準時版本」註記；已在快照裡就結束；快照還沒產生就先等、稍後再試。目的是不讓任何準時的送出被漏算，也不讓逾期的混進來。
- **做到哪裡**：本票交付對帳工作、三種時序情況的整合測試（快照已讀未寫入、送出已寫入未後處理、背景工作中途中斷重啟）、快照分頁顯示註記。改期時把等待中的對帳作廢由 S08-08；「更正」類註記 spec 沒有寫誰產生，不在本票。本票目前是「工程基礎」。
- **Roy 如何確認**：本票由工程驗證；Roy 在 E08 整體展示確認三種時序情況的測試都綠，並在名單頁快照分頁看到一筆標「晚 commit 的準時版本」的註記（工程用測試造出的案例）。Roy 不需要理解背景工作的重試機制。
- **誰確認**：工程核對。
- **原型畫面**：無原型畫面（待實作畫面）。

### S08-07 [模組05 個人與組別繳交] 管理員只對某一組或某一人重新開放並讓他補交
- **票型**：feature
- **這張做什麼**：截止後有一組（例如 G3）有正當理由要補交，A1 在名單頁對那一組按「指定重開」，填新期限與理由；對話框先讓他看清楚原截止、目前採計版本、會通知誰、範圍只有這一組。確定後只有 G3 收到通知、只有 G3 能在新期限前送，其他組仍然鎖著；G3 補交的版本標「重開後補交」；過了新期限再送一樣被擋。截止後想把原本不在名單的人（例如 SX2）補進來，可以「加入名單並一併重開」，一次操作、一則完整通知。
- **做到哪裡**：本票交付指定重開與加入名單兩個動作、對話框與影響預覽、個別期限的送出守門、重開到期的個別快照排程、「重開後補交」標記與通知。重開期限到期後的逾期檢查由 S08-11；封存後的重開由 S13。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1、S11（G3 成員）、S01（G1 成員）、SX2；要先有已截止且 G3 逾期的 MID1（S08-05 之後的狀態）；從管理員後台 → 專題事務 → MID1 → 名單頁。

  | 操作 | 預期看到 |
  |---|---|
  | A1 對 G3 按「指定重開」，新期限留空按確定 | 被拒，提示新期限與理由必填 |
  | 填 11/18 23:59 與理由後確定 | 回執；G3 該列狀態變「已重開至 11/18 23:59」；G1、G2 仍是「已鎖定」 |
  | 換 S11 登入 | 通知匣有一則指定重開；打開 MID1 可以填寫並送出，送出後版本標「重開後補交」 |
  | 換 S01 登入打開 MID1 | 仍是唯讀，沒有送出按鈕；通知匣沒有重開通知 |
  | 推鐘越過 11/18 23:59 後 S11 再送 | 被拒（DEADLINE_PASSED） |
  | A1 對 SX2 按「加入名單」並勾「一併重開」 | 一次回執；SX2 出現在名單且標已重開；SX2 通知匣只有一則完整說明（已加入＋新期限） |
  | A1 對已停用的 S15 指定重開 | 被拒（NOT_IN_ROSTER） |
