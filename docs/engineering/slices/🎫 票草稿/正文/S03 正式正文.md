# S03 正式正文｜找組員、提案、確認、終止、例外組、組長

> 本檔是 S03 每張票的「可讀正文層」，票號、順序照票草稿；技術九欄由產生器自動附在折疊區，這裡不重貼。環境依切片卡為 staging（未就緒時可用 local 並標明）。測試帳號只寫角色代號：A1 管理員、S01–S13 已核准學生（S01 為第一組提案人、S02–S05 被邀請者、S06 用來看找組員名單、S07–S09 例外組成員）、T1 老師。測試屆別：115-TEST，階段與成組截止已在 S02 設好，模擬業務鐘可推進。S03 做的是「五人提案、逐人確認、成立或終止」這整條，提案與確認畫面原型沒有，是 Roy 指定要看的畫面。

### S03-01 [模組03 分組、指導與產學] 第四支 migration：新增提案、邀請、占用、組別、成員、組長六張表
- **票型**：foundation
- **這張做什麼**：工程在 S02 的表之上只「新增」分組需要的六張表：提案、提案邀請（每人一筆）、提案占用（一個人同時只能被一個提案占住）、組別、組別成員（有效期間）、組長（有效期間與更換紀錄），以及屆別表上的「提案預設天數」欄（預設 7）。同時把「一人同屆只能在一個有效組」「一組同時只有一位有效組長」「同屆組別代碼不重複」這些規則做成資料庫約束，補權限矩陣與逐表測試（例如 app 不能改成員表的人是誰、但可以刪占用）。
- **做到哪裡**：本票交付一支純 SQL migration、欄級 UPDATE 權限、`roles.test.ts` 六表新增列、約束反例測試（例如標了終止卻沒填終止原因會被擋）。指導老師與產學案的表由 S06 自己的 migration；「公開找組員」旗標欄由 S03-03（落點待 Roy）；任何用例都不在本票。本票目前是「工程基礎」。
- **Roy 如何確認**：本票由工程驗證；Roy 在 E03 整體展示確認 CI 的「空庫 S00→S01→S02→S03 升級」與「舊版升版」兩條綠燈，並看工程附的六表清單與約束反例測試輸出（幾條規則、各被擋一次）。Roy 不需要讀 SQL。
- **誰確認**：工程核對。
- **原型畫面**：無原型畫面（待實作畫面）。

### S03-03 [模組03 分組、指導與產學] 學生打開「公開找組員」，同屆還沒分組的人在找組員名單看到他的姓名、學號與聯絡 Email
- **票型**：feature
- **這張做什麼**：還沒有組的學生 S06 在「我的組別」頁把「公開找組員」打開（預設是關的），同屆其他還沒分組的學生就會在找組員區看到他——只有姓名、學號、聯絡 Email，沒有手機。他關掉開關、或之後成組了，別人重新整理就看不到他。別人不能替他開關；已經在組裡的人不能開。
- **做到哪裡**：本票交付旗標的儲存（欄位落點 spec 未定：`user_profiles` 加欄或模組 03 新表，需 Roy 在本票開工前定案，本票自帶一支小 migration）、本人開關用例、找組員查詢（同屆、已核准未停用、沒有有效組、旗標開啟）、頁面的找組員區與開關。聯絡對話框或寄信產品已移除；提案由 S03-05。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S06、S01（同屆未分組）、以及一位他屆或已成組的學生；從學生側欄 → 我的組別 → 找組員區。

  | 操作 | 預期看到 |
  |---|---|
  | S06 打開「公開找組員」 | 回執；開關亮起 |
  | 換 S01 登入看找組員區 | 看到 S06：姓名、學號、聯絡 Email；沒有手機 |
  | S06 登出再登入 | 開關仍是開的 |
  | 換一位他屆學生（或 S02 在 116-TEST）看找組員區 | 看不到 S06 |
  | S06 關掉開關，S01 重新整理 | S06 消失 |
  | 由工程用 S01 的身分直接送出「把 S06 的開關打開」的請求 | 被拒（FORBIDDEN），S06 的開關不變 |
  | 讓 S06 成組後（S03-06 之後補做）再看名單 | S06 不再列出，即使他的開關還開著 |
- **誰確認**：工程核對／Roy 畫面操作確認／平台由 Roy 提供（旗標欄位落點決定）。

### S03-04 [模組02 屆別與年度流程] 管理員設定本屆提案的預設有效天數
- **票型**：feature
- **這張做什麼**：提案發出去後不是永遠等：每屆有一個「提案預設天數」（預設 7 天），A1 在屆別設定頁可以改。之後學生發起提案時（S03-05），到期時間就是「發起日＋這個天數」與「成組截止」兩者取早。輸入 0、負數或超過成組階段長度會被拒；非管理員不能改；兩個管理員同時改，後者會被要求重新載入。
- **做到哪裡**：本票交付設定用例、屆別查詢回傳此值、屆別設定頁的欄位；欄位本身由 S03-01 建。提案的到期計算與提案頁由 S03-05；成組截止的推導（成組階段結束＝下一階段開始日）由工程確認 E-20。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1；要先有設好階段的 115-TEST；從管理員後台 → 屆別（`/dashboard/admin/cohorts`）→ 115-TEST 設定。

  | 操作 | 預期看到 |
  |---|---|
  | 打開 115-TEST 設定 | 「提案預設天數」欄顯示 7 |
  | 改成 5，儲存 | 回執；離開再回來仍是 5 |
  | 輸入 0 儲存 | 被拒（VALIDATION_FAILED），仍顯示 5 |
  | 輸入一個比成組階段長度還大的天數 | 被拒，仍是 5 |
  | 換 T1 登入直接送出修改請求 | 被拒（FORBIDDEN），仍是 5 |
  | A1 在兩個分頁各開一次設定，第二個用舊資料送出 | 被拒（CONFLICT），要求重新載入 |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：無原型畫面（待實作畫面；屆別設定頁在模組 02 §7.2 列為缺口）。

### S03-05 [模組03 分組、指導與產學] 學生選四位同學發起五人提案，五個人都被占住並收到邀請，提案頁顯示到期時間
- **票型**：feature
- **這張做什麼**：S01 在「我的組別」頁選四位同屆同學（S02–S05）與組別類型（一般／產學）發起提案。送出後提案是「開放中」，五個人（含 S01 自己）各有一筆待確認的邀請，五個人同時被這個提案「占住」——在這個提案結束前，誰都不能被別的提案邀請；提案頁顯示到期時間（S03-04 設的天數與成組截止取早）與每個人的確認狀態；五個人各收到一則「等待本人同意」通知；系統排一件到期工作等時間一到自動終止（S03-07 接）。已在組裡的人、已被別的提案占住的人、成組期已過，都會被拒。
- **做到哪裡**：本票交付提案用例（五人驗證、占用、到期計算、事件、到期工作排程、帳本）、「某人目前在哪一組」查詢、提案表單與「開放中」狀態頁。確認由 S03-06；各種終止與到期處理器由 S03-07。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01–S05 與另一位學生 S06；要先有 115-TEST、業務鐘在成組期內、S03-04 設好天數；從學生側欄 → 我的組別 → 發起提案。

  | 操作 | 預期看到 |
  |---|---|
  | S01 選 S02–S05 與類型「一般」送出 | 回執；提案頁顯示「開放中」、到期時間、五人各標「待確認」 |
  | S01 登出再登入 | 提案仍在、內容一致 |
  | 換 S02 登入 | 通知匣一則「等待本人同意」；我的組別頁看到同一個提案與確認按鈕（按確認由 S03-06） |
  | 換 S06 發起提案並選 S02 | 被拒（INVITED_ELSEWHERE），S06 沒有提案產生 |
  | S06 只選三個人送出 | 被拒（VALIDATION_FAILED） |
  | 把預設天數設 5 而成組截止只剩 3 天，再讓 S06 對別人發提案 | 到期時間顯示成組截止（取早） |
  | 把業務鐘推過成組截止後，S06 再發提案 | 被拒（GROUP_PERIOD_CLOSED） |
  | 換 T1 登入直接送發起提案的請求 | 被拒（FORBIDDEN） |
- **誰確認**：工程核對／Roy 畫面操作確認（提案畫面是 Roy 指定要看的畫面）。
- **原型畫面**：
  ![學生｜/dashboard/student/groups｜我的組別 3/5 已確認；找組員只列開啟公開的人，電話不公開](<../../../../product/assets/prototype-2026-09-11/student--dashboard-student-groups.png>)
  原型 2026-09-11；正式版差異：提案表單、占用、到期時間與每人狀態為新做（原型固定 3/5、無提案操作），模組 03 §7.2 列為缺口。

### S03-06 [模組03 分組、指導與產學] 五個人各自按確認，最後一位確認的瞬間組別成立、占用釋放、全員收到成立通知
- **票型**：feature
- **這張做什麼**：被邀請的每個人在自己的「我的組別」頁按「確認」，畫面顯示目前 n／5；當第五個人按下去的那一筆交易裡，組別（配一個屆別內的代碼，例如 G01）、五筆成員、組長（提案人）同時建立，提案變「已成立」，五個人的占用釋放，到期工作取消，全員收到「組別成立」通知。如果在成立那一刻發現有人已經在別的組（兩個提案同時成立撞到同一人），整筆回滾、提案以「衝突」終止，不會出現半成立的組。網路斷掉沒收到回執，重新整理就看得到結果。
- **做到哪裡**：本票交付確認用例、成立交易、代碼配號（規則 spec 未寫，暫用屆別內遞增）、「目前成員」查詢、成立事件、取消到期工作、確認回執與成立畫面、組長標示，以及用 app 角色跑正向流程的權限測試。各種終止與衝突終止的紀錄呈現由 S03-07。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01–S05 與 S06；要先有 S03-05 發出的開放中提案；從學生側欄 → 我的組別。

  | 操作 | 預期看到 |
  |---|---|
  | S01（提案人）按確認 | 回執「1／5 已確認」 |
  | S02、S03、S04 依序登入按確認 | 分別是 2／5、3／5、4／5；S05 仍標待確認 |
  | 換 S06 登入，由工程用他的身分送出對這個提案的確認 | 被拒（FORBIDDEN） |
  | S05 按確認 | 回執「組別已成立」；頁面顯示組別代碼、五位成員、組長是 S01 |
  | 五人各自看通知匣 | 各有一則「組別成立」 |
  | S03 登出再登入 | 我的組別頁仍是五人與組長 S01；找組員區不再列出這五人 |
  | 換 A1 看分組頁 | 列出這一組（代碼、五人、組長） |
  | 由工程重演「兩個提案同時成立含同一人」 | 一個成立、另一個被標終止（衝突），沒有人同時在兩組 |
- **誰確認**：工程核對／Roy 畫面操作確認（確認畫面是 Roy 指定要看的畫面）／平台由 Roy 提供（組別代碼配號規則定案）。

### S03-07 [模組03 分組、指導與產學] 拒絕、撤回、提案人撤回、到期、管理員作廢任一發生就終止提案並釋放所有人
- **票型**：feature
- **這張做什麼**：提案不是只有成立一條路。任何一位被邀請者按「拒絕」、已確認的人「撤回確認」、提案人「撤回提案」、業務鐘超過到期時間（背景工作自動處理）、或管理員填理由「作廢」——五種情況任一發生，提案就終止並記下終止原因，五個人全部釋放（可以再被別的提案邀請），到期工作取消，提案人與每位被邀請者各收一則終止通知（同一人只收一則、寫明原因、不含管理員的內部備註）。終止後再對這個提案按確認或拒絕都會被擋。終止紀錄留在學生頁可查。
- **做到哪裡**：本票交付四個終止用例、到期處理器（掛進 S02-07 的註冊表）、衝突終止的紀錄與通知、終止事件、學生頁的終止紀錄區、管理員作廢入口。成立由 S03-06；管理員維運的重跑由 S12。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01–S06 與 A1；要先能重複發起提案（每種終止各發一個）；從學生側欄 → 我的組別；管理員從分組頁。

  | 操作 | 預期看到 |
  |---|---|
  | S01 對 S02–S05 發提案，S03 按「拒絕」 | 提案標終止（被拒絕）；S01 與其他人通知匣各一則終止通知（S01 只一則） |
  | S06 立刻對 S03 發新提案 | 成功（占用已釋放） |
  | 在新提案裡 S03 先確認再「撤回確認」 | 該提案終止（成員撤回）；紀錄區多一列 |
  | S01 再發一個提案後按「撤回提案」 | 終止（提案人撤回） |
  | S01 再發一個提案，把業務鐘推過到期時間並等 30 秒 | 提案自動終止（到期）；沒有人再被占住 |
  | S01 再發一個，A1 在分組頁對它按「作廢」，理由留空 | 被拒，理由必填；填理由後終止（管理員作廢），學生看到的通知不含理由備註 |
  | 由工程用 S02 的身分對已終止的提案送確認 | 被拒（PROPOSAL_NOT_OPEN） |
  | S01 登出再登入看終止紀錄區 | 五筆終止紀錄各標原因 |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：無原型畫面（待實作畫面；模組 03 §7.2 列「逐人確認／拒絕／撤回、到期終止的畫面」為缺口）。

### S03-08 [模組03 分組、指導與產學] 管理員用表單直接建立三人例外組，填核可依據並指定組長
- **票型**：feature
- **這張做什麼**：有些組不走五人提案（例如校方核可的三人組），A1 在分組頁用「建立例外組」表單選成員、填理由與核可依據（誰核可、何時、適用人數、來源），並指定其中一人當組長。成立後這個組跟提案成立的組一模一樣（成員、組長、代碼），成員各收一則「組別成立」通知。零人、沒有核可依據、成員已在別組或正被提案占住，都會被拒。測試環境可以勾「模擬核可資料」並明確標示，production 不允許。
- **做到哪裡**：本票交付例外組用例（成員驗證、核可依據寫入、模擬旗標依環境擋、同交易建組）、表單與回執。成員異動與解散由 S09；人數上下限規則待校方 Q-GRP05 後另加。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1 與 S07–S09（未分組）、S02（已在 G01）；從管理員後台 → 分組 → 建立例外組。

  | 操作 | 預期看到 |
  |---|---|
  | 打開表單，不選任何成員送出 | 被拒（VALIDATION_FAILED），提示至少一人 |
  | 選 S07–S09，核可依據留空送出 | 被拒，核可依據必填 |
  | 選 S07–S09、填核可依據並勾「模擬核可資料」、指定 S07 為組長，送出 | 回執；分組頁多一組，標示「模擬核可」與三位成員、組長 S07 |
  | 換 S08 登入 | 通知匣一則「組別成立」；我的組別頁顯示三人與組長 S07 |
  | A1 再建一組並選已在 G01 的 S02 | 被拒（ALREADY_MEMBER） |
  | 由工程在 production 模式送出勾「模擬核可資料」的表單 | 被拒（VALIDATION_FAILED） |
  | 換 T1 登入直接送出建立例外組的請求 | 被拒（FORBIDDEN） |
  | A1 離開再回來 | 例外組仍在 |
- **誰確認**：工程核對／Roy 畫面操作確認。

### S03-09 [模組03 分組、指導與產學] 管理員填理由把組長換給另一位有效成員，全組收到通知並可查歷史
- **票型**：feature
- **這張做什麼**：組長要換人時，只有 A1 能做：在分組頁對某組按「更換組長」，選一位現任有效成員、填理由，確定後舊組長紀錄結束、新組長生效，全組收到一則「組長更換」通知並清楚寫出新組長是誰；學生頁與管理員頁都顯示現任組長與歷史。學生（包含現任組長本人）沒有換組長的路徑——組長自己只能改組別類型與連結合作案（那是 S06 的事）。
- **做到哪裡**：本票交付更換組長用例（只有管理員、理由必填、版本檢查）、組長更換事件、管理員對話框、歷史列表。成員異動時的組長接任由 S09；組長改類型由 S06-10。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1、S01（G01 現任組長）、S02（G01 成員）、S07（他組）；要先有成立的 G01；從管理員後台 → 分組 → G01 → 更換組長。

  | 操作 | 預期看到 |
  |---|---|
  | A1 選 S02 為新組長，理由留空 | 被拒（VALIDATION_FAILED），理由必填 |
  | 選一位不在 G01 的人（S07） | 被拒（VALIDATION_FAILED） |
  | 選 S02、填理由確定 | 回執；G01 顯示組長 S02；歷史列出 S01（已結束）與 S02（現任）及理由 |
  | 換 S03（G01 成員）登入 | 通知匣一則「組長更換」，寫明新組長 S02；我的組別頁組長標示是 S02，頁面上沒有任何「更換組長」按鈕 |
  | 換 S01（前組長）登入，由工程用他的身分送出換組長請求 | 被拒（FORBIDDEN），組長仍是 S02 |
  | A1 在兩個分頁各開一次對話框，第二個用舊資料送出 | 被拒（CONFLICT），要求重新載入 |
  | A1 登出再登入看 G01 | 組長 S02 與歷史不變 |
