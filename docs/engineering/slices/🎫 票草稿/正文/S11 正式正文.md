# S11 正式正文｜簽核：版本、逐人同意、老師、退回、重置、匯出、授權查詢（含最小精選草稿）

> 本檔是 S11 每張票的「可讀正文層」，票號、順序與 BLOCKED 標記照票草稿；技術九欄由產生器自動附在折疊區，這裡不重貼。環境依切片卡為 staging（未就緒時可用 local 並標明）。測試帳號只寫角色代號：A1 管理員；S01–S05 第一組 G1 成員；G2、G3 另兩組（G3 三人）；T1 G1 主指導、T2 其他組主指導、T3 G3 主指導。簽核有兩種用途：「期中結果確認」與「最終文件授權」；後者的授權範圍從該組的精選草稿凍結而來，所以本切片先交付最小的精選草稿能力（題目、摘要、海報、影片連結；不發布，發布與公開閘門在 S12）。

### S11-01 [模組07 線上簽核] 建立簽核五張表與精選三張表、不可變保護與角色權限
- **票型**：foundation
- **這張做什麼**：工程一次建好簽核要用的表（簽核包、版本內容、版本狀態、每人一票的同意紀錄、匯出紀錄）和精選要用的三張表（精選條目、可編輯的草稿、發布版本——發布版本本切片只建空表不寫）。版本內容、同意紀錄、匯出紀錄、發布版本寫入後不能改不能刪；「最終文件授權」的版本沒帶授權範圍會被擋。這是簽核與精選全部功能的地基。
- **做到哪裡**：本票交付建表腳本、不可變保護、授權範圍檢查、逐表權限與測試、程式端資料結構對照；空資料庫從頭逐切片升級要成功。任何畫面與操作都不在本票（S11-02 起）；S12 的公開閘門相關表由 S12-01；發布版本的寫入由 S12-04。本票目前是「工程基礎」。
- **Roy 如何確認**：本票由工程驗證；Roy 在 E11 整體展示確認 CI 的「空庫升級」與「舊資料升版」兩條工作都是綠燈，並看到工程附的八張表結構輸出與權限測試輸出。Roy 不需要讀 SQL。
- **誰確認**：工程核對。
- **原型畫面**：無原型畫面（待實作畫面）。

### S11-02 [模組07 線上簽核] 做出三個角色的簽核頁與管理員精選頁的入口、空狀態與權限邊界
- **票型**：feature
- **這張做什麼**：學生、老師、管理員的後台導覽各多一個「簽核」，管理員另多一個「精選」。這張票只把四個頁面的殼做出來：進去看到空狀態（學生／老師「目前沒有待處理的簽核」、管理員「尚未建立簽核」「尚無精選草稿」）、頁面上預留建版區、進度格、匯出區、草稿列表等位置；沒登入被導去登入，走錯角色顯示「無法存取」並給下一步。真正的功能從 S11-03 起逐張接上。

- **Roy 如何確認**：staging（或 local）；用 S01、T1、A1；不需要其他資料；從各角色後台導覽。

### S11-03 [模組09 公開展示與共用介面] 管理員為一組建立精選草稿：題目、摘要、海報、影片連結（不發布）
- **票型**：feature
- **這張做什麼**：A1 在精選頁對 G1 建立一份精選草稿，填題目、摘要、上傳海報圖、貼影片連結後儲存；離開再回來內容都在。這份草稿之後會被「最終文件授權」的簽核版本拿來凍結授權範圍（S11-04）。本切片沒有發布按鈕，頁面註明「發布功能尚未交付」，閘門欄固定顯示「尚無授權」。同一組同一屆只能有一份草稿；兩個管理員同時改同一份，後存的會被提醒重新載入。
- **做到哪裡**：本票交付建立與編輯草稿、海報上傳與換圖、儲存回執、草稿列表。發布、撤稿、素材核閱、外部授權登記、公開頁都在 S12。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1、A2、S01；要先有已成立的 G1 與一張 PNG 海報、一個非圖片檔；從管理員後台 → 精選 → 建立草稿。

  | 操作 | 預期看到 |
  |---|---|
  | A1 對 G1 建立草稿，填題目與摘要、上傳 PNG 海報、貼影片連結，儲存 | 回執；列表出現 G1 草稿；閘門欄「尚無授權」；沒有發布按鈕 |
  | 離開頁面再回來 | 題目、摘要、海報、連結都在 |
  | 把海報換成一個非圖片檔 | 被拒，提示檔案類型不允許；原海報保留 |
  | 再對 G1 建立第二份草稿 | 被拒，提示已有草稿 |
  | A1 與 A2 同時開同一份，A2 先存、A1 再存 | A1 被拒，提示內容已被更新請重新載入 |
  | 換 S01 開精選頁網址 | 「無法存取」 |
- **誰確認**：工程核對／Roy 畫面操作確認。
- **原型畫面**：無原型畫面（待實作畫面）。

### S11-04 [模組07 線上簽核] 管理員建立簽核版本：貼全文、選附件、快照參與者，最終文件授權從精選草稿凍結範圍
- **票型**：feature
- **這張做什麼**：A1 在簽核頁對 G1 建版：選用途（期中結果確認／最終文件授權）、貼全文、選附件（可含該組正式繳交的附件），最終文件授權還要選該組的精選草稿——草稿當下的題目、摘要、海報、影片連結會被凍結成這一版的授權範圍，之後草稿再改也不影響這一版。建版時把當時有效成員與主指導拍成參與者名單，每位參與學生收到一則「輪到你同意」。同一組同一用途已有收集中的版本時，建新版會讓舊版失效（要重簽）。版本頁在全文後面列出授權範圍，並標示「站內內容確認與同意紀錄，行政採認待確認」。
- **做到哪裡**：本票交付建版表單（含影響人數預覽）、版本頁、參與者快照、授權範圍凍結、輪到本人通知。同意與退回由 S11-05／06；重置由 S11-07；成員或主指導改變造成的失效由 S11-08；匯出由 S11-09。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1、S01、T1；要先有 G1（五人、主指導 T1）、G1 的精選草稿（S11-03）、G1 已有正式繳交附件；從管理員後台 → 簽核 → 建立版本。

  | 操作 | 預期看到 |
  |---|---|
  | A1 選 G1、用途「最終文件授權」，全文留空按建版 | 被拒，提示全文必填 |
  | 貼全文、選附件，但不選精選草稿 | 被拒，提示最終文件授權需選精選草稿 |
  | 選 G1 草稿後建版 | 回執含版本 v1、參與者 5 人；版本頁全文後列出授權範圍（題目、摘要、海報、影片連結）與「行政採認待確認」標示 |
  | 換 S01 登入 | 通知匣有一則「輪到你同意」；換 T1 登入，通知匣沒有 |
  | A1 回精選頁改 G1 草稿的題目，再開 v1 版本頁 | 授權範圍仍是建版當下的題目 |
  | A1 對 G1 同用途再建一版 | v1 標「已失效（內容變更）」，v2 收集中 |
  | 用途「期中結果確認」卻選了精選草稿 | 被拒 |
  | 重新登入看版本頁 | 內容一致 |
- **誰確認**：工程核對／Roy 畫面操作確認。

### S11-05 [模組07 線上簽核] 學生逐人閱讀後同意或不同意，最後一位同意後輪到老師
- **票型**：feature
- **這張做什麼**：S01–S05 各自登入簽核頁，讀全文與附件、看授權範圍、勾「我已閱讀」，按「我已閱讀並同意」；確認框提醒只代表自己一票，同意後自己那格記下時間、進度變 n／5，之後這頁唯讀。全部五人同意後狀態轉「等待老師」，T1 收到「輪到你」。任何一位不同意（理由必填）就整版回到修正狀態。已投過票再按、版本已失效再按都被擋；管理員沒有代簽入口，直接請求也被拒。同意紀錄含當時姓名學號、登入方式、按鈕原文。
- **做到哪裡**：本票交付學生簽核頁三態、同意與不同意、最後一票轉老師、進度查詢、首頁「同意書」磚的狀態。老師同意與退回由 S11-06；版本失效後的完整舊頁文案與新版入口由 S11-08（本票只回錯誤）；管理員頁由 S11-07。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 S01–S05、T1、A1；要先有 G1 收集中的 v1（S11-04）；從學生後台 → 簽核。

  | 操作 | 預期看到 |
  |---|---|
  | S01 開簽核頁 | 全文、附件版本下載、授權範圍、已閱讀勾選；首頁「同意書」磚「等你同意」 |
  | S01 不勾已閱讀直接按同意 | 按鈕不可用 |
  | 勾選後按同意並確認 | 自己那格記時間、進度 1／5；頁面變唯讀；首頁磚變「已同意」 |
  | S01 重新登入再開 | 仍是已同意、時間相同 |
  | S02 按不同意但理由留空 | 被拒，提示理由必填（本輪先取消，改為同意） |
  | S02–S05 依序同意 | 進度 5／5，狀態「等待老師」；換 T1 登入，通知匣有「輪到你」 |
  | A1 在管理員頁找代簽入口，並直接對 S03 那格送出請求 | 沒有入口；直接請求「無法存取」 |
  | 另一組 G2：S06 按不同意並填理由 | 該版狀態變「修正中」；其他成員的頁面顯示已退回原因 |

### S11-06 [模組07 線上簽核] 老師最後同意或退回；學生沒全同意前不能按
- **票型**：feature
- **這張做什麼**：T1 在老師簽核頁看到各組卡片：「第 02 組輪到你」「第 07 組等待學生」。學生還沒全部同意時按鈕不可用，就算直接送請求也被伺服器擋。全員同意後 T1 按同意（確認框提醒只代表自己一票）→ 版本完成，完成當下仍有效的參與成員與主指導每人收到一則「此版本站內簽核已完成」（不代表校方採認）。T1 也可以不同意並退回（理由必填），整版回到修正狀態。
- **做到哪裡**：本票交付老師簽核頁、老師同意、退回、完成通知。換老師後的失權文案由 S11-08；新版建立後舊通知標歷史由 S12-10。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 T1、T2、S01；要先有 G1 v1 已 5／5 等待老師（S11-05）、G2 仍在收集中且 T1 也是 G2 主指導；從老師後台 → 簽核。

  | 操作 | 預期看到 |

  | T1 開簽核頁 | G1 卡「輪到你」、G2 卡「等待學生」 |
  | 對 G2 按同意 | 按鈕不可用；用開發者工具直接送請求被拒，提示學生尚未全部同意 |
  | 對 G1 按同意並確認 | 回執；G1 卡變「已完成」 |
  | 換 S01 登入 | 通知匣有一則「此版本站內簽核已完成」；T1 自己也有一則 |
  | T1 對 G1 再按一次同意 | 被拒，提示已投票 |
  | 換 T2 登入直接對 G1 送同意 | 被拒，不是這一版的參與者 |
  | 另一組 G3（T3 主指導，已 3／3）：T3 按不同意並填理由 | G3 狀態「修正中」；換 S11 登入看到退回原因 |

### S11-07 [模組07 線上簽核] 管理員看整體進度與缺誰、重置或作廢版本；三個角色看到一致進度
- **票型**：feature
- **這張做什麼**：A1 在簽核頁看到整體完成數與每組格子（每格一位學生、右邊短格是老師），點「缺 N 位」展開還沒同意的名單。對退回中的 G3 按「重置」：對話框列出將失效的簽署、理由必填，確定後建立新版本重新收集，舊版與舊的同意紀錄保留為歷史。「作廢」（理由必填）讓目前版本作廢，學生不能再投。學生、老師、管理員在「部分同意、等待老師、退回、完成」四種狀態下看到的進度與缺誰都一致，因為來源同一份。
- **做到哪裡**：本票交付管理員簽核頁完整（進度、缺誰、版本歷史）、重置、作廢、三角色一致的進度查詢。建版本體由 S11-04；成員／主指導改變造成的失效與解散作廢由 S11-08；匯出由 S11-09；提醒未同意者由 S11-11；「重開」由 S11-12（BLOCKED D-01）。本票目前是「可操作功能」。
- **Roy 如何確認**：staging（或 local）；用 A1、S11、T3、S01；要先有 G1 完成、G2 收集中 2／5、G3 修正中（S11-05／06）；從管理員後台 → 簽核。

  | 操作 | 預期看到 |
  |---|---|
  | A1 開簽核頁 | 整體完成數；G1 全格打勾、G2 兩格打勾、G3 標修正中 |
  | 點 G2「缺 3 位」 | 展開三個名字 |
  | 對 G3 按重置，理由留空 | 被拒，提示理由必填 |
  | 對話框列出將失效的簽署，填理由確定 | 回執；G3 出現 v2 收集中 0／3；版本歷史仍列 v1（修正中→已失效，原因「重置」）與舊同意紀錄 |
  | 換 S11 登入 | 通知匣有「輪到你同意」；簽核頁是 v2、進度 0／3 |
