## 讀 spec 時發現的問題（不改 spec，只列）
1. **每日備份的排程機制未寫**：SOP 04 只寫「03:00 真實時間 `backup` 服務…」，恢復段寫「手動 `docker compose run --rm backup`」（暗示一次性容器），但沒寫由誰在 03:00 觸發（host crontab、容器內 cron、常駐迴圈）；SOP 01 步驟沒有 crontab 項；S00-07 的 `backup` 服務定義也未寫是常駐或 one-shot。S14-06 假設 host crontab `docker compose run --rm backup`，請 Roy 定。
2. **`storage_stats` 寫入者三處不一致**（同 S12 問題 10）：模組 10 附錄 A 與契約 01 §5「worker 每小時寫」、模組 10 §5 `recordStorageStats` 授權「backup 服務／cron」、SOP 05 步驟 2「VM cron 每小時 `df`」。S14-07 依契約 01 §5 起草。
3. **磁碟告警沒有事件型別**（同 S12 問題 11）：`digest_events.kind` 只有 `overdue`、`unassigned_groups`、`projection_failed`、`backup_failed`；SOP 05 步驟 2「≥80% 站內通知管理員」與 SOP 04「磁碟 80%」無法對應到事件目錄。S14-07 的站內通知部分待 kind 定案（需 migration 改 CHECK，屬 expand）。
4. **SOP 06 步驟 3 的環境保護句讀不通**：「reset 腳本必須拒絕在 `BUSINESS_CLOCK_OVERRIDE_ENABLED=false` 以外的環境變數組合下被誤當 staging 使用（`--confirm` 需等於當日）」——切換時 reset 是在 staging（override=true）上執行、之後才改 false（步驟 5），字面條件會讓正常流程被拒。S14-11 只實作 `--confirm=<當日>` 與 owner 連線限制，環境變數條件請 Roy 改寫。
5. **清除範圍兩處不一致**：契約 05 §9 表沒有「保留 DB 角色、`backup_runs`、`restore_drills`、`storage_stats`」列，也沒有 `digest_events`、`business_clock_overrides`；SOP 06 步驟 3 表有這些但沒有契約 §9 的「公開資源、快取：刪除；重啟後快取空」與「舊 session 與舊 requestId」列。S14-11 以兩表聯集起草（保留備份三表與角色；刪除快取；測舊 cookie）。
6. **還原演練寫入哪個資料庫未明**：SOP 04 步驟 3「`pg_restore` 到 drill 資料庫（owner 連線的 drill 版本）」、步驟 5「以 `pnpm ops:record-drill`（app 容器、app 連線）寫 `restore_drills`」、步驟 6「`down -v`」——若寫進 drill DB 會隨 `down -v` 消失，S12-15 狀態頁（讀正式 staging DB）看不到。S14-09 假設寫入正式 staging DB（主線的 app 容器），請確認。
