## 0. 怎麼讀、三個完成層次、票欄位

- **拆法**：按切片拆、按可觀察結果拆；十份 spec 與五份契約用來核對漏需求，不按模組各做一包。共用的 migration、port、handler 註冊、頁面殼獨立成前置票；功能票只列它們為前置。票數依工作大小，不湊配額。
- **三個完成層次**（契約 04 §5）：**單票完成**＝該票行為、票列自動測試綠、Fable review、票列操作證據（`steps/<切片>/<票>/`），Fable 關票；**切片出場（epic）**＝四項既定 gate（本切片自動測試全綠、切片操作起點走通留 `steps/<切片>/`、Fable review、卡上要求的 Roy 看畫面），Roy 關 epic；**年度案例 PASS**＝S13 出場後同一版本一次跑完 P00–P09、B01–B08，依責任表判定。單票測試綠不關 epic；epic 不要求案例 PASS；票上的案例 ID 只作覆蓋追溯。
- **每票固定欄位**：目標｜spec｜範圍／非範圍｜前置｜路徑（正常／拒絕／重試）｜自動測試｜操作證據｜完成定義｜待 Roy／平台。前置只能引用同切片編號更前的票、更早切片的票號、或 `E0x 出場`。
- **編號**：`E00`–`E14` 切片 epic；票 `SNN-MM`；同切片內順序＝建議開工順序。
