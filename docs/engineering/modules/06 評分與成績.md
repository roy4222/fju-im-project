# 模組實作設計 06｜評分與成績（v2.3）

## 1. 使用者要完成的工作與案例

- 工作：系辦設方案、要求份數、指派；老師暫存與正式送出；系辦退回、改派（保留／替換／新增）、更正與復核、匯出；學生永遠看不到分數。

## 2. 名詞與不變量
- 分母＝`stage_requirements.required_count`；分子＝該組該階段 `evaluation_status.state='counted'` 數；每指派最多一筆 counted（部分唯一）。
- 只有「明確新增」增加 required_count。
- 方案版本第一筆正式評分後鎖定；改動走新版本，套用前預覽。
- 更正保留原值與新值；採計、來源版本或方案改變後既有更正 `pending_review`。
- 更正只針對**最終結果**（階段結果更正不在範圍）；最終結果尚未完成（任一階段 incomplete）時更正拒 `FINAL_INCOMPLETE`（P07 步驟 20 驗此；更正本身在 P08 步驟 8）。
- **預覽綁 `basis_hash`（v2.1，RR10）**：改派預覽回傳 `basis_hash`＝sha256(該組該階段有效指派 ID 排序集合 ＋ counted 評分 ID 集合 ＋ `required_count` ＋ 方案版本 ID)；執行時在鎖內重算比對，不同即 `CONFLICT`。
- 學生輸出不含分數評語排名（policy 與 DTO 白名單）。

## 6. 交易與並行（回覆 R06）
- 正式送出：`evaluator_assignments` **`FOR UPDATE`**（仍 active）→ 若同指派已有 counted 則拒（`CONFLICT`，需先退回）→ insert `evaluations(final)`＋`evaluation_status(counted, assignment_id)`；部分唯一 `(assignment_id) WHERE state='counted'` 為後盾。
- 退回（v2.2，Codex A2）：與改派同序——先 `groups` `FOR SHARE`、再對該評分的 `evaluator_assignments` 列 `FOR UPDATE`（仍 active，否則 `NOT_ASSIGNED`）、再對 `evaluation_status` `FOR UPDATE`；狀態必須仍是 counted（改派後已 historical → `CONFLICT`）→returned＋事件；再送才可新 counted。改派執行鎖該組該階段全部有效指派列，所以退回與改派互相排隊，退回不會在 `basis_hash` 比對後改掉採計集合。
- 移除指派（v2.1，RR10）：執行時 `groups` `FOR SHARE` → 該組該階段全部有效 `evaluator_assignments` 列依 id 順序 `FOR UPDATE` → 鎖內重算 `basis_hash` 與預覽 token 比對，不同即 `CONFLICT`（不看單列 revision）；keep：狀態不動、`valid_to`；replace：counted→historical、新指派、缺評；add：新指派、required_count+1；draft 一律 invalidated；受影響更正→pending_review；事件。正式送出只鎖自己的指派列，因此與執行互相排隊、不死鎖。
- 更正：insert `grade_overrides`＋`override_review_state(effective)`；基礎變更用例同交易把相關 override 標 pending_review 並發事件給管理員（首次）。
- 解散：`stopForDissolution` draft invalidated、counted 保留唯讀、指派 `valid_to`。

### 7.2 尚無原型畫面的流程與狀態（缺口；不用假圖補）

- 改派三選一預覽對話框與 `CONFLICT`（預覽過期）
- 待復核清單與復核操作
- 匯出 XLSX／CSV
- 停用老師後的分母與缺評顯示
- 計算明細頁（82.145／85.287 的 decimal 值）
- 結果未知

## 8. 序列
正常：方案 60／40→指派 T1、T3 評 G1（required 2）→T1 暫存 80→正式→T3 84.29→平均 82.145 顯示 82.15→期末 90→最終 85.29。改派：T1→T2 選 replace→80 historical→1／2→T2 送出重算。退回：A1 退回 T2→T2 重送。更正復核：G3 更正→T3 重送→pending_review→管理員通知→沿用或新更正。停用：未送列缺評、已送採計。並行：T3 兩個不同 requestId 同時送出→一 counted 一 `CONFLICT`。

## 9. 保存、匯出、他角色所見
原始輸入、狀態事件、更正與復核保留；匯出 XLSX／CSV 只管理員（文字儲存格）；學生頁面／API／匯出掃描無分數。

## 10. 自動測試
單元：decimal 計算與捨入、權重驗證、三選一影響、待復核觸發。整合：兩個 requestId 並發正式送出只一筆 counted；送出×退回並發；移除指派三分支；預覽過期；停用不縮分母；解散停止；學生 DTO 掃描。對應 GRD-01–15；預覽衝突四種（同指派送分、另一指派送分、退回、方案套用）都使舊 `basis_hash` 失效；最終未完成時更正拒 `FINAL_INCOMPLETE`；退回×改派執行同步屏障（先後兩種順序都只有一方成功；後者依狀態回 `CONFLICT`（評分已 historical）或 `NOT_ASSIGNED`（指派已結束），與 §6 分類一致）。

## 11. Codex 操作
劇本 P07（期中評分、最終未完成時更正被拒）、P08（期末、最終結果更正）、B04（改派、預覽衝突、停用、更正復核）。證據：計算明細頁、`evaluation_status`、匯出檔、學生頁 HTML／JSON 掃描。
