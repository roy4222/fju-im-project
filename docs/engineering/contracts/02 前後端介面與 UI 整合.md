## 1. 輸入、DTO、Result 與錯誤碼

```ts
type Ok<R> = { ok: true; receipt: R & { requestId: string; serverTime: string } }
type Err = { ok: false; code: ErrorCode; message: string; next?: NextStep; details?: Record<string, unknown> }
type Result<R> = Ok<R> | Err
type NextStep = { kind: 'reload'|'login'|'home'|'contact_office'|'retry_same_request'|'query_result'|'change_password'|'pending_page'; href?: string }
// 一次性秘密回應（R04）：不是 Result 的 receipt；秘密只在此型別，不進帳本、audit、log
type SecretOnce = { ok: true; secret: string; issuedAt: string; expiresAt: string; receipt: { requestId: string; kind: 'temp_password'; issuedBy: string } }
```

輸入 DTO 由 Zod 定義在 `application/<m>/dto.ts`；所有副作用 DTO 必含 `requestId`（UUID v4 由前端產生）與相關 `revision`。

錯誤碼（`shared/errors.ts`）：

| 分類 | 代碼 | 下一步 |
|---|---|---|
| 身分 | `UNAUTHENTICATED`、`ACCOUNT_PENDING`、`ACCOUNT_DISABLED`、`PASSWORD_CHANGE_REQUIRED`、`FRESH_SESSION_REQUIRED`、`TURNSTILE_REQUIRED` | login／pending_page／disabled 頁／change_password／重新登入／顯示驗證 |
| 授權 | `FORBIDDEN`、`NOT_MEMBER`、`NOT_ASSIGNED`、`NOT_IN_ROSTER`、`EXEMPTED`、`COHORT_ARCHIVED`、`COHORT_MISMATCH`、`NOT_PARTICIPANT` | home 或 reload |
| 狀態 | `ITEM_NOT_OPEN`、`DEADLINE_PASSED`、`VERSION_SUPERSEDED`、`PROPOSAL_NOT_OPEN`、`GROUP_DISSOLVED`、`SCHEME_LOCKED`、`ALREADY_CLAIMED`、`ALREADY_MEMBER`、`INVITED_ELSEWHERE`、`STUDENT_NO_TAKEN`、`STUDENTS_PENDING`、`ALREADY_VOTED`、`ITEM_HAS_RESPONSES`、`OPPORTUNITY_NOT_LINKABLE`、`AUTHORIZATION_NOT_COVERED`、`ASSET_NOT_APPROVED`、`PII_DETECTED`、`FILE_REFERENCED`、`FINAL_INCOMPLETE` | reload |
| 併發 | `CONFLICT`、`REQUEST_MISMATCH` | reload 並顯示差異；REQUEST_MISMATCH 不自動重試 |
| 輸入 | `VALIDATION_FAILED`、`SCHEMA_INVALID`、`FILE_NOT_READY`、`FILE_NOT_OWNED`、`FILE_TYPE_REJECTED`、`FILE_TOO_LARGE`、`DRAFT_NEEDS_REVIEW` | 修正輸入 |
| 帳本 | `RECEIPT_EXPIRED`（回執本體已清、結果參照仍在） | 顯示結果參照 |
| 系統 | `INTERNAL`；前端狀態 `RESULT_UNKNOWN` | query_result |

回執範例（組別正式送出）與錯誤範例沿用 v1；每個回執必含 `requestId`、`serverTime`、業務時間版本（如 `receivedAt`）。

## 2. Server Action 與 Route Handler 分工、OperationContext

| 用途 | 機制 |
|---|---|
| 讀取 | Server Component 呼叫 query port |
| 一般變更 | Server Action（`app/**/actions.ts`：檔頭 `'use server'`，只匯出 async 函式；函式內經 `composition` 取用例） |
| 檔案上傳、下載 | Route Handler 串流（`/api/files/upload`、`/api/files/[id]`） |
| 匯出 | Route Handler，每次授權 |
| Auth | `app/api/auth/[...all]` 經契約 03 矩陣 |
| 結果查詢 | Server Action `getOperationResult(requestId)`，只回本人 |
| health | `GET /api/health` |

所有入口第一步建立 `OperationContext{actor, sessionId, loginMethod, requestId, receivedRealAt, receivedBusinessAt}`（`loginMethod` 讀目前 session 列的 `sessions.login_method`，契約 01 §4.1），時間在完整 body 解析完成當下取樣；Route Handler 在 multipart 全部讀完並 finalize 後才算完整。客戶端宣告的時間一律忽略。

## 4. 衝突、結果未知與重試協議（回覆 R08）

| 情況 | 前端行為 |
|---|---|
| `CONFLICT` | 顯示「別人已更新，你的輸入保留在本機」，提供載入最新並比對；不自動覆蓋 |
| 網路失敗、逾時、無回應 | 狀態列「結果尚未確認」；以同一 requestId 呼叫 `getOperationResult`：有回執→顯示成功；`NOT_FOUND`→允許以同一 requestId 重送；`RECEIPT_EXPIRED`→顯示結果參照；查詢失敗→保留按鈕可再查 |
| 連點 | 同一 requestId；伺服器回原回執 |
| `REQUEST_MISMATCH` | 「這筆操作已用不同內容送出過」，要求重新載入 |
| `VERSION_SUPERSEDED` | 顯示新版本入口 |
| `UNAUTHENTICATED` | 導 `/login?returnTo=`；本機草稿輸入放 sessionStorage |
| `ACCOUNT_PENDING` | 導等待審核頁（可修改申請） |
| `PASSWORD_CHANGE_REQUIRED` | 導改密頁；成功後回原頁 |
| 一次性秘密回應遺失 | 顯示「已核發但無法取回」，提供「重新核發」（舊密碼失效）；不重播 |

「未送出」只在伺服器明確回錯誤時使用。

## 5. schema 新版與草稿遷移（模組 04／05）

新 schema 發布前對每份既有草稿計算遷移預覽：`key` 相同且型別相容→自動帶入；`key` 消失→保留在 `drafts.legacy_answers`；型別不相容或新必填無值→`migration_state='needs_review'`。學生開啟 needs_review 草稿看到差異清單；送出時草稿必須是新版且 state none，否則 `DRAFT_NEEDS_REVIEW`。已正式版本不動。

## 6. 檔案傳輸

上傳：先取 `uploadTicket`（Server Action：actor、項目、欄位、類型與大小上限）→ `POST /api/files/upload?ticket=` 串流，邊寫 `tmp/<id>` 邊算 sha256 → finalize（magic bytes、宣告 MIME、大小）→ `stored`；失敗刪暫存回 `FILE_TYPE_REJECTED`／`FILE_TOO_LARGE`。Caddy `request_body max_size 105MB`；Server Action `bodySizeLimit` 維持預設 1 MB，永遠不用 Server Action 傳檔；不做續傳；中斷殘留 24 小時後 GC。下載 `GET /api/files/[id]` → `AuthorizeFileDownload` → 串流，`nosniff`、`attachment`。

## 7. server／client 邊界

Client Component 只能引用同功能目錄的 `actions.ts`、`application/<m>/dto.ts` 型別（type-only）、`shared` 純型別、UI 元件；頁面資料以 props 傳給 client。`app/**/actions.ts` 檔頭是 `'use server'` 指令（Next 16 規則：頂層 `'use server'` 的檔案所有匯出必須是 async 函式，Client 匯入時得到 Server Function 參照），檔內可引用 `composition`，**不加** `import 'server-only'`；`composition/*`、`infrastructure/*` 檔頭 `import 'server-only'`。lint：Client 匯入 `actions.ts` 是明確例外，Client 匯入任何 `server-only` 模組或 `composition`／`infrastructure` 一律擋；另加規則「`actions.ts` 只能有 async 函式匯出」；`lint-fixtures` 各放合法例（Client 表單呼叫 Action）與反例（Client 直接匯入 composition），並在 S00 以最小 Client 表單呼叫 Action 的 build 證明。

## 8. 快取矩陣與公開閘門（回覆 R09、R17；Next 16.3.1）

| 資料 | 策略 | 失效 | 更新時點 |
|---|---|---|---|
| 一般公開內容（公告、規則、榮譽） | `'use cache'` 於資料函式＋`cacheTag` | 發布／下架 action `revalidateTag(tag,'max')` | 下次造訪先舊後新 |
| **授權相關公開內容（精選成果、海報、OG、JSON）** | 每請求先呼叫 09 `PublicationGate.isPublishable`（查 07 簽核有效性、09 外部授權、素材版本 checksum 與核閱）；通過才使用快取片段 | 撤權當下即生效；worker 只做撤稿整理與 tag 失效 | 立即 |
| 私有查詢 | 不快取，每請求讀 DB | — | 重載即最新 |
| 權限事實 | 永不跨請求快取 | — | 撤權後下一請求 |
| 回執後同頁 | action 內 `updateTag(...)` | — | 立即 |
| 統計 | 每請求計算 | — | 即時 |
| 已開分頁 | 不推送；`visibilitychange` 時 `router.refresh()` | — | 重新聚焦 |
| 通知匣 | 不快取；鈴鐺每 60 秒輪詢 | — | ≤60 秒 |

單參數 `revalidateTag(tag)` 已 deprecated，不用。

## 9. CSP 與渲染（待 Roy 決定；選項見母 spec §4.15）

預設方案 A：全站動態渲染＋Proxy 產生 nonce＋`strict-dynamic`；`'use cache'` 只用在資料函式。若 Roy 選 B（實驗性 SRI）或 C，本節與契約 03 §6 同步改。任一方案都要驗證 hydration 正常且非預期腳本被擋。

## 10. 登入、改密、待審與角色切換

- pending 與 must-change 帳號可以登入取得受限 session（契約 03 §2 矩陣）；pending 只到等待審核頁（可修改申請）；must-change 只到改密頁。
- 角色切換 cookie `ui.role`、屆別切換 `ui.cohort` 只選畫面，不作授權。

## 11. Turnstile（回覆 R11）

前端只在伺服器告知需要時渲染 widget（`TURNSTILE_REQUIRED` 帶 `siteKey` 與 `action`）；token 隨表單送出；伺服器驗證規則在契約 03 §7。
