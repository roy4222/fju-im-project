# 共用契約 04｜測試與驗收（v2.1）

> 2026-09-12 v2：依母 spec v3.2 §5 與 Codex R12、R13、R14／SL06 重寫。本文只定**規則、環境、證據格式、結果定義**（A）；Codex 逐步操作劇本在 `📖 操作與驗證`（B）；案例責任表在 `🧱 實作切片/01 案例責任表`（C）。已寫、待 review；149 案全部 NOT_RUN。

> 2026-09-12 v2.1（Codex 第二輪 RR03、RR11）：§5 區分「切片出場」與「年度案例 PASS」，出場不要求案例 PASS 也不得依賴後繼切片；§6 副本取樣加寫入暫停窗口與逐檔 checksum 核對。

## 1. 追溯鏈與責任

產品條文 → 案例 ID（149，唯一）→ 子 spec 第 10／11 節 → 切片卡與案例責任表 → 自動測試檔名或 Codex 劇本步驟 → run 目錄。每個非延後案例有**一個最終驗收責任切片**與**環境**；早期切片可先做子步驟並留證據，但案例結果在最終責任切片完成前只能是 NOT_RUN 或 BLOCKED，不得升為 PASS。

## 3. 四欄判定

| 欄 | 要證明什麼 | 固定序列或清單 | 證據 |
|---|---|---|---|
| UI 與入口 | 哪種身分或狀態看到哪個入口；送出中、成功、錯誤、未知、衝突的顯示 | — | 截圖＋DOM 文字 |
| 操作邏輯 | Given 前置、When 動作、Then 成功或拒絕與後置狀態 | — | action 回傳 JSON |
| 持久化 | 儲存→離開頁面→重新載入→另一角色讀取→查歷史 | 五步都做 | 重載截圖、SQL 輸出、hash |
| 授權 | 直接請求、跨人、跨組、跨屆、失權、舊版本 | 六種都測適用者 | 直接請求回應、前後 hash |

涉及時間、並行、背景工作、不可變資料的案例再列：權威時間、鎖或唯一性、重試 key、故障注入位置、恢復後最終狀態、秘密不得出現的位置。結果只用 NOT_RUN／PASS／FAIL／BLOCKED／N/A；設計狀態另記。

## 5. 環境階梯與 Gate 界線

| 環境 | 用途 | 可驗收的層 |
|---|---|---|
| local（開發者 Compose） | 自動測試、切片出場的操作起點證據（`steps/`；staging 未就緒時任何切片都可在 local 取得） | lint、DB 整合、local browser |
| staging（校方 VM） | 第一次部署時點待 Roy（預設 S01 後）；之後所有切片的瀏覽器驗收與完整年度 | browser、VM、SOP |
| production | SOP 06 切換後 | 正式 Gate |
| 人工 | Roy 看 UI 與手機、Google 三案、Turnstile 真實服務；校方核可 | 人工 Gate |

lint、DB 整合、browser、VM、人工接受分列，不因前一層通過自動升級。

**切片出場 ≠ 年度案例 PASS（v2.1）**：切片出場條件＝該切片自動測試綠、切片操作起點（只用本切片與前置切片已交付的功能，清單在切片總圖）走通並留 `steps/<切片>/` 證據、Fable review、Roy 看指定畫面；不要求任何產品案例 PASS，也不得要求後繼切片才有的功能。產品案例的 PASS 只在 S13 出場後以同一版本一次跑完的完整年度（P00–P09、B01–B08）判定；責任表的「最終責任切片」是指該案在完整年度出現缺陷時由哪張切片負責修，不是該切片的出場門檻。

## 6. 只 seed A1 的主線與分支（回覆 R14／SL06）

- 主線：一個 run ID、一個受測版本、從只有 A1 的空庫開始，115-TEST、帳號、名單、組別、項目、版本全部由 UI 產生，最後建 116-TEST。
- 分支：需要破壞主線的案例用獨立 run，起點是主線某階段的**隔離副本**：`pg_dump` 副本＋附件目錄複本（檔案 manifest hash 相符）＋獨立 Compose override（不同 DB URL、port、附件目錄、worker 關閉或指向副本、通知不指真實通道）；結束後不回填主線；來源樣本 hash 必須不變。副本取樣（SOP 04「隔離副本」）：先停 app 與 worker（主線在 checkpoint 暫停），確認沒有在途上傳，再依序 `pg_dump`、複製附件目錄；以 dump 內全部有效 `file_references` 逐一核對副本檔案存在且 sha256＝`checksum`，全部相符才算副本成立；分支劇本 §2 列出副本內必須新建的帳號與資料，操作人不得臨時補 fixture 或直接改 DB。
- 局部重跑：修復後只重跑受影響案例並記新版本；完整年度通過必須同一版本一次走完。

## 7. run manifest 與證據格式

```
📖 操作與驗證/runs/<run-id>/
  manifest.json   { runId, kind: mainline|branch|partial, commit, imageDigest, schemaVersion, workerVersion, env, dataset, businessClockStart, startedAt, operator }
  cases/<CASE-ID>.json { status, ui, logic, persistence, authz, evidence:[...], requestIds:[...], versionIds:[...], notes, defects:[...] }
  steps/<劇本>-<步驟>.json   子步驟證據（不升為案例 PASS）
  evidence/<CASE-ID>/...
  defects/<n>.md  { caseId, version, businessAt, lastGoodStep, actual, expected, evidence, severity }
```

缺陷分級：S1 資料遺失、越權、主線阻塞（Gate 阻擋）；S2 功能錯有繞路；S3 文案體驗。

## 8. 進場條件

Fable 交付：環境 URL 與版本（commit、映像 digest、schema、worker）、A1 取用方式（經密碼管理器）、去識別 CSV 與測試檔、三角色登入步驟、業務鐘操作與重置說明、案例責任表、劇本清單、run 目錄範本。缺一即 BLOCKED，並在 manifest 記阻塞原因。
