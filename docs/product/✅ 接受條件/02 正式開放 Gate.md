## 每案結果如何記

案例設計狀態是「可執行設計／待決／延後」，執行結果另用 NOT_RUN、PASS、FAIL、BLOCKED，不混用。每案記 run ID、commit、環境URL、資料集、角色、真實時間、業務日期、前置、實際步驟、預期、實際、四欄結果與證據路徑、缺陷或阻塞原因。

四欄分別是：UI（畫面文字與可操作）、操作邏輯（狀態轉移與拒絕）、保存（重整重登入後ID／版本／hash）、權限（其他角色與直接請求）。不適用可寫 N/A 並說明；未提供證據寫 NOT_RUN／UNKNOWN。截图不能單獨證明DB保存或API權限；API測試也不能代替Roy看操作。

規格與案例住產品區，執行結果及artifact住工程區「📖 操作與驗證」。每個重要成功動作都要四欄，不只挑三個示例。草案內SUB案例的示範PASS／FAIL不是實測結果，不轉抄成通過。
