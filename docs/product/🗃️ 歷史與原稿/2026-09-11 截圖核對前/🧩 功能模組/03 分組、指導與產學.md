### 誰、什麼時候、從哪裡進來
分組期學生會用到：沒組的人開「公開找組員」讓同屆看到自己；組長提出五人名單，五個人各自登入按確認，全員確認後組別才成立；不足五人的例外由系辦建立。指導老師期：一般組由系辦依抽籤結果指派，產學組的老師在「分組總覽」看到「可認領產學組」先按先得。產學合作案由老師在「產學合作」建立，公司聯絡資料只有案主與系辦看得到；學生登入後在前台看合作案列表，訪客看不到。

### 一步一步怎麼操作
1. 學生進「我的組別」：看到第 07 組 3/5 已確認，兩位待確認；下方「找組員」列出開啟公開的同屆未分組學生，只有姓名、學號、聯絡方式，不顯示電話。
2. 組長填「專題分組名單確認表」（作業區）指定組長學號與組別類型；成員各自確認的動作在原型裡沒有獨立畫面，只看得到狀態。
3. 老師進「分組總覽」：上方「產學組認領」列出可認領的產學組，按「認領」→ 確認 → 看到「已指定為你的組別」；若被別人搶先，看到「已被其他老師認領」。
4. 系辦在「分組總覽」看未分組學生（可「加入某組」填理由）與全部組別；對一般組按「指派老師」選老師並填理由，對已有老師的組按「重派」，對話框說明評分與簽核指派會一併移轉；點組別名稱開詳情抽屜看成員、老師、繳交。
5. 老師進「產學合作」按「新增合作案」填公司、部門、內容、條件、備註，下方地址／聯絡人／電話／Email 標「只有你與系辦看得到」，儲存為草稿或開放學生；之後可編輯、下架。
6. 學生在前台「產學合作」看列表與詳情，聯絡資訊區寫「僅負責老師與系辦可見」，可看到已連結的組別。

### 操作後自己與其他角色看到什麼
學生：我的組別狀態、找組員名單、首頁「組員確認 3/5」磚。老師：認領後首頁「指導組別」多一組，該組的評分與簽核入口出現。系辦：分組總覽的統計（9 組、44 人已分組、4 人未分組、產學未指派）與操作紀錄多一筆含理由的指派／重派。

### 畫面現況
已有畫面：學生我的組別與找組員、名單確認表、老師分組總覽與認領（成功／衝突）、老師與系辦的產學合作管理、新增／編輯合作案、系辦指派／重派／加入某組對話框、組別詳情抽屜、前台產學列表與詳情、訪客 403。只是預期（尚無原型）：組長發起提案與成員逐一確認的畫面、拒絕提案、例外組建立表單、解散或重組的影響預覽、組別類型變更警告。要討論：拒絕／過期／退出的提案狀態表（Q-GRP01）、解散重組後繳交與成績怎麼承接（Q-GRP02）、一案多組是否正式採用（Q-GRP03）、一般組行政指派的輸入（Q-GRP04）。

## 1. 目的與範圍
完成正常五人及管理員例外分組，維護主指導與產學關係。

## 2. 角色與入口
學生找組員／我的組別；老師全部組別、產學案與認領；管理員分組工作台。

## 3. 主要操作
先依下一節業務規則操作；正常跨模組順序見 [年度主線](<../🔁 年度情境/01 完整年度主線.md>)，本模組逐案步驟在第 11 節。

## 4. 產品規則
### 5.1 名單與找組員

- 已驗證的本屆學生可查看本屆已分組與未分組名單。
- 未分組學生的「公開找組員」預設關閉，必須本人主動開啟。
- 開啟後，僅向同屆已驗證學生、老師與管理員顯示姓名、學號與聯絡 Email；電話不公開。
- 關閉公開、完成分組或帳號停用後，聯絡資訊立即隱藏。
- 名單明確分成本屆與過往屆別；過往資料預設唯讀，不和本屆未分組混在一起。

### 5.2 正常五人分組

1. 組長輸入剛好五位有效學生學號，包含自己。
2. 系統檢查同屆、未在其他有效組別、沒有另一個進行中申請。
3. 五位成員各自登入確認。
4. 五人全部確認後，以單一 transaction 成立組別。
5. 任一人拒絕或申請過期，不成立半套組別。退回修改／作廢及釋放占用規則存在來源衝突，見 Q-GRP01。

- 非五人組只能由管理員建立例外，並記錄理由。
- 並發確認、重複送出或同一學生同時被兩組邀請，不得造成雙重 membership。

### 5.3 一般專題與產學合作

- 分組類型保留：`GENERAL` 一般專題、`INDUSTRY` 產學合作。
- 建組前學生可表達個人意向；成組後以組別類型為準。
- 組長可在允許期間修改組別類型，所有組員可看見；變更要留 audit。
- 若變更會和既有指導老師或產學案連結衝突，系統警告並交管理員處理，不可靜默刪關聯。
- 分類只影響流程與標示，**不限制老師看見哪些學生／組別**。

### 5.4 指導老師規則

- 所有老師都可查看一般與產學組別。
- `INDUSTRY` 且尚未指派的組別，老師可按「指定為我的組別」直接認領。
- 認領採 first-success transaction；同時兩位老師操作時只能一位成功，另一位收到明確衝突訊息。
- 管理員可覆寫、重新指派或解除指派，必須填理由。
- `GENERAL` 組別由管理員依抽籤／行政結果指派，不提供自由搶占。
- 每組 v1 僅有一位主要指導老師；未來若要共同指導再另改資料模型。

### 5.5 管理與匯出

- 管理員可新增、編輯、解散、重組與例外建立組別。
- 任何重組都要先顯示對繳交、成績與簽核的影響，禁止無痕覆寫。
- 分組表可搜尋、排序、依屆別／類型／老師／狀態篩選。
- 可勾選部分或全選篩選結果，下載 CSV／Excel。

### 6.1 角色與用途

- 產學合作是登入後資訊與老師建立合作案的模組，不做投遞或審批平台。
- **可見性 `DECIDED`（2026-09-07 Roy，依 7/22 會議 §6.2 與需求表）**：產學合作列表與詳情為**登入後**內容，訪客看不到；取代本節「訪客可看公開列表」的舊條文。公司聯絡資料仍只有負責老師與管理員可見。
- 老師可建立、編輯、下架自己的合作案；管理員可管理全部。
- 申請／負責老師由登入帳號帶入，公開顯示老師姓名。
- 已登入且有權限的學生與老師可看已發布列表及詳情；訪客不可看。

### 6.2 欄位

| 欄位 | 輸入 | 預設可見性 |
|---|---|---|
| 公司名稱 | 必填文字 | 登入者可見 |
| 公司地址 | 文字 | 老師本人＋管理員 |
| 需求部門 | 必填文字 | 登入者可見 |
| 聯絡人 | 文字 | 老師本人＋管理員 |
| 聯絡電話 | 文字 | 老師本人＋管理員 |
| 聯絡 Email | Email | 老師本人＋管理員 |
| 專題／合作內容 | 可拉伸長文字 textarea | 登入者可見 |
| 對學生的條件／需求 | 可拉伸長文字 textarea | 登入者可見 |
| 備註 | 可拉伸長文字 textarea | 建立時選登入者可見或內部 |
| 負責老師 | 系統帶入 | 登入者可見 |
| 申請／發布日期 | 系統帶入 | 登入者可見 |
| 狀態 | 草稿／已發布／下架 | 依狀態 |

- 不再用短 input 限制長內容；後端用合理安全上限，UI 必須適合段落輸入。
- 列表只顯示摘要欄位；完整內容進詳情頁，避免把長文硬塞在 Data Table。
- 地址、電話、Email 不因合作案公開而自動公開。

### 6.3 與組別關係

- 一案多組／一組最多一案目前只是工程預設，尚待 Q-GRP03 封板；不可據此定案多對多操作。
- 產學組可選擇／連結合作案；公司與部門從合作案帶入，不要求重複輸入。
- 老師認領產學組不等於自動建立合作案；兩個動作各自留痕。

## 5. 狀態與權限
提案→逐人確認→成立；拒絕／到期後續待決；一般／產學分類獨立；合作案草稿→發布→下架。

## 6. 欄位與資料歸屬
提案成員、確認狀態、組別類型、主指導、例外原因；合作案公司部門內容條件與私有聯絡欄位。

## 7. 保存、版本與回執
保存每次確認、指派、重派、類型變更與管理影響；不無痕覆寫歷史 membership。

## 8. 其他角色所見
所有老師看一般與產學名單；只有案主與管理員看私有聯絡欄位；學生看自身關係。

## 9. 例外與未決事項
Q-GRP01、Q-GRP02、Q-GRP03、Q-GRP04。完整問題、建議與決策影響見 [待討論清單](<../💬 討論與決策/2026-09-11 產品待討論清單.md>)；不可將建議直接當成定案。

## 11. 驗收案例
各案使用年度資料集或明標獨立分支。待決案例須先補決定，延後案例不納本輪 Gate；兩者都不能記 PASS。未特別列出的他角色以第 8 節權限核對，拒絕案例也要證明資料未變。

### GRP-01｜找組員隱私

- 前置與操作：未組隊 S03 預設關閉，開啟再關閉；S06、訪客及停用帳號查看。
- 預期與跨角色核對：只有同屆已驗證學生、老師與管理員可看姓名學號聯絡 Email；不顯示手機；關閉或成組即隱藏。
- 證據：開关前後多角色頁與回應；按接受條件分別記 UI、操作邏輯、保存、權限。
- 案例狀態：可執行設計；執行結果：**NOT_RUN**。
