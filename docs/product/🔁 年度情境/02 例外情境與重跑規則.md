# 例外情境與重跑規則

> 2026-09-12 更新：七輪定案後，下表「期待／限制」改為現行規則與案例 ID；原「待決」措辭保存在各定案頁。

主線之外的分支保留同一版本與來源，但分支 run ID、資料集、起點及影響要獨立記錄。會占住主線組員、刪除帳號、改組員或解散組別的測試，使用明確分支資料，不能做完後偷偷重 seed 還原並把結果合稱主線。

## 失敗與恢復

失敗先記案例ID、版本、業務日期、最後成功步驟、實際結果與證據，再建缺陷。修好後可由最近安全狀態局部重跑；原失敗保留，局部通過不能自動回填整條主線通過。影響跨模組資料或權限的改動，重跑受影響路徑。

## 探索與規格更新

探索發現新行為時，分清「違反已決規則」與「原先沒決定」。前者缺陷，後者回產品待討論清單；不能為讓測試變綠改預期。外部Email／Google Calendar另列DEFERRED，不以人工操作頂替本輪站內通知證據。
