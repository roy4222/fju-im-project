## 0. 一句話

在同一台 VM 上多跑一組**獨立的** compose（`fju-status`），裡面是一個自己寫的 Next.js 小站（三頁：測試地圖、開發進度、能不能上線）加上現成的 Beszel（VM）、Dozzle（log）、PgHero（資料庫）、Gatus（健康檢查，只在內部）。外面只透過 **Cloudflare Tunnel** 進來，前面擋 **Cloudflare Access**（只放 Roy 的 Google 信箱）。資料由 VM 上一個「收集器」每 10 分鐘整理成 JSON；驗收結果由 Mac mini 在整夜驗收跑完後推上來。主網站 `web/`、主網站的 compose 與 Caddy **一個字都不動**。

### 3.2a 四個網址都要兩道鎖（Fable 定稿新增）

初稿只有 status-web 自己驗 JWT，Beszel、Dozzle、PgHero 三個網址只靠 Access 一道。定稿改成：

1. **隧道端驗 JWT（涵蓋四個網址）**：`ops/status/cloudflared.yml` 每條 ingress 加 `originRequest.access: { required: true, teamName: <team 名稱，不含 .cloudflareaccess.com>, audTag: [<AUD>] }`（Cloudflare 官方 origin-parameters 文件已確認），cloudflared 在轉給容器前就核 JWT；不合法回 403，流量不會進到任何容器。S-4 實作時以**固定版本**的 cloudflared 文件核對這個欄位；若該版本沒有，退而求其次把 cloudflared 換到有的版本，不是放棄這道鎖。
2. **status-web 自己再驗一次**（3.2），兩道獨立。
3. **Dozzle 用 Access 傳來的身分**（Docker API 另經 docker-proxy，3.13）：`DOZZLE_AUTH_PROVIDER=forward-proxy`、`DOZZLE_AUTH_HEADER_USER=Cf-Access-Authenticated-User-Email`（其餘 header 名照 Dozzle 固定版本文件）。容器不發布 port、唯一入口是隧道，所以這些 header 不可能被外人偽造。
4. Beszel 保留自己的登入（Roy 第一次開時建帳號）；PgHero 不另設 basic auth（已有兩道）。

安裝腳本第 10 步第一段與 Gatus 的「四個網址都被擋」檢查，驗的是第一道（Access 302）；第二段核對容器內實際掛載的設定；隧道端 403 的行為驗證是 AC-S-25 (b-2)（Access 暫時 Bypass 時八次請求全部 403、status-web 收不到請求）。

### 3.6 映像與部署

- `status/` 是獨立 Next.js 專案：**不加進 `pnpm-workspace.yaml`**，有自己的 `status/pnpm-lock.yaml`，安裝用 `pnpm install --ignore-workspace`。
- 版本與主網站相同：Next `16.3.8`、React `19.2.8`、Tailwind `4.3.3`、TypeScript `5.9.3`。**理由**：AGENTS.md 的「這不是你熟悉的 Next」與 `node_modules/next/dist/docs` 一套就好；主網站已審過的 override（`pnpm-workspace.yaml` 的資安版號）照抄到 `status/package.json` 的 `pnpm.overrides`。**獨立 lockfile 的理由**：主網站升版不會牽動後台、後台出事也不會讓主網站 CI 紅；另一位架構師的檔案（根目錄 lockfile、workspace）完全不碰。

### 3.13 compose 細節（`docker-compose.status.yml`，S-4）

- project 名固定 `fju-status`；只有一個自己的網路 `fju-status`；**任何服務都不發布 port**（`ports` 不寫）。
- pghero 額外接外部網路 `fju-test_default`（測試站 Postgres 所在），只監看測試站；正式站開站後另開小票加 `fju-prod_default`（現在加會讓 compose 在正式站沒起時起不來，也降低兩站網路隔離）。`pg_stat_statements` 沒開，PgHero 的「慢查詢」那頁會是空的——開它要改 `docker-compose.vm.yml` 並重啟資料庫，不在本次範圍。
- **docker-proxy**（新服務，受信任的權限邊界）：`tecnativa/docker-socket-proxy:<固定版本>`，唯一一個掛原始 `/var/run/docker.sock` 的容器；只放行讀取：`CONTAINERS=1 INFO=1 EVENTS=1 VERSION=1 PING=1`，其餘（含 `POST=0`、`EXEC=0`、`IMAGES=0`、`VOLUMES=0`、`NETWORKS=0`）全部 0；只接 `fju-status` 網路、不發布 port；`mem_limit: 32m`。**理由**：socket 掛 `:ro` 只擋不了什麼——容器仍能對 daemon 發 create／exec／stop，Dozzle 關按鈕也不會限制 API（Docker 官方：daemon attack surface）。
- dozzle：**不掛 socket**，`DOCKER_HOST=tcp://docker-proxy:2375`；`DOZZLE_ENABLE_ACTIONS=false`、`DOZZLE_ENABLE_SHELL=false`；forward-proxy 身分（3.2a）。
- beszel-agent：**不掛 socket**，`DOCKER_HOST=tcp://docker-proxy:2375`，所以**不用 `network_mode: host`**（host 模式解析不到 `docker-proxy`，而且 Beszel 預設 `LISTEN=45876` 會在主機開一個 TCP listener）；改成 `LISTEN=/beszel_socket/beszel.sock`，hub 與 agent 共用 volume `beszel_socket`，hub「新增系統」填這個 socket 路徑（Beszel 官方「connecting to a local agent」）。代價：Beszel 的主機網路流量圖不顯示（CPU、記憶體、磁碟不受影響；磁碟照官方說明掛 `/:/extra-filesystems/root:ro`）。
- gatus：設定檔 `ops/status/gatus.yml`；SQLite 存在 volume；**不建對外網址**；`client.ignore-redirect: true` 以檢查 Access 302。不設 email 警報（VM 外警報歸 health-cron）。
- cloudflared：`--config /etc/cloudflared/config.yml`（`ops/status/cloudflared.yml` 的產物）＋`secrets/tunnel.json`；每條 ingress 帶 `originRequest.access`（3.2a）。
- 所有映像固定版本號（不用 `latest`）；`restart: unless-stopped`；log 上限沿用每容器 10MB×5。
- 映像拉取：VM 的 deploy 帳號已登入 GHCR（`vm-setup.sh:276-280`，classic PAT 只勾 `read:packages`，涵蓋同帳號所有套件），`ghcr.io/roy4222/fju-status` 用同一組登入拉，不需新憑證。GitHub repo 是公開的（已查 `gh repo view`），collector 讀 API 與 raw 檔不用 token。
