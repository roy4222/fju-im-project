### 2.1 位置與版面

### 2.2 參數（React Bits PixelCard 改寫；Holo 不做）

| 參數 | 值 |
|---|---|
| 密度 | 「疏」：gap 10 px、speed 35、像素邊長 2–3 px |

| `pointerenter` | 從中心漣漪擴開（原型自加的 `enterPulse`，約 10 行：以中心為圓心、半徑隨時間擴到對角線長，掃過的像素點亮再回 idle） |
| `click`／`pointerdown` | 從點擊座標漣漪（原版 `clickPulse`） |
| 鍵盤 | `section.hero` **不加 `tabIndex`**（React Bits 原版 root `tabIndex=0` 不要）；內容層任一按鈕 `focusin` 觸發中心漣漪 |
| 手機（`pointer: coarse`） | 不掛 idle 閃動（省電）；點擊漣漪保留 |

### 2.3 取代 Pixel Trail

- 現在的 `HeroTrail`（`_ui/fx/hero-trail.tsx` → `pixel-trail.tsx` WebGL）**整個換成** `HeroPixel`（canvas 2D）。同一個掛載條件：`useTrailAllowed()`（`media-query.ts` 的 `TRAIL_QUERY`：hover＋fine pointer＋no-preference）改名 `useFxAllowed()`，另加一條 `PIXEL_TOUCH_QUERY`（coarse＋no-preference）給手機點擊漣漪版。
- 三個 `page.tsx`（admin／teacher／student）傳給 `HomeHero` 的 `trail` prop **名字與語意不變**，所以①②持有的頁檔一個都不碰；只改 `_stage.tsx` 的 import 與掛載那一行。
- `pixel-trail.tsx`、`trail-points.ts`＋test、`hero-trail.tsx`＋`.css` 刪除（`待問.md` Q3，建議刪）。
- `scripts/perf/trail.mjs` 改抓 `section.hero [data-testid=hero-pixel]`，預算不變（scriptPct ≤ 20、longTasks 0）；`README.md` 同步。**退路**：若 scriptPct > 20，先把 fps 上限 30 → 20；還超就把 idle 閃動關掉只留 hover／click（原型 hover-mode 表的「hover 版」）。

### 2.4 共用核心

- 新 `_ui/fx/pixel-canvas.ts`：純函式的像素格子引擎（建格、idle、enterPulse、clickPulse、fps 節流、IO／visibility 控制），**不碰 React**，單元測試可測（`pixel-canvas.test.ts`：格數、漣漪半徑隨時間、reduced／hidden 時 `tick` 不呼叫）。
- `hero-pixel.tsx`（後台橫幅）與 `home-hero-pixel.tsx`（前台首頁，§3）都用它，各自 `next/dynamic({ ssr: false })` 包一層 client 外殼。

### 2.5 CSP／測試鉤子

- React Bits 原版輸出 `style="--pixel-card-radius…"`，**不照抄**：圓角走 class，顏色走 `data-colors="…"`，gap／speed 走 `data-gap`、`data-speed`；canvas 用 `width`／`height` 屬性設尺寸（`ResizeObserver` 時改屬性）。
- `hero.spec.ts:107` 斷 `hero.locator('[style]')` 為 0：**`section.hero` 裡面任何元素都不准有 `style` 屬性**，含 CSSOM `setProperty` 產生的（它會長出屬性）。
- `data-testid="hero-pixel"`、`data-state="idle|pulse"`（給 `perf:trail` 與 e2e）。

## 7. 換頁載入提示：內容骨架（不用 `loading.tsx`）

### 7.1 為什麼不用 `loading.tsx`（`待問.md` Q1）

- 殼在頁裡：`SiteShell`／`DashboardShell` 是每個 `page.tsx` 自己 render 的，區段 `loading.tsx` 一出現，**頂列與側欄會整個被骨架蓋掉**，不是「內容骨架」。
- 串流改狀態碼：有 `loading.tsx` 的區段會先送 200，之後的 `redirect()`／`notFound()` 沒辦法改狀態碼；`pages.spec.ts:296-400` 的 PROTECTED 直接打 HTTP 要 3xx＋`location`、`public-pages.spec.ts:350` 要 404，**約 56 條斷言會紅**；`not-found.tsx` 的註解也寫明不能加。

### 7.2 做法

- 根 `layout.tsx` 掛一個 client 元件 `_ui/nav-pending.tsx`（+0.4 JS／+0.4 CSS，進 `$shared`）：
  - 在 `document` 捕獲階段監聽 `click`：同源 `a[href]`、沒有修飾鍵、左鍵、沒有 `target`／`download`、不是 `#` 錨、路徑跟目前不同 → 150 ms 後把 `document.documentElement.dataset.navPending = '1'`（150 ms 內完成的換頁不閃）。`popstate` 同樣。
  - `usePathname()`＋`useSearchParams()` 變了、或 8 秒安全上限 → 清掉。`useSearchParams` 在根 layout 的 client 元件要包 `<Suspense fallback={null}>`；這個邊界只包骨架元件本身，頁面在它外面，所以 3xx／404 狀態碼不受影響（`not-found.tsx` 的「不加 Suspense」註解指的是包住頁面；AC-46 當守門）。
  - 骨架本身是這個元件 render 的 `<div class="nav-skeleton" role="status" aria-live="polite" hidden>`：`html[data-nav-pending] .nav-skeleton { display:block }`，固定定位在頂列之下（前台 top 5 rem、後台 top 3.5 rem；後台 ≥ lg 時 left 16.5 rem 讓側欄露出來）、半透明底、三條灰色塊（深色模式用 `--card`）；sr-only 「載入中」。
  - CSP：全部 class＋data 屬性，沒有 `style=`。
- 表單送出（server action）不顯示骨架（按鈕自己有 pending 字樣，既有）。
- 減少動態：灰色塊不閃爍（`animation: none`）。
- `useLinkStatus` 不用：它要改每個 `<Link>` 的子元素（側欄、分頁列、頂列都是②持有），而且 prefetch 命中的連結不會進 pending。
