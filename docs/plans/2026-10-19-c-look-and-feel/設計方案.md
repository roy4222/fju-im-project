| 參數 | 值 |

### 2.3 取代 Pixel Trail

- 現在的 `HeroTrail`（`_ui/fx/hero-trail.tsx` → `pixel-trail.tsx` WebGL）**整個換成** `HeroPixel`（canvas 2D）。同一個掛載條件：`useTrailAllowed()`（`media-query.ts` 的 `TRAIL_QUERY`：hover＋fine pointer＋no-preference）改名 `useFxAllowed()`，另加一條 `PIXEL_TOUCH_QUERY`（coarse＋no-preference）給手機點擊漣漪版。
- 三個 `page.tsx`（admin／teacher／student）傳給 `HomeHero` 的 `trail` prop **名字與語意不變**，所以①②持有的頁檔一個都不碰；只改 `_stage.tsx` 的 import 與掛載那一行。
- `pixel-trail.tsx`、`trail-points.ts`＋test、`hero-trail.tsx`＋`.css` 刪除（`待問.md` Q3，建議刪）。
- `scripts/perf/trail.mjs` 改抓 `section.hero [data-testid=hero-pixel]`，預算不變（scriptPct ≤ 20、longTasks 0）；`README.md` 同步。量法照 `scripts/perf/README.md` §1 先起隔離量測庫與正式 build 的服務（port 3399），再 `pnpm -C web perf:trail --base http://localhost:3399 --as student` 與 `--as teacher` 各跑一次。
- **效能退路（主腦裁定）**：**桌機正常模式必須保留常駐閃**，不得改成只有 hover／click。若 scriptPct > 20，依序：(1) fps 上限 30 → 20；(2) 每幀只更新一部分格子（例如每幀輪流更新 1/2、1/3 的格，閃動節奏仍連續）；兩步都做了仍超標 → **回報未達驗收**，由主腦決定，不准關 idle 通過。手機（`pointer: coarse`）與減少動態的退路照 §2.2 既定（手機不掛 idle、減少動態不掛）。
- 常駐閃的驗收證據不能只看 `data-state="idle"`：無 hover、無 click 時，相隔 1 秒兩次取 canvas 像素（`getImageData` 或 `toDataURL`）必須不同（AC-70）。

### 2.4 共用核心

- 新 `_ui/fx/pixel-canvas.ts`：純函式的像素格子引擎（建格、idle、enterPulse、clickPulse、fps 節流、IO／visibility 控制），**不碰 React**，單元測試可測（`pixel-canvas.test.ts`：格數、漣漪半徑隨時間、reduced／hidden 時 `tick` 不呼叫）。
- `hero-pixel.tsx`（後台橫幅）與 `home-hero-pixel.tsx`（前台首頁，§3）都用它，各自 `next/dynamic({ ssr: false })` 包一層 client 外殼。

### 2.5 CSP／測試鉤子

- React Bits 原版輸出 `style="--pixel-card-radius…"`，**不照抄**：圓角走 class，顏色走 `data-colors="…"`，gap／speed 走 `data-gap`、`data-speed`；canvas 用 `width`／`height` 屬性設尺寸（`ResizeObserver` 時改屬性）。
- `hero.spec.ts:107` 斷 `hero.locator('[style]')` 為 0：**`section.hero` 裡面任何元素都不准有 `style` 屬性**，含 CSSOM `setProperty` 產生的（它會長出屬性）。
- `data-testid="hero-pixel"`、`data-state="idle|pulse"`（給 `perf:trail` 與 e2e）。

## 7. 換頁載入提示：內容骨架（不用 `loading.tsx`）

### 7.1 為什麼不用 `loading.tsx`（`待問.md` Q1）

- 殼在頁裡：`SiteShell`／`DashboardShell` 是每個 `page.tsx` 自己 render 的，區段 `loading.tsx` 一出現，**頂列與側欄會整個被骨架蓋掉**，不是「內容骨架」。
- 串流改狀態碼：區段 `loading.tsx` 會在它之下建立串流邊界；守衛（`requireRole`／`notFound()`）若在邊界**之後**才跑，回應已經先送 200，狀態碼改不了（Next.js `loading` 文件的 status codes 一節）。本專案的殼與守衛都在 `page.tsx` 裡、在邊界之後，所以會中：`pages.spec.ts:296-400` 的 PROTECTED 直接打 HTTP 要 3xx＋`location`、`public-pages.spec.ts:350` 要 404，約 56 條斷言會紅；`not-found.tsx` 的註解也寫明不能加。不是「所有 `loading.tsx` 都必然 200」，但要避開就得把守衛搬到 layout 層，那是②的殼，不在④範圍。

### 7.2 做法

- 根 `layout.tsx` 掛一個 client 元件 `_ui/nav-pending.tsx`（+0.4 JS／+0.4 CSS，進 `$shared`）：
  - 在 `document` 捕獲階段監聽 `click`：同源 `a[href]`、沒有修飾鍵、左鍵、沒有 `target`／`download`、**導覽鍵不同**才追蹤。導覽鍵＝`pathname + search`（`?page=2` 這種同頁分頁也算換頁，RSC 延遲時一樣要有骨架）；**只排除純 hash 變更**（`pathname + search` 相同、只有 `#` 不同）。命中 → 150 ms 後把 `document.documentElement.dataset.navPending = '1'`（150 ms 內完成的換頁不閃）。`popstate`（返回／前進）同樣追蹤：`popstate` 記錄目的導覽鍵；開始追蹤及 150 ms 計時器觸發時，都比較已提交鍵。已到達就清除全部計時器，不顯示骨架（返回／前進命中 client cache 時，導覽鍵提交可能早於 `popstate` 追蹤）。
  - 完成：`usePathname()`＋`useSearchParams()` 組成的導覽鍵變了 → 清掉 `data-nav-pending`、清掉兩個計時器（150 ms 顯示計時器、8 秒逾時計時器）。
  - 取消：還沒完成又點了另一個連結（快速連點）→ 先清掉舊的兩個計時器再重新計時；畫面上始終只有一個骨架，舊計時器不得在新導覽完成後才觸發。
  - 逾時：8 秒還沒完成 → **不視為完成**，骨架留著並改顯示「仍在載入……」＋「重新整理」連結（`<a href>` 指向目前網址）；導覽鍵變了才清掉。
  - 失敗：換頁失敗通常是整頁 hard navigation 或錯誤頁，元件會重新掛載，state 自然歸零；元件 unmount 時清掉所有計時器。
  - `useSearchParams` 在根 layout 的 client 元件要包 `<Suspense fallback={null}>`；這個邊界只包骨架元件本身，頁面在它外面，所以 3xx／404 狀態碼不受影響（`not-found.tsx` 的「不加 Suspense」註解指的是包住頁面；AC-46 當守門）。
  - 骨架本身是這個元件 render 的 `<div class="nav-skeleton" role="status" aria-live="polite" hidden>`：`html[data-nav-pending] .nav-skeleton { display:block }`，固定定位在頂列之下（前台 top 5 rem、後台 top 3.5 rem；後台 ≥ lg 時 left 16.5 rem 讓側欄露出來）、半透明底、三條灰色塊（深色模式用 `--card`）；sr-only 「載入中」。
  - CSP：全部 class＋data 屬性，沒有 `style=`。
- 表單送出（server action）不顯示骨架（按鈕自己有 pending 字樣，既有）。
- 減少動態：灰色塊不閃爍（`animation: none`）。
- `useLinkStatus` 不用：它要改每個 `<Link>` 的子元素（側欄、分頁列、頂列都是②持有），而且 prefetch 命中的連結不會進 pending。
