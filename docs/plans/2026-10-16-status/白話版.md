# 開發者後台改版：給 Roy 的白話版

日期：2026-10-16（第 2 輪，照 Review 修過）。這一頁講我們要做什麼、你要決定什麼、你要做什麼。細節在同一個資料夾的另外四份文件。

## 一句話

把開發者後台從「三張入口卡」改成一個監控儀表板。你打開第一頁，就看到網站現在健不健康、備份有沒有做、磁碟還剩多少、能不能上線。

## 改前、改後

| 地方 | 改前 | 改後 |
|---|---|---|
| 第一頁 | 版本卡＋三張入口卡＋三張工具卡 | 狀態列（全部正常・3 分鐘前更新）→ 五張小卡（版本一致、24h 錯誤、備份、主機儲存、CI）→ 一張回應時間圖 → 能不能上線五條 → 最近事件 |
| 左側欄 | 四項＋三個工具 | 八項：總覽、服務健康、部署與 CI、錯誤紀錄、備份與儲存、使用報表、開發進度、驗收地圖。下面是三個外部工具：Dozzle、PgHero、Beszel |
| 顏色 | 只有淺色 | 跟你電腦的系統設定走。系統是深色，它就是深色。沒有切換鈕 |
| 主機儲存 | 在系辦首頁 | 搬到這裡。系辦首頁那塊我們建議拿掉（你決定） |

| 重複的東西 | 版本卡出現兩次、CI 出現三次、工具連結兩份 | 每件事只放一個正本。其他地方只放連結 |
| 錯誤紀錄 | 沒有 | 簡單版：哪個資料來源失敗、什麼時候。一鍵跳到 Dozzle 看 log |
| 使用報表 | 沒有 | 程式先寫好。正式站上線前這頁不會出現。上線後你在 VM 做幾個步驟，它就會出現 |

## 要你動手的事

- **A 階段：不用。** 合併後十分鐘內測試站會自己更新。你用 Google 帳號登入看就好。
- **B 階段：**
  1. Beszel 第一次進去建帳號（2 分鐘）。
  2. 使用報表：照 README 的步驟表在 VM 貼幾行指令（約 15 分鐘）。這些指令只會建一個「只能數數、不能讀資料」的角色。
  3. PgHero 慢查詢：主腦改主站設定，要重啟一次資料庫。排在備份之後。

## 我們這次不做

- 不加容器、不改伺服器設定（10/18 前來不及，也沒記憶體）。
- 不做容器錯誤數、不做 log 搜尋（Dozzle 已經有）。
- 不做請求數的圖。先用 Gatus 的回應時間和可用率。

## 來不及怎麼辦

先做：新側欄、部署與 CI 頁、第一頁、G5 自動檢查、測試地圖修正。
再做：其他三個子頁。
來不及時先延後使用報表，再延後開發進度的小修。部署與 CI 頁不延後。
版本卡和 CI 會先在「部署與 CI」頁出現，舊位置才拿掉。所以任何時候都看得到它們。
任何時候停下來，測試站都是完整的一套，不會半套。
