# 系辦後台（AD）拆票

> 每張票：可改檔案（**硬邊界**，含測試檔）、會受影響的既有測試（e2e 斷言與驗收劇本的檔＋行，對照盤點）、跟測試衝突時怎麼辦、對應 AC、階段、相依、大小（S／M／L，L 一律再拆）。同一波的票**檔案不重疊**，可平行。程式基準 `origin/main` @ `5b68058`。

## 0. 共通規則

1. **只准改自己票列出的檔**。要動別的檔＝回報主腦改票，不是直接改。
2. **既有測試**：行為沒變的斷言不改；本份規格明說改掉的字（標題、按鈕名、提示句）才改對應那一行，而且只改字串。新增行為一律加新案例。
3. **`web/e2e/pages.spec.ts` 系辦區（`:60-110` 三個 test、`:311-352` FINGERPRINTS 的 `/dashboard/admin*` 列）**：各頁票只改自己那一頁的行；合併前 rebase 到最新 main；衝突只會在這個檔，解法是雙方都留。`PROTECTED` 區（`:354-394`）不動（`_nav.ts` 歸共用）。
4. **指紋句**（FINGERPRINTS）：若票把那句說明砍掉，必須在同一票換成該頁仍存在、且只有系辦看得到的一句（例如區塊標題），並在 PR 說明寫明新舊句。
5. **跨角色檔**（`e2e/acceptance/**`、`tools/tutorial/storyboard.md`、`docs/**`）集中在 AD-18 一張票最後做；頁面票不碰。
6. **D-1（h1 用側欄名）定案前照建議做**；若 Roy 改決定，只需回改各票的 `h1` 字串與對應斷言。
7. 第 1 批（V1～V8）擁有的檔不碰：`dashboard/admin/affairs/*`（V1）、`dashboard/admin/showcase/actions.ts`、`showcase-forms.tsx`（V3）。
8. 每票 PR：Review 程式模式 PASS、CI 全綠、只限 A、10/18 18:00 前，主腦可直接合併（Q102）。
