# C 階段規格③：驗收案例

- 對應《設計方案》章節寫在編號後括號；定案表編號在「前置狀態」欄首。
- 四欄：前置狀態／操作／預期可觀察結果／目前版本（`origin/main` = `69116fc`）怎麼失敗。標 **既有保證** 的是目前版本就成立、本份只確認不退步的。
- 驗收環境：`stage-c` 建置後用 `pnpm -C web verify --e2e …` 的 app（自己的資料庫、seed-demo 或各 spec 的 fixture）；打包用 `pnpm -C web perf:bundle`；SQL 數用 `scripts/perf/sql.mjs`。
- 證據一律寫「檔名／PR 說明／CI 附件」，不寫本機路徑。
