## 2. 全站頭像（S2、C2、X10）

### 2.1 一句話

後台每個顯示人名的地方都用既有 `UserAvatar`（`web/src/app/_ui/avatar/user-avatar.tsx`），資料從**同一句列表查詢**帶兩個欄位出來，不另外查。

### 2.2 元件與資料契約（凍結；①②也照這個用）

- 元件：`UserAvatar`，props 不改（`user: AvatarUser`、`size`、`decorative?`）。`AvatarUser = { id, name, avatarPreset: number | null, avatarFileId: string | null }`（`application/accounts`，既有）。
- **規則：任何回傳「人」的查詢列型別都要帶 `avatarPreset`、`avatarFileId`**（型別層面：讓列型別 `extends AvatarUser` 或含 `avatar: AvatarUser`）。來源一律是列表查詢本來就 join 的 `user_profiles`（姓名就是從那裡來的），多選兩欄，**查詢數不變**。這是 N+1 的防線，驗證 seam 在 §12（`scripts/perf/sql-expect*.json` 的查詢數上限不得上調）。
- 圖片請求走既有 `/avatars/*`（`next.config.ts` `Cache-Control: public, max-age=86400`）與上傳檔的既有路徑；一頁 60 張頭像是 60 個可快取的圖片請求，不是 60 句 SQL。
- **照片的讀取權限沿用既有伺服器授權，不另做**：`GET /api/files/<id>` 每次下載都重新授權（`api/files/[id]/route.ts`）——啟用中的登入帳號（學生、老師、系辦）200、訪客 401、換掉的舊頭像 404；`e2e/avatar-download.spec.ts:104` 已斷這三種結果（既有保證，AC-C3-46 只確認卡片上的照片網址走同一條）。本份不放寬、不改成公開。
- 預設頭像規則不變（`avatar_preset` 1～100；兩欄都 NULL 依帳號 hash 固定一張，Q105）。**「只顯示姓氏字」的占位全部換掉**：有上傳就是照片、沒上傳就是預設圖，不再有首字圓圈。
- **現況（探索結果）**：目前沒有共用的 `avatarsFor(userIds)`；四處讀頭像的查詢各自 join `user_profiles`（身分解析、`pg-groups.ts` 組員子查詢、簽核 `profilesForSnapshots`、帳號目錄 `DIRECTORY_BASE`）。本份新增 `infrastructure/db/person-avatar.ts`：一個跟 `person-name.ts` 同款的 SQL 欄位片段 `personAvatar('p')`（展開成 `p.avatar_preset, p.avatar_file_id`），讓每句列表查詢用同一寫法多選兩欄；不做「依 userId 再查一次」的 helper，避免有人拿它寫出 N+1。
- **client 元件的限制**：`UserAvatar` 是 Server Component（刻意不用 `next/image`，因為它會輸出 `style=`）。client 元件（對話框、表格、甘特）不能直接 render 它。兩條路，實作擇一、全站一致：(a) 伺服器先畫好 `ReactNode` 以 `Record<userId, ReactNode>` 傳進去（`admin/accounts/page.tsx` 重設頭像對話框的做法）；(b) 新增 client 可用的 `_ui/avatar/avatar-img.tsx`（`'use client'`，用 `application/accounts/avatar.ts` 的純函式 `avatarUrl` 算網址，輸出一樣的原生 `<img>`）。**本份選 (b)**：卡片與對話框都是 client，(a) 會讓每個對話框多一個 Record prop。`avatarUrl` 在 application 層是純函式，前後端都能 import；`composition/avatar-url.ts` 的 `server-only` 版不動。

## 3. 頭像圓形裁切（S13）

### 3.1 行為

- 入口不變：「我的帳號」頭像卡的「上傳照片」（`_ui/avatar/avatar-picker.tsx`）。選檔後**不直接上傳**，先開裁切視窗：圓形取景框（直徑 256px CSS，手機 220px）、底下照片可**拖動**（pointer 事件）、**縮放**（滑桿＋滾輪＋雙指捏合）、「重選」「取消」「儲存」。
- 「儲存」：用 `<canvas>` 把圓框內的區域畫成 **512×512 的正方形 JPEG（品質 0.9）**，以 `canvas.toBlob` 產生檔案，交給**既有**流程（`AvatarPicker` 的 `uploadTicketAction` → `POST /api/files/upload?ticket=` → `submitAction({ fileId })`；檔名 `avatar.jpg`、宣告 MIME `image/jpeg`，2 MiB 上限沿用）。伺服器端既有的檢查與縮圖（`infrastructure/ops/avatar-image.ts`：EXIF 轉正、`fit: cover`、輸出 256×256 WebP）**不改**——它收到的只是「已經裁好的正方形」，`cover` 不會再裁掉東西。所以 `account-avatar.spec.ts:49` 斷的「256×256 WebP」照舊成立。
- 圓形是**顯示**時裁（`UserAvatar` 本來就 `rounded-full`），存檔是正方形：所以舊照片、預設頭像、系辦重設頭像（②的 `AvatarResetDialog`，export 名保留）都不受影響。
- 太小的圖（短邊 < 256px）：仍可裁，但視窗提示「照片較小，會模糊」。HEIC 等瀏覽器畫不出來的格式：`createImageBitmap` 失敗就顯示「這個格式不能裁切，請換 JPG 或 PNG」，不送出。EXIF 方向：用 `createImageBitmap(file, { imageOrientation: 'from-image' })`，不自己讀 EXIF。
- 鍵盤：方向鍵移動照片 4px、`+`／`-` 縮放；視窗 `role="dialog"`、焦點鎖在視窗內。

### 3.2 打包與 CSP

- **不加套件**（0.3 第 2 條）。裁切視窗是一支獨立 client chunk，`next/dynamic` 在按「上傳照片」選到檔案那一刻才載入；`/account` 首載不變。估 **≤ 4 KB gzip**（pointer 事件＋canvas 繪圖＋一個 `<input type="range">`）；AC-C3-04 用 `perf:bundle` 證明 `/account` 不超過既有 limit 249。
- 照片位置用 `canvas` 畫，不用 `transform` style；圓框用 CSS class。整個視窗沒有 `style=` 屬性（AC-C3-04 驗 CSP 違規 0）。

### 9.1 資料模型：活動可以跨好幾天（migration ③-2）

`project_events` 不加欄，**把既有 `ends_at` 的語意定清楚**並補 CHECK（目前只有 `ends_at >= starts_at`，「只有一天」是用例與表單的規則）：

| `all_day` | `starts_at` | `ends_at` | 意思 |
|---|---|---|---|
| true | 開始日 00:00（臺灣） | **結束日的次日 00:00**（exclusive，iCal `DTEND` 慣例；單日活動＝`starts_at + 1 天`） | 整天活動，可跨日 |
| false | 開始時刻 | 結束時刻（可以是另一天）或 NULL（沒寫結束時間，當天） | 有時間的活動 |

- 新 CHECK `project_events_all_day_end_check`：`all_day = false OR ends_at IS NOT NULL`；既有 `ends_after_starts` 改成 `ends_at > starts_at`（全天）／`>=`（有時間）合併寫成 `(ends_at is null) or (not all_day and ends_at >= starts_at) or (all_day and ends_at > starts_at)`。
- 資料搬移：`UPDATE project_events SET ends_at = starts_at + interval '1 day' WHERE all_day AND ends_at IS NULL`（示範資料與測試站資料都適用；seed-demo 的活動定義改寫成帶 `endsAt`）。
- 用例輸入 `ActivityInput`（`application/cohorts/activities.ts`，現在是 `{ title, description, date, allDay, startTime, endTime, audience }`）改成 `{ title, description, startDate, endDate, allDay, startTime, endTime, audience }`：`endDate` 空＝同 `startDate`；驗證 `endDate >= startDate`；有時間且同一天時 `endTime > startTime`；**非全天活動跨日時（`endDate ≠ startDate`）結束時間必填**（錯誤句「跨日的活動要填結束時間」）；只有單日（`endDate = startDate`）才可不填，存 `ends_at = NULL`。不自動補 23:59、不捏造結束日。`moveActivity` 在伺服器端用同一條規則：非全天、`ends_at` 為 NULL 的活動若 `endDate ≠ startDate` 就回 `VALIDATION_FAILED`（同一句），不只靠 client 擋。**查詢回傳的 `Activity` 型別形狀不變**（`startsAt`、`endsAt`、`allDay`…），只是全天活動的 `endsAt` 一定有值；這樣 `app/page.tsx`（②的檔）與老師首頁 `_home/load.ts` 不用改。`updateActivity` 另外要收「只改日期」的小輸入（拖拉用）：新增 `moveActivity(actor, activityId, { startDate, endDate }, expectedRevision, requestId)`，其餘欄位沿用，避免拖拉要回傳整份表單。
- **所有讀活動的地方一起對**（同一票 C3-06）：`formatActivityWhen`（`composition/cohorts.ts`）顯示「3/5–3/7」或「3/5（四）09:00–3/7（六）17:00」；`publicActivities` 的 SQL 已用 `coalesce(ends_at, …) >= now()`，跨日活動在整個期間都算「近期」，不改；老師首頁 `upcomingActivities` 用 `startsAt > 今天` 篩，改成「`endsAt`（或 `startsAt`）在今天之後」——這是 `teacher/_home/load.ts`（①②可能也碰，本份只改那一個比較式，後合者 rebase）；前台 `/timeline` 在 §9.5 整個重做；`calendar-model.ts` 隨 `full-calendar` 一起刪。
- 刪除：每列直接「刪除」（確認框「確定刪除『說明會』？學生的時程上會直接消失。」），**不必先取消**：CHECK `project_events_deleted_check` 拿掉 `status='cancelled'` 那半句；`deleteActivity` 前置改成「未刪除」。「取消」按鈕從畫面拿掉；`cancelActivity` 用例與 `status` 欄保留（舊資料與前台「已取消」顯示不變，Q-C3-6）。

### 9.2 階段日期：拖拉改 `cohort_stages.start_date`／年度結束日

### 9.3 甘特元件（自己做；共用）

檔案：`web/src/app/dashboard/_timeline/gantt/`（新）——`gantt-model.ts`（純函式：日期↔像素、階段最後一天、夾限、車道配置、縮放刻度；從 `proto-timeline` 的 `proto-model.ts` 重寫，**附單元測試**）、`gantt.tsx`（client 元件）、`gantt.css`（一般 stylesheet，Next 掛 nonce）、`gantt-dialogs.tsx`（新增／編輯活動視窗、刪除確認、階段確認；只系辦載）。

**介面（凍結；系辦頁與前台共用同一個元件）**：

```ts
export type GanttStage = { seq: number; name: string; startDate: string; lastDate: string; deadlineVersion: number }
export type GanttActivity = { id: string; title: string; startDate: string; endDate: string; allDay: boolean; startTime: string | null; endTime: string | null; timeText: string | null; audienceKind: ActivityAudience; status: 'scheduled' | 'cancelled'; revision: number }
// startTime／endTime：'HH:mm'；全天都是 null。非全天且 endTime 為 null ＝「單日、沒寫結束時間」，拖拉把手跨日時 gantt 要改開編輯視窗（§9.3 互動）。
export type GanttDeadline = { id: string; title: string; date: string; href: string | null }   // 作業截止，鎖住
export type GanttProps = {
  cohortId: string
  stages: GanttStage[]; yearEndDate: string | null; activities: GanttActivity[]; deadlines: GanttDeadline[]
  today: string
  mode: 'edit' | 'view'           // 前台一律 view
  editor?: {                      // mode='edit' 才有；全部是 server action 的包裝（C3-03 凍結，C3-08、C3-13 共用這版，不另加方法）
    // 階段分界／年度結束日放開（或把手上按 Enter）時呼叫。gantt 不管「要不要確認」：由 `gantt-mount` adapter 完成
    // preview → 確認框 → 真正儲存；resolve `{ ok:true }` 停在新位置、`{ ok:false, cancelled:true }` 只回彈不顯示 alert、
    // 其他 `{ ok:false, message }` 回彈＋ `role="alert"`。
    saveSchedule(input: { stages: { seq: number; startDate: string }[]; yearEndDate: string; revision: number }): Promise<ActionResult | { ok: false; cancelled: true }>
    openStage(seq: number): void   // 點階段色塊、或色塊聚焦時按 Enter：開「編輯第 n 階段」視窗（名稱、說明、開始日、第 4 段年度結束日）
    moveActivity(id: string, revision: number, startDate: string, endDate: string): Promise<ActionResult>
    openCreate(prefill: { startDate: string; endDate: string }): void
    openEdit(id: string, prefill?: { startDate: string; endDate: string }): void   // 一般點擊不傳；無結束時間的活動拉把手跨日時傳拖後起訖（AC-C3-48）
    remove(id: string, revision: number): Promise<ActionResult>
    cohortRevision: number
  }
}
```

- 載入方式：`next/dynamic(() => import('./gantt'), { ssr: false })`。**理由**：橫條位置、寬度、今天線、右鍵選單位置都要寫 `style`，SSR 會輸出 `style=` 屬性被 CSP 擋；只在瀏覽器渲染時 React 走 CSSOM 設樣式（原型已實測 CSP 違規 0）。載入前的占位是同高度的灰色骨架（④的骨架規格之前先用一個 `dash-card` 空框）。
- 版面（原型 C）：左欄固定（月份／階段／每段一列／學生截止），右邊橫向捲動；最上面「階段」列是四條色塊（可拉分界、拉最右端＝年度結束日）；每段一列放落在該段的活動橫條（開始日落在哪段就在哪列；跨段的橫條照實畫長）；重疊的活動自動往下排車道；作業截止是鎖住的菱形（滑過看名稱，點了連到①的作業頁）；今天是橘色直線；第一次畫捲到今天前兩週。
- **互動（Google 日曆）**，`mode='edit'`：
  - 點橫條 → 開編輯視窗；拖橫條整段平移（保留天數）；拉橫條左右端改起訖；拖拉中橫條旁即時顯示新日期；放開才送 action，失敗回彈＋錯誤句（`role="alert"`）。**例外**：非全天且 `endTime` 為 null 的活動（單日、沒寫結束時間），拉把手讓 `endDate ≠ startDate` 時放開**不送 `moveActivity`**，橫條回彈並呼叫 `openEdit(id, { startDate, endDate })` 開編輯視窗（起訖日已預填成拖到的日期、結束時間欄標必填）；填了結束時間按「儲存」才寫入，「取消」就什麼都不變（§9.1；AC-C3-48）。整段平移不受影響（起訖同天，仍是單日）。
  - 點階段色塊（或色塊聚焦按 Enter）→ `editor.openStage(seq)`；階段分界與最右端把手放開 → `editor.saveSchedule(...)`（確認框在 adapter，§9.2）。
  - 點某一列的空白處 → 開新增視窗，日期預填點到的那天（起迄同一天、全天）。
  - 右鍵橫條（或長按 600ms、或鍵盤 `Shift+F10`／`ContextMenu`）→ 自製選單「編輯」「刪除」（`role="menu"`，Esc 關）。
  - 鍵盤：橫條是 `button`，`←→` 平移一天、`Shift+←→` 一週、`Alt+←→` 改結束日、`Alt+Shift+←→` 改開始日、`Enter` 編輯、`Delete` 刪除（跳確認）；階段分界與年度結束日把手也是 `button`，`←→`／`Shift+←→`，`Enter` 開確認。每個把手 `aria-label` 寫清楚現值（原型的句子）。
  - 縮放：「週／月」兩段切換（週＝每天 26px、月＝每天 8px；原型的四級收成兩級＋`Ctrl+滾輪`微調），狀態存 `localStorage`。
  - 拖拉階段分界放開 → §9.2 的確認框（由 `gantt-mount` adapter 在 `saveSchedule` 裡完成，gantt 元件本身不知道有確認框）。
- `mode='view'`：沒有把手、沒有右鍵選單、橫條是 `<a>`（連到活動的 `#` 錨點，下方清單展開說明）；仍可縮放與鍵盤捲動。

### 14.3 本份與①的

- ①消費：`UserAvatar`（server）、`AvatarImg`（client，第 0 波）、`infrastructure/db/person-avatar.ts` 的 `personAvatar(alias)` SQL 片段；列型別請 `extends AvatarUser`。
