# C 階段規格③：拆票

- 17 張票 C3-01～C3-17，第 0～5 波。基準 `origin/main` = `69116fc`，實作開在 `stage-c`；每票一個 PR 進 `stage-c`。
- 路徑都相對於 `web/`。「可改檔案」逐檔 `git ls-files` 確認過存在；**新**＝新檔。沒列的檔案不可改（跨規格例外行在《設計方案》§14.2 列明）。
- **同一波內各票檔案不重疊**（例外檔 `e2e/fingerprints.ts`、`scripts/perf/budget.json`、`scripts/perf/sql-expect.json` 每票只動自己那一列、同一波可並存）。
- 每票獨立通過 verify：改介面就同票改完所有呼叫端或保留舊介面；後端先放寬、畫面後改的票，e2e 若因此變紅在「受影響既有測試」欄寫清楚處置。
- verify 指令照 `web/AGENTS.md`：`pnpm -C web verify [單元檔…]`、`pnpm -C web verify --integration <檔…>`、`IDENTITY_CACHE_TTL_SECONDS=0 pnpm -C web verify --e2e e2e/<spec>`；打包 `pnpm -C web perf:bundle`。證據只寫檔名與「PR 說明／CI 附件」。
- 公開 repo：PR 說明與 `docs/plans/` 不寫本機路徑與 agent id；原型只寫分支名 `proto-timeline`。
- 所有理由欄選填；權限一律伺服器端；頁面 `redirect()` 是 307；CSP 無 `unsafe-inline`；每頁首載 gzip ≤ 250 KB。
