## 1. 現況（748090a）

- 外框 `web/src/app/_ui/dashboard-frame.tsx`（client）：側欄分 5 個群組（總覽、專題事務、分組與產學、評分與同意書、系統管理），`SEGMENTS` 以網址段決定群組與圖示；項目啟用狀態是 `item.href === current` 精確比對；頁首 `h-14`：收合鈕、目前頁名、深淺色切換、鈴鐺、帳號選單。
- 側欄清單 `web/src/app/dashboard/_nav.ts`：系辦 14 項、老師 7 項、學生 7 項，三份都有「通知」；`PROTECTED_ROUTES` 給 e2e 驗守衛。
- 徽章：`_ui/nav-badges.ts`（server、React `cache`）算 `BadgeCounts`；`_ui/nav-badge-rules.ts` 的 `badgeFor(role, href, counts)` 依網址段配數字：學生 `/affairs`、`/signoff`、`/inbox`，老師 `/grading`、`/signoff`，系辦 `/accounts`、`/inbox`。
- 「現在」橫幅 `web/src/app/dashboard/_stage.tsx`：`HomeHero` 有歡迎句、階段句（`data-testid="stage-text"`，外層 `section[aria-label="現在階段"]`）、進度 SVG、階段四格、小卡 chips、`hero-next`。三個角色首頁都用。
- 色票 `web/src/app/globals.css`：淺色＝淡藍外框、白側欄、深藍橫幅＋藍圓花紋、品牌橘；`.dark` 是**中性炭灰**（`--background oklch(0.19 0.012 253.89)`），沒有個性，和淺色的深藍沒有關係。
- 共用零件分散在四個檔：`_ui/primitives.tsx`、`_ui/dashboard-primitives.tsx`（票 38）、`_ui/dashboard-kit.tsx`（票 35）、`_ui/dashboard/primitives.tsx`（`PageTitle`、`Panel`、`Pill`…）。沒有「彩色邊框待辦卡」「狀態膠囊」「區塊標題＋細線」。
- CSP：正式站 `style-src` 只有 nonce，**不允許 `style` 屬性**（`web/src/proxy.ts`）。原型 v4 的待辦卡用 inline `style` 配色，搬過來一定要改成 class／data 屬性。
- 效能：`/tmp/eng-lead/perf-audit.out` 是空的（量測還沒回來），沒有現值基線。
- 頭像：`users.image`（Better Auth 建的欄）沒人用；`user_profiles` 沒有頭像欄；`stored_files.purpose` 的 check 沒有 `avatar`；`FILE_TYPES` 只認 PNG／JPG，沒有 WebP。`sharp@0.35.5` 已在 `pnpm-lock.yaml`（根 `overrides`，由 `next` 的 optional 與 `miniflare` 帶進來），但 `web/package.json` 沒有直接依賴。
- Cloudflare：只當 DNS，沒開代理。Caddy `ops/Caddyfile.vm` 用 Let's Encrypt HTTP-01，`header_up X-Real-IP {remote_host}`；app 的 `clientIpFrom`（`web/src/infrastructure/auth/sign-in-rate-limit.ts:60`）先讀 `x-real-ip` 再讀 `x-forwarded-for` 第一段。開了代理之後 `remote_host` 會變成 Cloudflare 的 IP，登入限速會把全校鎖在一起。

- 學生 `/dashboard/student/grading`（成績說明頁，F-102）與 `/dashboard/student/industry`（Q73 學生不碰產學）不在側欄也不在 `activeFor`；學生規格決定 `industry` 要轉址還是保留說明頁。老師 `/signoff`、`/industry` 的轉址（Q77「舊網址轉到新分頁」）由老師規格做，側欄只負責亮對的項目。

- 側欄**不再分群組**（原型 v4 沒有群組標題；學生 3 項、老師 4 項不需要）。`DashboardFrame` 的 `GROUPS`、`SEGMENTS` 刪掉，改成一個 `SidebarGroup` 直接列 items；圖示改放在 `NavItem.icon`（`_nav.ts` 列）。
- 權限原則（Q47）：側欄只列該角色能用的入口，這在現況已成立（每個角色一份清單）。待審者、訪客沒有側欄（既有）。
- 其他不動：logo＋「專題管理平台」、`aria-label="後台導覽"`、`SidebarMenuBadge data-testid="nav-badge-<href>"`、頁尾「回到前台」、`sidebar_state` cookie、手機版 Sheet 與「側欄選單」鈕、頁首的 `DashThemeToggle`、`InboxBell`、`AccountMenu`。
- 頁首標題＝亮著那一項的 `label`（含 `activeFor` 命中的），都沒命中時＝`roleLabel`（既有行為）。

### 3.3 老師兼系辦的身分標示（Q92）

- `DashboardFrame` 在側欄 logo 區下方加一行 `<p data-testid="workbench-indicator">目前：{roleLabel}</p>`（`roleLabel` 來自 `WORKBENCH`：「系辦後台」「老師後台」「學生後台」）。只在 `switchLinks.length > 0`（有別的後台可切）時顯示。收合側欄時只顯示首字圖示（tooltip 全文）。
- 不是 `<nav>`、不是 landmark（很多 e2e 用裸的 `getByRole('navigation')`，多一個會爆 strict mode）。
- 切換入口仍在帳號選單（「切換到系辦後台」等，`role-switch.ts` 不動）。

### 3.4 「現在」橫幅（Q71、Q77、10/15 晚）

`HomeHero` 依原型 v4 `home-student.tsx`／`home-teacher-v2.tsx` 重寫，介面見 §2.2。版面（桌機兩欄、手機一欄）：

- 左欄：小字「現在」＋ `line`（角色自己的一句）；大字階段句（`stage-text`，字級 32／40、品牌橘的階段名）；「還有 N 天」（`stage.daysLeft` 為 null 時不顯示這行）；白色膠囊「看完整時程」→ `timelineHref`；`cta` 若有，橘色主按鈕放在膠囊旁。
- 右欄：`next` 卡（白底、「下一件要交的」或角色自己的標題、標題、到期、按鈕）＝ `hero-next`。沒有 `next` 時右欄不渲染，左欄滿版。
- `<h1>歡迎回來，{name}</h1>` 保留為小字第一行（e2e 與 a11y 的 h1）。
- 深藍底＋兩個藍圓（`::before`／`::after`，既有），深色模式改漸層＋內圈光（§3.6）。
- 刪掉：進度 SVG、`cohortProgress` 的呼叫（函式留著給時間軸頁）、階段四格、chips。
- CSS 搬到 `web/src/app/dashboard/_stage.css`（由 `_stage.tsx` import；App Router 允許任何元件 import 全域 CSS），`globals.css` 的 `.hero` 區塊在 SH-4 刪掉（SH-4 在 SH-2 之後，不會撞檔）。
- 系辦首頁：照舊可用 `HomeHero`（`trail` 不傳）；系辦規格若改成純待辦卡，`stage-text` 要留著（`timeline.spec.ts:240-244` 讀 `/dashboard/admin` 的階段句）。

### 4.2 Cloudflare 代理（Q59、Q50）

目標：公開圖片由 Cloudflare 邊緣快取；登入限速仍讀到真實 IP；憑證不中斷；CSP 不被 Cloudflare 的自動改寫弄壞。

**程式與設定（SH-10）**

- `ops/Caddyfile.vm`：全域 `servers { trusted_proxies static <Cloudflare IPv4/IPv6 清單> ; client_ip_headers CF-Connecting-IP }`，`header_up X-Real-IP {client_ip}`（Caddy 2.7+ 的 `{client_ip}` 已經是穿過 trusted proxy 後的真實 IP）。清單用 `ops/cloudflare-ips.txt`（從 `https://www.cloudflare.com/ips-v4` 與 `ips-v6` 抓，附更新日期；每季手動更新）。
- app 的 `clientIpFrom` **不改**（仍讀 `x-real-ip`）；只加一條防呆：若 `x-real-ip` 落在 Cloudflare 網段，記 warn 一次（代表 Caddy 的 trusted_proxies 沒生效）。
- 憑證：**維持 Caddy 的 Let's Encrypt HTTP-01**。Cloudflare 代理會放行 `/.well-known/acme-challenge/*`（不受 Always Use HTTPS 影響），所以不用換 Origin CA。SSL/TLS 模式設 **Full (strict)**。
- 快取：Cloudflare 預設只快取副檔名類靜態資源（`/_next/static/*`、`/avatars/*.webp`、`/brand/*.png` 會自動快取）。`/api/files/<id>` 沒副檔名，要加一條 Cache Rule（步驟表第 6 步）：路徑 `starts_with "/api/files/"` → Eligible for cache、**Respect origin TTL**。來源回 `public, max-age=300`（第 1 批 V4，只有訪客可看的 PNG／JPEG）才會被存；私有檔回 `private`／`no-store`，Cloudflare 不存。頭像回 `private`，也不存（頭像只給登入者）。
- 必須關掉的 Cloudflare 功能（都會改寫 HTML／注入 script，撞 nonce CSP）：Rocket Loader、Auto Minify（HTML／JS）、Email Address Obfuscation、Mirage、Polish 可開（只改圖片）。
- Turnstile（訪客規格）本來就走 Cloudflare，不受影響；驗證仍在伺服器端。
- `clientIpFrom` 與 `ops/Caddyfile.vm` 不在任何人的擁有表，本票認領（`拆票.md` 註明）。

### 7.2 做法

- **一頁一次聚合讀取**：頁面用 `Promise.all` 一次發所有查詢（學生首頁已是 6 條、老師 7 條）；徽章的 `navBadgeCounts` 與頁面共用 `loadStudentWorkload`／`loadTeacherWorkload`（React `cache`，同一請求第二次呼叫不打 DB）。驗證：AC-SH-27 用 `DEBUG_SQL` 計數。
- **Server Component 為主**：`HomeHero`、`TodoCard`、`SectionHead`、`UserAvatar` 都是 server；client 只有：`DashboardFrame`（側欄狀態、Sheet）、`DashThemeToggle`、`AccountMenu`（選單）、`HeroTrail`＋`PixelTrail`（WebGL）、`AvatarPicker`（B）。理由各一句寫在檔頭。
- 圖示：`@tabler/icons-react` 在 Next 16 的 `optimizePackageImports` 預設清單，不用設；但側欄圖示由 `_nav.ts`（server）指定成元件參照再傳進 client 的 `DashboardFrame`，每個角色只打包自己 3～6 個。
- 圖片：`UserAvatar` 固定寬高＋lazy；預設頭像 WebP ≤ 25 KB；橫幅沒有點陣圖。
- 動畫：Pixel Trail 只在 `pointer: fine`＋未減少動態＋WebGL2 可用時載入（§3.5）；深淺色切換的 View Transition 在 `prefers-reduced-motion: reduce` 時直接切。
- 字型、CSS：不新增字型；狀態色與深色 token 加進 `globals.css` 約 +60 行，CSS 總量 ≤ 現值 ＋ 5 kB。

### 7.3 量測腳本（SH-6）

- `web/scripts/perf-budget.mjs`：讀 `.next/app-build-manifest.json` 與 `.next/static/**` 的 gzip 大小，算每個 `app/dashboard/**` 路由的 First Load JS，和 `web/perf-budget.json` 比對；超過 `limit` 就 exit 1 並印出超過的路由與最大的 5 個 chunk；也檢查首頁路由 chunk 清單不含 `recharts`。CI 在 `pnpm -C web build` 之後加一步 `pnpm -C web perf:budget`。
- `web/scripts/perf-lab.mjs`：Playwright Chromium（4× CPU 節流）打 6 個路由（三角色首頁、`/dashboard/admin/accounts`、`/dashboard/teacher/grading`、`/dashboard/student/affairs`）各 5 次，用 `web-vitals` 的 attribution build（inline 注入，不進產品 bundle）取 LCP／INP／CLS 與伺服器時間，印 p75 表；不進 CI，PR 附結果。
- 兩個腳本不改產品程式；`package.json` 加 `perf:budget`、`perf:lab` 兩個 script。
