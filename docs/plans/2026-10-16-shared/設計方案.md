### 3.5 Pixel Trail：正式寫法（10/15 晚＋效能基準 §5）

量測：原型卡頓的來源是每幀為每個軌跡點 `createRadialGradient` 畫到 512² 的 2D canvas（`prototype/src/components/dashboard/pixel-trail.tsx:481-494`），再把兩張 canvas 用 `texImage2D` 上傳成貼圖（`:629-633`）；CPU×4 時主執行緒 48%、4 次長任務。正式版規則：

- **禁止**：每幀 `texImage2D`／`texSubImage2D` 上傳 2D canvas；每幀 `createRadialGradient`；用 2D canvas 當中介。
- **允許兩種做法，擇一**：(a) 軌跡點保存在 JS 陣列（上限 64 點，含插補），每幀以 `uniform vec4 u_points[64]`（x、y、age、force）送進 fragment shader，格子亮度在 shader 內用放射衰減計算；(b) 兩張 `gridSize²` 的 framebuffer ping-pong：每幀只畫新點與衰減（兩次小 draw call），主畫面取樣結果貼圖。兩種都沒有每幀 CPU 側的像素工作。
- 參數：gridSize 64、maxAge 800、color `#c9d1dc`、trailColor `#bea468`、shape square、gap 0.16、decay fade、shine 1、glow 0.15；`interpolate` 降到 2（點數上限 64 內）。
- 閒置：指標離開橫幅且所有點 age ≥ maxAge 後停 `requestAnimationFrame`；分頁不可見時停；unmount `loseContext()`。
- 載入條件、`data-state`、CSP、`pointer-events: none`、零依賴、授權檔頭同第 2 輪。
- 預算（CPU×4、滑鼠在橫幅上掃 5 秒）：主執行緒腳本占用 ≤ 20%、長任務（> 50 ms）0 次、chunk gzip ≤ 10 KB。量法 §7.5。
