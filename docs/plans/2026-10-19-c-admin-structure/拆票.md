# C 階段規格② — 拆票

- 基底一律 `origin/stage-c`；PR 目標 `stage-c`；每票 PR 必須 CI 綠（會紅等後票修的測試，由改的那張票一起改斷言，不留紅）。
- 每票五欄：可改檔案（含測試檔）／受影響既有測試／衝突時怎麼辦／對應驗收案例／verify 指令與證據。加「依賴」與「波次」。**同一波票的檔案不重疊**（§6 碰撞表）。
- verify 入口照 `web/AGENTS.md`：`pnpm -C web verify [單元檔]`、`--integration <檔>`、`--e2e <spec>`（build＋start＋worker，`--workers=1`）。證據：終端最後一段貼 PR；SQL 證據存 `/tmp/<票>-sql-<n>.json`；perf 證據貼 `perf:bundle` 全表。
- 大小：S 1.5h、M 3h、L 5h（B 階段時數模型）。
- 「不改程式碼」是架構師的規則；實作者照票改。
