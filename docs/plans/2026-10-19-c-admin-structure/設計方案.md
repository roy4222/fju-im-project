## 0. 這份規格解決什麼

走查（主腦探索 X1–X10、角色走查 S/T/A）找出的問題有三類，全部屬於「外殼」：

1. **找不到**：功能散在危險區、小字連結、`<details>` 折疊、入口頁第二層（X1、X4、X5、A17、A25、Q104）。→ 每個側欄項目變成「一頁多分頁」，分頁是自己的路由（§2），功能全部在分頁的標題列或每一列上。
2. **多餘的問法**：核實方式、必填理由、「第 N 版」（X2、X3、A18、A19）。→ 全站規則（§1）。
3. **前台與後台的分工**：登入後的前台跟訪客不一樣、「我的帳號」在前台、系辦改不到前台文字（S12、S18、A7、A8、X8、X9）。→ 前台對所有人一樣（§5）；系辦多一個「編輯頁面」開關（§6）。

## 2. 系辦後台：每個側欄項目的分頁與路由

### 2.1 原則

- **分頁 = 路由**（沿用 B 階段 `AdminTabs` 純連結的做法，`_tabs.tsx` 元件不改）。每個分頁有自己的 `page.tsx`、自己的 `requireRole`、自己的 `PROTECTED_ROUTES` 列與 `e2e/fingerprints.ts` 指紋（B 階段規矩：守衛在頁面自己，layout 擋不住）。
- 分頁列常數**集中**到新檔 `web/src/app/dashboard/admin/_tabs.ts`（`AFFAIRS_TABS`、`GROUP_TABS`、`GRADING_TABS`、`ACCOUNT_TABS`、`SETTINGS_TABS`），各頁只 import；目前 12 個 `page.tsx` 各自複製一份常數的做法停掉（`cohorts/page.tsx:23`、`audit/page.tsx:32`、`home-settings/page.tsx:16`、`timeline/page.tsx:48`、`affairs/page.tsx:40`、`showcase/page.tsx:30`、`files/page.tsx:17`、`groups/page.tsx:58`、`industry/page.tsx:25`、`grading/page.tsx:33`、`grading/settle/page.tsx:20`、`signoff/page.tsx:119`）。①③之後不得再自己定義分頁列。
- 每個分頁的外殼固定三層：`PageTitle`（標題＝側欄名；`actions` 放這個分頁的主要「新增」鈕）→ `AdminTabs`（`label="<側欄名>分頁"`）→ **一行說明句**（`<p data-testid="tab-intro">`，也是該路由的 e2e 指紋，見 §11.1）→ 內容插槽。①③接內容時不得刪說明句（改句子要連 `fingerprints.ts` 一起改）。
- 側欄「設定」`href` 改 `/dashboard/admin/cohorts`，`activeFor` 列新路由；其他五項 `href` 不動，`activeFor` 補新分頁路由。

### 3.3 待審核 `/dashboard/admin/accounts/pending`（A17、A19、V5、X3）

- 列：姓名、學號、Email、申請時間、名單比對（「名單有這個人（115 屆）」／「名單沒有」／「學號對到別人」）、本人填的系級。**不出現「第 N 版」**；被退回後重送的人只在列尾加「已重送」灰字。
- 每列兩顆：**核准**、**退回**。
  - 核准：名單有比對到 → 一鍵完成（屆別＝名單那屆，`verification_method='office_review'`，理由不問）。名單沒比對到 → 跳一個只有「屆別」下拉的小視窗，選了就核准。
  - 退回：視窗只有一欄「理由（必填，申請人會看到）」（`registration.ts:405-406` 既有）。
- 批次：勾選 → 「核准勾選的 N 人」，沿用 `BulkApproveDialog`，但去掉核實方式；名單沒比對到的人在預覽裡標「要先選屆別」並跳過（既有 `offRosterIds` 行為）。

## 6. 前台編輯模式框架（A8、X8、X9；定案 B）

### 6.1 誰看得到、長什麼樣

- 只有**系辦＋已開通**（`actorHasRole(actor,'admin') && checkStatus(actor,'business') === null`）。訪客、學生、老師的 HTML 一字不差。

  - 只能改不能刪的（頁尾聯絡、隱私權政策、首頁橫幅文字、三張卡）只有「編輯」；
  - 再按一次「完成編輯」關掉。開關狀態存 `sessionStorage`（換頁保持、關分頁就忘）。
- 編輯模式下點一則的連結照常跳頁（跟 C 不同）；「編輯」「刪除」按鈕放在連結**外層**（原型已知限制要修）。
- 涵蓋頁面：`/`（橫幅文字、最新公告、近期活動、歷屆專題一覽、優秀專題、榮譽與競賽、三張卡）、`/files`（檔案、分類名稱）、`/rules`（每一節）、`/industry`（合作案，③）、`/privacy`（整頁內文）、頁尾（每一頁）。

### 6.2 怎麼做到「訪客一個位元組都不多」（沿用原型做法，正式化）

1. 前台頁照常是 server 元件。只在系辦時，既有元素多 `data-fe-*` 標記（`feSection`／`feItem`，`_ui/front-edit/mark.ts`）；其他人拿到空物件。
2. 編輯層（client）**不放在** `/`、`/files`… 的模組圖裡（原型實測：連 `next/dynamic` 條件載入也會讓訪客多 3.9 KB）。它只存在另一組路由 **`/office-edit`、`/office-edit/files`、`/office-edit/rules`、`/office-edit/industry`、`/office-edit/privacy`**（每個 `page.tsx` 只是「原頁元件＋`<FrontEdit/>`」）。
3. `proxy.ts`：請求是 GET/HEAD、路徑在那五條、而且帶 **`fju_office=1`** cookie 時，`NextResponse.rewrite` 到 `/office-edit/*`，網址列不變。沒有 cookie 的人完全不經過這段。
4. `fju_office` cookie：**只是提示，不是授權**。Better Auth `hooks.after`（`auth-instance.ts` 已 import `createAuthMiddleware`）在 `/sign-in/email`、`/callback/*`（Google）、註冊續辦完成建 session 之後，查 `role_assignments` 有 active admin 就 `setCookie('fju_office','1',{httpOnly:true,sameSite:'lax',path:'/'})`；`sign-out.tsx` 的 `signOutAction` 清掉；設為／取消管理員會撤 session（B-R4），重登就重算。cookie 存在但不是系辦（例如撤了管理員還沒登出）：`/office-edit/*` 自己再用 `renderActor()` 判一次，不是系辦就只回原頁不掛編輯層（多下載一支 chunk，但畫面零差異）。
5. 直接打 `/office-edit/*`（沒有 proxy 改寫）：proxy 在改寫時加請求標頭 `x-fju-office-rewrite: 1`；`office-edit` 的 page 讀不到這個標頭就 `redirect` 回對應公開路徑，避免同一頁兩個網址被收錄。
6. 編輯層的樣式由 `front-edit.tsx` 自己 `import './front-edit.css'`（原型 `be52dd3` 的做法），全站 `globals.css` 不變。

### 6.3 編輯層對「一則」做什麼（框架提供的）

#### 6.3.1 表單 registry 契約（②集中登錄；①③只提供模組，不碰 `forms.ts`）

`web/src/app/_ui/front-edit/forms.ts`（C2-16 建檔並定型別；C2-17 登錄②的四種；①③的表單合進 `stage-c` 後，由②各補一行 import，①③的票不改這個檔）。**這裡是定版**：kind 名對齊①既有模組命名（`rules`、`submission`、`showcase` 都照 placement／資料表叫），①《設計方案》§11.3 照這版改；①原本的 `ItemFormProps`（`onDone` 回 `{itemId,status}`、revision 讀 `ItemDetail.revision`）包一層 adapter 模組就符合下面的介面。

```ts
export type FeKind =
  | 'news' | 'submission' | 'rules' | 'resource' | 'honor' | 'showcase'   // ①（競賽併在 news）
  | 'resource_category'                                                // ①（要補模組）
  | 'activity' | 'opportunity'                                          // ③
  | 'hero' | 'quick_card' | 'footer_contact' | 'privacy'                // ②

/** `data-fe-fields` 的 JSON：只放表單要預填的純值。 */
export type FeFields = Record<string, string | number | boolean | null>

export interface FeFormProps {
  mode: 'edit' | 'add'
  kind: FeKind
  id: string | null          // edit 必填（data-fe-id）；add 為 null
  revision: number | null    // data-fe-rev 預填；表單可以自己重讀最新 revision（①用 ItemDetail.revision）
  cohortId: string | null    // 區塊的 data-fe-cohort；add 時建立用，沒有就由表單取預設工作屆別
  fields: FeFields
  /** 成功後呼叫一次。回傳值框架只拿來組 toast（「已儲存」／「已發布」）與記 log，不依賴它。 */
  onDone(result?: { id: string; status?: 'draft' | 'published' | 'saved' }): void
  onCancel(): void
}

export interface FeFormModule {
  default: React.ComponentType<FeFormProps>
  /** 有才能刪；框架先跳確認再呼叫。回 ok:false 時框架把 message 顯示在確認框、不關窗。 */
  remove?: (input: { id: string; revision: number | null; requestId: string }) => Promise<{ ok: true } | { ok: false; message: string }>
}

export const FE_FORMS: Record<FeKind, () => Promise<FeFormModule>> = {
  news: () => import('@/app/dashboard/admin/affairs/front-edit/news'),      // 路徑由①定、②登錄
  // …
  hero: () => import('./forms/hero-form'),                                  // ②
  quick_card: () => import('./forms/site-text-form'),
  footer_contact: () => import('./forms/site-text-form'),
  privacy: () => import('./forms/site-text-form'),
}
```

責任切分：**表單**自己呼叫自己的 server action（`requestId` 冪等）、自己顯示欄位錯誤與 `STALE`（revision 不符）訊息、自己管送出中的按鈕狀態；**框架**負責開關窗、刪除確認、`onDone` 後的 toast＋`router.refresh()`＋關窗、`remove` 成功後的 toast＋refresh、找不到 kind 時顯示「這個區塊還不能在前台改」。表單不得 `router.push`、不得自己 `router.refresh()`、不得自己發 toast。

## 9. 快取與打包

- **沒有 ISR／revalidate 問題**：`proxy.ts` 每請求發 nonce 寫進 CSP，所有頁面都是動態渲染（`page.tsx` 有 `renderActor()`），存完 `router.refresh()` 就是新資料。不用 `revalidatePath`。

- **打包預算**（`budget.json`）：`/` 列不動（baseline 222、limit 245），AC-C2-43 要求訪客 `/` 的 gzip **不大於** `stage-c` 開工時的實測值（原型實測 −273 B）。新路由各加自己的列：`/office-edit`、`/office-edit/files`、`/office-edit/rules`、`/office-edit/industry`、`/office-edit/privacy`、`/dashboard/admin/accounts/pending`、`/disabled`、`/roster`、`/dashboard/admin/affairs/assignments`、`/resources`、`/rules`、`/dashboard/admin/groups/unassigned`、`/dashboard/admin/grading/teachers`，limit 一律 250（S10 不加路由，§5.3）。刪掉的路由（`/dashboard/admin/home-settings`）刪列。
- **編輯路由自己也受 250 KB 管**：`/office-edit` 首載 = `/` 首載 ＋ 編輯層（原型 +3.9 KB）；①③的表單（尤其帶 Tiptap 的公告、成果展示表單，`/dashboard/admin/editor/[id]` 已 241.7 KB）**一律按下編輯才載入**（§6.3）。若實測仍超：**實作回報 ESCALATE**，不改成跳後台（B 模式一律原頁開窗；Q-C2-5 主腦裁定）。
