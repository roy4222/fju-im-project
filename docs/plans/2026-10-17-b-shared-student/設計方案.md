## 4. 登入身分快取 60 秒（SH-B1，Q189 已定）

### 4.1 設計

- 新模組 `web/src/infrastructure/auth/identity-cache.ts`：程序內 `Map<sessionToken, { actor: ResolvedActor, userId, expiresAt }>`，TTL 由 `IDENTITY_CACHE_TTL_SECONDS` 決定（預設 `60`，`0` = 關閉）；提供 `get(token)`、`set(token, actor)`、`bustUser(userId)`（刪掉該使用者所有 token 的項目）、`bustToken(token)`、`clear()`（測試用）。上限 5000 筆，超過時丟最舊的。
- `DbActorResolver.resolve(headers)`：先取 cookie 裡的 session token；命中且未過期直接回 `ResolvedActor`（**0 句 SQL**）；未命中走現在的流程（Better Auth `getSession` ＋ users／user_profiles ＋ role_assignments ＋ `needsSetup`），存進快取。匿名（沒有 cookie）不進快取。
- **主動失效（程序內 bust）**，這些動作後下一次請求就是新資料：
  - 登出：`wrapper.ts` 的 signOut 包裝呼叫 `bustToken`。
  - 系辦停用、恢復、去識別化、加／撤角色：`account-directory-command.ts` 對應 command 成功後 `bustUser(userId)`。
  - 改密碼、重設密碼、撤銷 session（VB-2 的 `revokeSessionsOnPasswordReset`）：`auth-instance.ts` `hooks.after`（:473 已有）比對 `ctx.path` 為 `/change-password`、`/reset-password`、`/revoke-session`、`/revoke-sessions` 時 `bustUser`。
  - 老師首次設定完成（`teacher-setup.ts` 的 `complete`）：`bustUser`。
  - 系辦核發暫時密碼（設 `must_change_password`、撤 session 的那個 command，`session-revocation.integration.test.ts` 蓋到的路徑）：`bustUser`。
  - `/reset-password` 的 after hook 裡使用者沒登入、`ctx` 拿不到 `userId` 時，退而 `clear()`（整個快取清掉；重設密碼是罕見路徑，寧可全清）。
  - 角色切換不需要 bust：resolver 不讀「目前角色」欄位，切換只在 URL 與畫面。
  - 換頭像、重設頭像（SH-9 的 `avatar-store.ts`）：`bustUser`。
  - Better Auth 的 `cookieCache` 維持 `enabled: false`，不用它（它快取的是 session 不是我們的 actor，且 TTL 在 cookie 裡客戶端可控）。
- **被接受的延遲（Q189）**：直接改 DB（worker、SQL、別的程序）而沒經過上面那些入口的改動，最多 60 秒後生效。
- **單程序假設**：正式與測試站都是 compose 裡一個 standalone app 容器，程序內 bust 足夠。將來多副本時這個設計要換成共用快取（寫在契約 03 的註記，不是待問）。

### 4.2 測試環境

- `perf:sql` **開著快取跑**（預設 60 秒）：第二次抓取時身分 SQL 歸 0，這就是 SH-B1 的證據。`sql-expect.json` 全部路由重新基準（identity 欄為 0，total 減去各路由原本的身分句數），缺列的路由（§8）一併補上。
- **e2e 與 CI 的 e2e job 用 `IDENTITY_CACHE_TTL_SECONDS=0`**：幾乎所有 spec 直接用 `DATABASE_URL_OWNER` 改帳號狀態、角色（`identity-per-request.spec.ts`、`accounts.spec.ts:141`、`session.ts grantExtraRole`…），關掉快取才能保持它們的前提。`playwright.config.ts` 沒有 `webServer`，app 由 verify 腳本（或 CI）啟動並繼承 `process.env`，所以 verify 指令前綴 `IDENTITY_CACHE_TTL_SECONDS=0` 即可，不改 V0 的腳本；若 V0 不透傳 env，請 V0 擁有者加一行。`ci.yml` e2e job 的 env 多一行，併進 SH-B3（Roy 合）。
- `identity-per-request.spec.ts` 的檔頭說明改寫：「快取不跨請求」改成「TTL 0 時不跨請求；正式環境的停用、撤角色走系辦畫面，由 `bustUser` 保證下一次請求生效」。AC-SH-59、60 的斷言不變。
