## 3. 各項做法

### 3.1 待辦口徑（ST-1）：一份清單給首頁、交作業、徽章

新檔 `web/src/app/dashboard/student/_todo/todos.ts`（純伺服器、不含 JSX）與 `_todo/due-text.ts`（`dueText`，ST-2／ST-3 都用，所以放 ST-1）：

```ts
export type TodoStatus = 'overdue' | 'soon' | 'open' | 'notOpen' | 'exempt' | 'done'
export type StudentTodo = {
  kind: 'item' | 'consent'
  id: string            // itemId 或 versionId
  title: string
  due: Date | null      // 同意書永遠 null
  status: TodoStatus
  label: string         // 膠囊字：逾期／快到期／待交／尚未開放／免繳／已交／補交／待你同意／已同意／不同意／（signoffStateLabel）
  href: string          // /dashboard/student/affairs/<itemId> 或 /dashboard/student/signoff?version=<versionId>
  draft: boolean        // 有草稿 → 首頁卡按鈕字「繼續填寫」
  unit: 'individual' | 'group' | null   // 'group' → 卡片小字「整組」（已定 Q128）
  late: boolean         // reopenUntil 生效中 → 膠囊「補交」（已定 Q128）
}
export const studentItems   = cache(async (userId: string) => Promise.all([getSubmissionQuery().myItems(userId), getBusinessClock().now()]))
export const studentSignoff = cache(async (userId: string) => getSignoffQuery().studentView(await shellViewer()))  // 只讀；授權已在頁面做過
export const studentTodos   = cache(async (userId: string): Promise<readonly StudentTodo[]> => …)  // studentItems + studentSignoff
export function todoCounts(todos): { open: number; done: number; overdue: number }   // open 篩選＝ 'open'+'soon'+'notOpen'；done 篩選＝ 'done'+'exempt'
export function studentOpenCount(todos): number     // 徽章＝ 'open'+'soon'＋同意書 'open'（**不含** overdue、notOpen；已定 Q117、Q119）
export function nextDue(todos): StudentTodo | null  // 第一件有截止日、status ∈ open/soon/overdue 的
export function homeTodos(todos, limit = 5): readonly StudentTodo[]  // 未完成不足 5 用最近已交補滿（已定 Q124）
export const SOON_DAYS = 10                          // 已定 Q118
```

- 作業列 → `receiverStatus(row, row, now)`（既有 `ItemStatusView`）對應：`overdue` → `overdue`；`submitted`（含可重送）→ `done`；`exempt` → `exempt`（膠囊「免繳」、在「已交」篩選）；還沒到開放時間 → `notOpen`（灰膠囊「尚未開放」、在「待交」篩選、**不計徽章**）；`pending` 且 `daysLeft ≤ SOON_DAYS` → `soon`；其餘 `pending` → `open`。截止日用 `reopenUntil ?? dueAt`，`reopenUntil` 生效時 `late = true`、膠囊「補交」（已定 Q128）。
- **同意書（已定 Q123；照 Review 6 修）：** `isCurrent` 只表示簽核包目前指標 `current_version_id` 指著它，**不表示有效**。組員異動或人工作廢後，`current_version_id` 仍指向 `state === 'superseded'`／`'void'` 的版本（實例：`pg-signoff.integration.test.ts:584` 的 `{ state: 'superseded', cause: 'member_change', isCurrent: true }`）。所以取卡的順序是：
  1. 只取 `isCurrent` 的版本；
  2. **先排除 `state === 'superseded' || state === 'void'`**（作廢不列卡，同意書頁的 `signoff-invalidated` 提示保留，新版建立後出現新卡）；
  3. `state === 'revision'`（退回修正中、不能表態）→ `done`、膠囊照 `signoffStateLabel`（「退回修正中」）；
  4. 其餘：`viewer.canRespond` → `open`（「待你同意」）；`viewer.voted` 有值 → `done`（「已同意」／「不同意」）；其他（輪到老師、已完成、不在名單）→ `done`（字照 `signoffStateLabel`）。
  反例寫進 `todos.test.ts`：`isCurrent: true, state: 'superseded', viewer.voted: 'agree'` → **不列**（不能變成「已同意」卡）；`isCurrent: true, state: 'void'` → 不列；`isCurrent: false, state: 'complete'` → 不列。AC-ST-27 驗畫面。
- 排序（原型 `studentTodos()`）：未完成先、依截止日近到遠，沒截止日的同意書排在有日期的後面；已完成排最後、依最近送出時間。首頁取前 5，不足 5 張用最近已交補滿（已定 Q124）。
- `cache` 是 React 的 per-request memo，**引數比對用 `Object.is`，物件引數會 miss**（共用 r3 §2.0：loader 一律以 primitive 當 key）。所以三個函式都用 **`userId: string`** 當 key；**所有呼叫端一律傳 `actor.userId`**（首頁、交作業、組別里程碑、同意書頁、`/timeline`、`nav-badges.ts` 學生分支——後者由共用 SH-1-ST 接線），需要 `ResolvedActor` 的地方在函式內用 `renderActor()`（共用 SH-P1；`shellViewer` 是它的別名）取（只讀，不做授權）；所以 `todos.ts` 只能在 Server Component 用，Server Action／Route Handler 不得 import（SH-P1 的 lint 規則會擋）。同一次請求裡 `myItems` 與 `studentView` 各只**讀一次**（在真實 RSC 請求內以 `perf:sql` 的 `duplicates` 驗，見 §4.1、AC-ST-25）。
- 單元測試 `todos.test.ts`：對應關係（含 `notOpen`、`exempt`、`late`）、排序、`nextDue`、`homeTodos` 補滿、同意書狀態（含三個反例）、`reopenUntil` 優先；用固定時鐘。`due-text.test.ts`：「沒有截止日」／「M/D 截止・剩 N 天」／「今天截止」／「逾期 N 天」／「補交到 M/D」。
