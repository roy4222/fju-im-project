## 3. 各項做法

### 3.1 待辦口徑（ST-1）：一份清單給首頁、交作業、徽章

新檔 `web/src/app/dashboard/student/_todo/todos.ts`（純伺服器、不含 JSX）：

```ts
export type TodoStatus = 'overdue' | 'soon' | 'open' | 'done'
export type StudentTodo = {
  kind: 'item' | 'consent'
  id: string            // itemId 或 versionId
  title: string
  due: Date | null      // 同意書永遠 null
  status: TodoStatus
  label: string         // 卡片右上角的字：逾期／快到期／待交／已交／待你同意／已同意／尚未開放／免繳（後兩個 ⏸ D-ST-3）
  href: string          // /dashboard/student/affairs/<itemId> 或 /dashboard/student/signoff?version=<versionId>
  draft: boolean        // 有草稿 → 首頁卡按鈕字「繼續填寫」
  unit: 'individual' | 'group' | null
}
export const studentItems = cache(async (userId: string) => Promise.all([getSubmissionQuery().myItems(userId), getBusinessClock().now()]))
export const studentSignoff = cache(async (userId: string) => getSignoffQuery().studentView(await shellViewer()))  // 只讀；授權已在頁面做過
export const studentTodos = cache(async (userId: string): Promise<readonly StudentTodo[]> => …)  // studentItems + studentSignoff
export function todoCounts(todos): { open: number; done: number; overdue: number }       // open = 'open' + 'soon'
export function studentOpenCount(todos): number                                           // 徽章＝open（⏸ D-ST-1）
export function nextDue(todos): StudentTodo | null                                        // 第一件有截止日、未完成的
export function homeTodos(todos, limit = 5): readonly StudentTodo[]
```

- 作業列 → `receiverStatus(row, row, now)`（既有 `ItemStatusView`）對應：`overdue` → `overdue`；`submitted`（含可重送）→ `done`；`pending` 且 `daysLeft ≤ SOON_DAYS` → `soon`；其餘 `pending` → `open`。截止日用 `reopenUntil ?? dueAt`（系辦開了個別補交期限就以它為準，⏸ D-ST-13）。`SOON_DAYS = 10`（⏸ D-ST-2），與前台「我的工作」列的 10 天橘字同一個數。
- 同意書 → `studentView(actor).versions` 只取 `isCurrent` 的版本：`viewer.canRespond` → `open`（字「待你同意」）；`viewer.voted` 有值 → `done`（字「已同意」／「不同意」）；其他（輪到老師、已完成、不在名單）→ `done`（字照 `signoffStateLabel`）。`superseded`／`void` 不是目前版本，不列（⏸ D-ST-8）。
- 排序（原型 `studentTodos()`）：未完成先、依截止日近到遠，沒截止日的同意書排在有日期的後面；已完成排最後、依最近送出時間。首頁取前 5（⏸ D-ST-9：未完成不足 5 時要不要用已交補滿）。
- `cache` 是 React 的 per-request memo，**引數是物件時比的是參照**：頁面的 `actor`（`requireRole` → `currentActor()`，刻意不 cache，見 `guard.ts:30-33`）和徽章的 `actor`（`shellViewer()`）是兩個不同物件，用 `actor` 當 key 會 miss、查兩次。所以三個函式都用 `userId: string` 當 key，需要 `ResolvedActor` 的地方在函式內用 `shellViewer()` 取（只讀，不做授權）。同一次請求裡首頁、側欄徽章（共用的 `nav-badges.ts` 改成呼叫 `studentOpenCount(await studentTodos(actor.userId))`，見 §7）、「下一件要交的」、同意書頁（改讀 `studentSignoff(userId)`）都讀同一份結果，`myItems` 與 `studentView` 各只查一次。
- 單元測試 `todos.test.ts`：對應關係、排序、`nextDue`、同意書的四種狀態、`reopenUntil` 優先；用固定時鐘。

### 4.3 圖片

A 階段學生頁沒有內容圖片（圖示是 SVG）。B 的頭像：`<img loading="lazy" width height>`、固定尺寸、`alt` 是姓名；首頁「現在」橫幅沒有圖片，LCP 元素是階段名文字。

### 4.4 動畫載入條件（Pixel Trail，AC-ST-20）

- 元件由共用提供；本規格只在 `now-banner.tsx` 的 `trail` 插槽掛 `<HeroTrail />`。
- `next/dynamic(() => import(...), { ssr: false })`：不進首頁的首批 JS；只有 `(hover: hover) and (pointer: fine) and (prefers-reduced-motion: no-preference)` 成立才掛（原型 `hero-trail.tsx` 的 `useSyncExternalStore` 寫法）；觸控、縮減動態、WebGL2 不可用都不掛、不報錯。
- 只掛在學生與老師首頁的「現在」橫幅，其他頁不載。
- 畫布 `pointer-events: none`，橫幅裡的「看完整時程」「繼續填寫」照常可點（AC 驗）。
- 原型量測 ~16 KB（gzip ~6 KB），不計入首頁 First Load JS 目標（動態載入）。

### 4.5 其他

- 卡片顏色全用 class（CSP 無 inline style）。
- 分頁與篩選是連結，RSC 導覽；不做 client 端篩選。
- `studentTodos` 用 React `cache` 做 per-request memo，不做跨請求快取（學生資料是私有的）。
