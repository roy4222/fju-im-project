## 1. 這次絕對不要做

1. **不要把任何私有檔標成可快取，也不要把公開的非圖片檔標成可快取。** 只要下載政策不是以「訪客」身分放行的，回應就是 `private, no-store`、沒有 `ETag`；訪客放行但 `mime_detected` 不是 `image/png`／`image/jpeg` 的（PDF、Office、ZIP…）同樣 `private, no-store`、沒有 `ETag`。公開與否只能走 `authorizeDownload` 既有的政策鏈（§3.4），不准在 route 或別處另寫一套「這個 purpose 大概是公開的」判斷。
2. **不要把置頂塞進編輯器草稿（`ItemInput`／`ItemDraft`）。** 置頂是列表上的展示動作：不切版本、不寫發布紀錄、不動 `revision`，不碰 `normalizeItemInput`、`item-form-model.ts`、`item-settings.tsx`、`quick-create-dialog.tsx`。
3. **不要放寬 CSP、不要改共用的 `search-sort-bar.tsx`、不要改 `showcase_versions`／`showcase_drafts` 既有資料列。** 影片解析在讀取端做；CSP 字串與 `security-headers.test.ts` 一字不動。

### 3.4 Q50-a 公開圖片可快取

**判定（只在既有授權鏈上加一個布林）**

- `web/src/application/ops/files.ts` `FileDownload` 加 `publicRead: boolean`，註解：「訪客（`ANONYMOUS`）走同一條政策也會放行＝這個檔此刻對所有人公開」。
- `web/src/infrastructure/ops/file-storage.ts` `authorizeDownload`：
  - 現行流程不動（先查檔、查引用、問政策、不允許就 `denied()`）。
  - 允許之後：`publicRead = (anonymous || gatedToVisitor) ? true : await policy(ANONYMOUS_ACTOR, facts)`。登入者多一次政策查詢（一兩句 SQL），訪客不多查。
  - **不准**用 `publicReadPurposes` 或 purpose 名稱推論公開：`publicReadPurposes` 的語意是「待審／必須改密的人比照訪客問政策」，不是「這些 purpose 公開」。
- 哪些檔會是 `publicRead = true`（由既有政策決定，不新增規則）：`poster`＝發布中、有獎項等級的條目目前版本的海報；`photo`＝`home_settings.hero_file_id` 現在那張；`attachment`（含公告封面）＝發布中、對象「公開訪客」的項目的附件與封面。其餘（學生對象附件、草稿海報、未得獎作品海報、繳交檔 `submission`…）全部 false。`publicRead` 的語意只有「訪客也拿得到」，**不等於可快取**。

**可快取（另一個判斷，疊在 `publicRead` 上）**

- `web/src/application/ops/files.ts` 加純函式 `isCacheableDownload(d: Pick<FileDownload, 'publicRead' | 'mime'>): boolean` ＝ `d.publicRead && (d.mime === 'image/png' || d.mime === 'image/jpeg')`，配單元測試（加在既有 `web/src/application/ops/files.test.ts`；公開 PNG／JPEG 真；公開 PDF、DOCX、ZIP、`application/octet-stream` 假；私有 PNG 假）。經模組入口 `web/src/application/ops/index.ts` 匯出，`web/src/composition/files.ts` 再 re-export 給 route（route 現在只從 `@/composition/files` 拿 `contentDisposition`、`downloadFile`）。
- `FileDownload.mime` 已經是 `row.mime_detected ?? 'application/octet-stream'`（`file-storage.ts:423`）：`mime_detected` 是上傳收檔時依驗證後的檔型寫入的 canonical MIME（`file-storage.ts:245-251`），不是使用者宣告的；`null` 自然落到 octet-stream、不可快取。
- route 只呼叫 `isCacheableDownload`，不自己比對 MIME 字串。
- 結果：公開的海報、首頁大圖（只收 PNG／JPEG）可快取；公開公告的**圖片**封面與**圖片**附件可快取；公開公告的 PDF、Office、ZIP 附件維持 `private, no-store`、無 `ETag`、不回 304（AC-V35）。

**回應（route）**

- `web/src/app/api/files/[id]/route.ts`：
  - 授權失敗：完全不變（401／403／500 JSON、303 導向，都 `private, no-store`）。**先授權再看 `If-None-Match`**：下架後帶舊 `ETag` 重打，拿到的是 401／403／303，不是 304。
  - 授權成功且 `isCacheableDownload(file) === false`（私有檔，或公開但不是 PNG／JPEG）：完全不變（`private, no-store`，不帶 `ETag`、不看 `If-None-Match`、不回 304）。
  - 授權成功且 `isCacheableDownload(file) === true`：
    - `cache-control: public, max-age=<秒數>, must-revalidate`。秒數是 **D8（pending）**，寫成 route 裡一個具名常數，測試的期望字串從同一個值組出來，定案後只改一處；這份文件與 AC 先以建議值 300 書寫，定案不同就同步改 AC（建議 300：下架、撤回、換圖後最多 5 分鐘內瀏覽器還可能顯示舊圖，但網址直接打一定是最新結果；同一個 5 分鐘內逛列表→詳情→回列表不再重抓）。
    - `etag: "<checksum>"`（強 ETag；`checksum` 為空字串時不給 `etag`，只給 `cache-control`）。
    - 請求帶 `if-none-match` 且其中任一值（去掉 `W/`、逗號分隔）等於 `"<checksum>"` → `304`，標頭只帶 `cache-control`、`etag`、`x-content-type-options`，沒有 body、沒有 `content-length`。**回 304 前必須 `await file.body.cancel()`**：`authorizeDownload` 回傳前已經 `createReadStream` 開了檔案，不消費也不取消的話檔案描述子要等 GC 才關，大量 304 會把 fd 用完。
    - `authorizeDownload` 第二次以 `ANONYMOUS_ACTOR` 問政策時重用同一份 `facts`（已查好的列與引用），不重查。
    - 200 時其餘標頭（`content-type`、`content-disposition: attachment`、`content-length`、`content-security-policy: default-src 'none'; sandbox`、`x-file-checksum-sha256`）照舊。
  - 不加 `vary: cookie`：公開回應對任何人都一樣，私有回應是 `no-store` 不會被存。Cloudflare 日後接上時再評估。
- 快取時間短的理由寫在 route 註解：可見性會變（下架、撤回、換圖、刪除），授權事實永不跨請求快取（契約 02 §8），所以只給瀏覽器 5 分鐘、而且 `must-revalidate` 過期後必須回來問。

**Next 16 注意（寫給實作者）**：route 目前只 export `GET`；驗收用 `curl -s -D - -o /dev/null`（真的發 GET），不用 `curl -I`（HEAD 可能 405）。全站 `force-dynamic` 下 Next 對頁面會自己下 `cache-control: private, no-cache, no-store…`；Route Handler 自己 `new Response(..., { headers })` 設的 `cache-control` 應該原樣送出，`proxy.ts` 的 matcher 也涵蓋 `/api/files/[id]` 但沒有改寫 cache 標頭。**本機 `next dev` 看不準**（CSP 與標頭行為不同），驗收一律用 `pnpm build && pnpm start` 後 `curl -s -D - -o /dev/null`（見 AC-V26）。

**安全考量**

- 私有檔絕不可快取：由 `publicRead` 只能來自「訪客身分走政策也放行」保證；AC-V22、AC-V24 用學生對象附件、草稿海報、未得獎海報三種私有檔驗證 `private, no-store` 且沒有 `etag`。
- 公開的非圖片檔不快取：由 `isCacheableDownload` 的 MIME 白名單（只看已驗證的 `mime_detected`）保證；AC-V35 用公開公告的 PDF 附件驗證 `private, no-store`、無 `etag`、帶 `If-None-Match` 仍 200。
- `ETag` 洩漏：`checksum` 本來就以 `x-file-checksum-sha256` 送給所有拿得到檔的人，沒有新增揭露；私有檔不給 `etag`。
- 304 不能繞過授權：304 只在授權成功之後；AC-V20、AC-V21 用「換圖後舊圖」「下架後封面」帶 `If-None-Match` 驗證。
- `sec-fetch-dest: document` 的 303 導向維持 `no-store`（既有）。

**測試 seam**：`file-storage.integration.test.ts` 加 `publicRead` 的真假案例（海報公開／草稿／未得獎、hero 現任／舊圖、公開公告附件／學生對象附件）；`files.test.ts` 加 `isCacheableDownload` 案例；route 的 304 加「連打 50 次 304 後程序開啟的 fd 數不增加」（e2e 裡用 `lsof -p` 或 `process.getActiveResourcesInfo()` 都可，寫明用哪個）；`file-download-pages.spec.ts` 加公開圖片封面 200 標頭、304、下架後帶 `If-None-Match` 仍 401／403、公開 PDF 附件 `private, no-store` 無 `etag`（AC-V35）；既有 401／303 `no-store` 斷言不改。
