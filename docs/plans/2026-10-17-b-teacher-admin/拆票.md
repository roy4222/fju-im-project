## 4. 整合分支與遷移

- 主腦開 `claude/b-integration`（從 main）。每票 Review 通過後，主腦依 §5 順序 merge 進整合分支（**不進 main**）。波 2、3 的票從整合分支開 worktree：`git worktree add -b claude/b-<票> /tmp/b-<票> origin/claude/b-integration`。
- 遷移編號（merge 到整合分支的順序決定）：0015 VB-1、0016 SH-8、**0017 A-01 grade_settlements、0018 A-01 evaluations.comment、0019 A-14 rules_position**；之後其他規格的票從 0020 起。A-09、A-08、A-19 無遷移。
- **rebase 後重新產生 migration 與 journal 的程序**（每次 merge 進整合分支前，由票的實作者做）：
  1. `git rebase origin/claude/b-integration`。
  2. 看 `web/drizzle/` 最大編號；自己的 SQL 檔若撞號或編號不連續 → 重新命名成 `max+1`。
  3. `web/drizzle/meta/_journal.json`：刪掉自己那一筆，照新檔名重新加（`idx` 連號、`tag` 同檔名、`when` 用當下毫秒）；**不要手動合併兩邊的 journal 差異**，一律以整合分支的 journal 為底再加自己的。
  4. `node web/scripts/generate-grants.mjs --write && node web/scripts/generate-grants.mjs --check`。
  5. 在乾淨 DB 跑 `pnpm -C web db:migrate`（或 verify 的 e2e 會自動跑），再跑自己票的 integration／e2e 一次，證據更新。
- 共用 JSON（`sql-expect.json`、`budget.json`、`matrix.json`、`_journal.json`）：rebase 後**不手動合併**——`matrix.json` 兩邊的列都保留、重跑產生器；`sql-expect.json`／`budget.json` 重新量測後填自己那一段。
