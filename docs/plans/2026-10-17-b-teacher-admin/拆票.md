- GRANT 產生器（`generate-grants.mjs`）只會改「切片對應的那一支」migration：新表一定用**新切片**對到**自己的新 migration**，絕不把新表掛在 `S10` 之類的舊切片（否則會改到已部署的 `0009`，升級既有資料庫時新表拿不到權限）。`managed_items.update` 維持 `"all"`，不改成欄位清單。

### 4.3 產生方式（A-01、A-14 共用；不手寫檔名、不手編 journal、不手造 snapshot）

1. 改 `infrastructure/db/schema/*.ts`。
2. `pnpm -C web db:generate --name <名>`（drizzle-kit 產出 `web/drizzle/<n>_<名>.sql`、`meta/<n>_snapshot.json`，並在 `_journal.json` 加一列）。
3. 手動補 drizzle 產不出來的部分，**只追加在該檔尾**：
   - A-01 的 0017：加兩行標記 `-- >>> 由 scripts/generate-grants.mjs 從 permissions/matrix.json 產生；不要手改 >>>` ／ `-- <<< 產生區塊結束 <<<`（前面接一行 `--> statement-breakpoint`），`matrix.json` 加 `grade_settlements` 列（`slice: "B17"`），`generate-grants.mjs` 的 `MIGRATION_BY_SLICE` 加 `B17: 'drizzle/0017_te_b2a_grade_settlements.sql'`，跑 `node web/scripts/generate-grants.mjs --write` 填入，再 `--check`。
   - A-01 的 0018：不需要（`evaluations` 只有 insert 權限，欄位級不用補）。
   - A-14 的 0019：追加回填 `update managed_items m set rules_position = x.rn from (select id, row_number() over (partition by cohort_id order by actual_opened_at asc nulls last, id asc) rn from managed_items where placement='rules' and deleted_at is null) x where x.id = m.id;`（**按屆別各自從 1 編號**，跟 `moveRule` 的鄰居集合一致）。
4. **A-01 要分兩次產生**（Review 看得出兩個變更）：先只加 `grade_settlements` 表 → 步驟 2 得 0017；再加 `evaluations.comment` → 步驟 2 得 0018。
5. 波 1 在 main 上開發時，`stage-b` 還沒有 0015／0016，本機產出來的會是 `0015_te_b2a_…`／`0016_…`：**這只是暫時編號**，合併前照 4.4 重產。

### 4.4 rebase 後重產程序（每次 merge 進 `stage-b` 前，由票的實作者做）

1. `git fetch origin && git rebase origin/stage-b`。journal／snapshot 衝突一律取 `stage-b` 版：直接 `git checkout origin/stage-b -- web/drizzle/meta/_journal.json`（不要用 `--ours`／`--theirs`，rebase 時兩者意思相反容易弄錯），繼續 rebase。
2. 刪掉自己尚未合併的 `web/drizzle/<舊編號>_<名>.sql` 與 `web/drizzle/meta/<舊編號>_snapshot.json`；journal 恢復成 `origin/stage-b` 的版本（同上指令）。
3. 重跑 4.3 步驟 2～4（A-01 兩次：暫時把 `comment` 欄從 schema 拿掉 → 產 0017 → 放回 → 產 0018）。
4. 核對新檔編號**正是**本文的 0017／0018（A-01）或 0019（A-14）。不是就停：代表 `stage-b` 的遷移順序和本表不同，回報主腦，不要自己改號、也不要手動合併 journal。
5. 更新 `migrations.integration.test.ts` 的 `LATEST`；`node web/scripts/generate-grants.mjs --check`。
6. 乾淨庫：`pnpm -C web db:migrate`（或 verify 的 e2e 會自動跑）；**升級**：從只套到 main `0014` 的資料庫再跑一次 `db:migrate`（`migrations.integration.test.ts` 的「已套 00xx、有資料的庫升版」案例就是這個 seam，A-01／A-14 各加一條）。兩者都過，再跑自己票的 integration／e2e，證據更新。
7. `git diff origin/stage-b --stat -- web/drizzle/` 只能出現自己的新 SQL、新 snapshot 與 journal 一列。

### 4.5 共用 JSON

`sql-expect.json`／`budget.json`：每票只改自己的那一列，後合者 rebase 後重新量測再填；`matrix.json`：只有 A-01 加一列；`_journal.json`：只走 4.4，不手動合併。
