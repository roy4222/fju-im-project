## 1. TE-B1 重送與暫存、TE-B4 評語（票 A-01 後端、A-02 UI）

沿用老師 r3 設計方案 §4.8 全文，這裡只列定案後的差異與契約。

### 1.1 行為

- 正式送出（counted）之後，老師仍可**暫存**（新的 evaluation，狀態 `draft`）與**重新送出**。重送：舊 counted → `historical`（`evaluation_status_events.reason = 'resubmitted'`），新的一筆 → `counted`。`evaluation_status_one_counted` 部分唯一索引保證同一時間只有一筆採計。
- 重送不通知系辦（D6）。退回（`returned`）後的流程不變。
- 已結算的階段（§2）不能暫存也不能重送：`CONFLICT`「{階段名}成績已結算，不能再改。」
- 評語：`evaluations.comment text null`，`check (char_length(comment) <= 500)`。跟分數同一次暫存／送出寫入；`evaluations` 是不可變表（matrix 只允許 insert），所以每次暫存就是新一列、評語隨列帶。空字串存成 null。

### 1.2 資料

- 遷移 `0017_te_b2a_grade_settlements.sql`（§2）、`0018_te_b4_evaluation_comment.sql`（兩支都由 `db:generate` 從 schema 產生，分兩次；0018 等價於 `alter table evaluations add column comment text; alter table evaluations add constraint evaluations_comment_length_check check (comment is null or char_length(comment) <= 500);`）。
- matrix：`evaluations` 不改（insert 已含全欄）。

### 1.3 契約（`application/grading/ports.ts`）


### 1.4 併發

- 兩個不同 `requestId` 同時重送同一指派：兩個都成功，後鎖到的那一個把前一個改成 historical；最後 counted 恰一筆（既有測試「只有一筆採計，另一筆 CONFLICT」改成「兩筆都 ok、counted 恰一筆、historical 一筆」）。
- 同一 `requestId` 重放：回同一張收據。
- 重送跟結算交錯：結算在 `grading_schemes` 頭列 `FOR UPDATE` 內先數採計份數；重送在同一把鎖內先查結算表。誰先拿到鎖誰贏（§2.4 交錯案例）。

### 1.5 畫面（`teacher/grading/[groupId]`）

- 已採計且可重送：分數欄可編輯、按鈕「暫存」「重新送出」（`data-testid="resubmit"`）；頂端狀態「已正式送出（第 n 次），可再修改後重新送出」；「送出紀錄」摺疊區列每次送出時間（`data-testid="submit-history"`）。

### 2.2 契約（`application/grading/ports.ts`，實作 `infrastructure/grading/pg-grade-settlements.ts`）

```ts
export type Settlement = {
  readonly settlementId: string; readonly cohortId: string; readonly stageKey: string; readonly stageName: string
  readonly settledAt: Date; readonly settledBy: { readonly userId: string; readonly name: string }
  readonly reason: string; readonly countedEvaluations: number
}
export type SettlementHistory = Settlement & {
  readonly releasedAt: Date | null; readonly releasedBy: { readonly userId: string; readonly name: string } | null; readonly releaseReason: string | null
}
export type SettlementReceipt = Settlement & { readonly requestId: string; readonly serverTime: Date }
export type ReleaseReceipt = { readonly settlementId: string; readonly stageKey: string; readonly stageName: string; readonly releasedAt: Date; readonly requestId: string; readonly serverTime: Date }

export interface GradingSettlementCommand {
  /** 系辦結算一個階段。FORBIDDEN → VALIDATION_FAILED(理由 1–500、階段不存在於目前版本) → COHORT_ARCHIVED → CONFLICT「{階段名}已於 {時間} 結算」。 */
  settleStage(actor: ResolvedActor, input: { cohortId: string; stageKey: string; reason: string }, requestId: string): Promise<Result<SettlementReceipt>>
  /** 解除結算。NOT_FOUND「找不到這筆結算，請重新整理頁面。」；CONFLICT「這筆結算已於 {時間} 解除」。 */

}
export interface GradingSettlementQuery {
  /** 老師與系辦都可讀；非兩者 → FORBIDDEN。 */
  settlementOf(actor: ResolvedActor, cohortId: string, stageKey: string): Promise<Result<Settlement | null>>
  /** 系辦：該屆所有階段的現行結算＋歷史（新的在前）。 */
  settlements(actor: ResolvedActor, cohortId: string): Promise<Result<readonly SettlementHistory[]>>
}
```
