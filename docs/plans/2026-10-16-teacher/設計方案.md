## 3. 共同規則（整個老師後台）

- **文字**：全站叫「作業」「作業區」「交作業」（Q83）；「認領」→「擔任指導老師」（Q52）；「暫存」→「儲存草稿」；「正式送出」保留；第 N 次送出；「我的評分」頁名改「評分」；「各組繳交」留作分頁名（決定頁原文）。
- **請洽系辦（Q81）**：所有說明段、提示句、頁面描述裡的「請洽系辦」「要改請系辦退回」「交系辦處理」拿掉；只有**被擋下的錯誤訊息**（後端 `err()` 回的 message、`blockReason`）可以留「請聯絡系辦」。逐行清單見 §8。
- **權限原則 Q47**：不能用的入口不顯示。老師沒有評分指派 → 首頁不出現「繼續評分」與待評卡；沒有指導組 → 作業區顯示空狀態而不是空表。

- **卡片不是表格**：各組繳交、我的組別、評分總覽都用卡片格；DataTable 只留在「全部組別」（分組總覽內搜尋篩選用）。
- **伺服器元件優先**：每頁一個 server component 讀一次資料；client component 只留需要互動的：評分表、分頁切換（可用 `<Link>` 加 `?tab=`，不必 client）、擔任指導老師對話框、合作案表單、作業篩選。

#### 4.2.1 TE-11：唯讀資料（A，TE-06／07 的前置）

- `TeacherQueueEntry`（`ports.ts:131-144`）加三個欄位：`leaderName: string | null`（有效組長 `group_leaders.valid_to is null` 的顯示名）、`finalScore: string | null`（`counted` 時用 `summarizeScores(stage, scores).score`）、`submittedAt: Date | null`（`counted` 列的 `submitted_real_at`）。後兩個直接從 `teacherQueue` 已經撈的 `latestEvaluations` 列算出，**0 句新 SQL**；`leaderName` 在 `teacherQueue` 的主查詢加 `left join lateral`（或同一查詢的子查詢）帶出，**不得逐組再查**。`nav-badges.ts` 只讀 `.state`，加欄位不影響它。
- **附件資料由 TE-11 自己提供（主腦裁定擁有者；r4 照複查 A-1）**：既有 `GroupVersionEntry`（`application/submissions/ports.ts:444`）只有作業 ID、標題、版本號、時間與送出人，沒有附件，初開單組頁產生不了 PDF／zip 連結。TE-11 在繳交資料的 port 新增**唯讀**批次查詢（`pg-advisor-submissions.ts` 是老師擁有的檔）：
  - `AdvisorSubmissionQuery.groupVersionsWithFiles(actor, groupId): Promise<readonly GroupVersionWithFiles[] | null>`；`GroupVersionWithFiles = GroupVersionEntry & { readonly attachments: readonly VersionAttachment[] }`；`VersionAttachment = { readonly fileId: string; readonly name: string; readonly mime: string; readonly sizeBytes: number }`。兩個新型別放在 `GroupVersionEntry` 旁，並由 `application/submissions/index.ts`（:45-46 旁）匯出。
  - 實作（`pg-advisor-submissions.ts`，在 `groupVersions` :352-378 旁新增；可抽 private helper 與 `groupVersions` 共用版本列查詢，但 `groupVersions` 的對外行為與回傳不變）：授權與 `groupVersions` 完全相同（`viewerOf` 1 句＋版本列 1 句，版本列多選 `v.id`），經 `readable()` 篩過之後，只對**讀得到的版本 ID** 再發一句 `submission_files sf join stored_files f on f.id = sf.file_id where sf.submission_version_id = any($1::uuid[])`（依版本、`field_key` 排序）；沒有讀得到的版本就不發。`name`＝`f.original_name`、`sizeBytes`＝`Number(f.size_bytes ?? 0)`、`mime`＝`coalesce(f.mime_detected, 'application/octet-stream')`（與下載回應的 `content-type` 同源：`infrastructure/ops/file-storage.ts:423`，**不用** `mime_declared`）。固定 **3 句**，不隨版本數或附件數成長。不是老師、`groupId` 非 UUID → `null`（同 `groupVersions`）。

系辦 r2 §7.9 寫的 `GradingCommand.finalize(actor, cohortId, reason)`／`gradebook.finalizedAt` **作廢**，以下表為準。所有命令走既有操作帳本（`OperationLedger.begin`／`commit`，契約 01 §8）：同 `requestId` 同內容回原回執（`outcome: 'replay'`）、同 `requestId` 不同內容 `REQUEST_MISMATCH`、回執過期 `RECEIPT_EXPIRED`、`requestId` 不是 UUID → `VALIDATION_FAILED`（`badRequestId()`）。錯誤碼只用 `src/shared/errors.ts` 既有的。

| 介面 | 輸入 | 回執／回傳 | 錯誤型別（依序檢查） | requestId 規則 |
|---|---|---|---|---|
| `GradingCommand.settleStage(actor, input, requestId)` | `{ cohortId: string; stageKey: string; reason: string }`（`reason` 去空白後 1～500 字） | `SettlementReceipt = { settlementId; cohortId; stageKey; stageName; settledAt: string(ISO); settledBy: { userId; name }; countedEvaluations: number（結算當下該階段 counted 份數）; requestId; serverTime }` | `FORBIDDEN`（非系辦）→ `VALIDATION_FAILED`（`requestId`／`cohortId` 非 UUID、`reason` 空或超長、`stageKey` 不在目前方案）→ `COHORT_ARCHIVED` → `CONFLICT`「{階段名}已於 {時間} 結算」（同屆別×階段已有未解除的結算） | 帳本 `operationKind='grading.settle'`，`fingerprint=sha256(canonicalJson({cohortId, stageKey, reason}))`，`scope='cohort'`；audit `grading.settle`，事件 `grading.settled`（收件人：系辦；老師是否通知依 D6 的同一原則，不另發） |
| `GradingCommand.releaseSettlement(actor, input, requestId)` | `{ settlementId: string; reason: string }` | `ReleaseReceipt = { settlementId; cohortId; stageKey; stageName; releasedAt; releasedBy: { userId; name }; requestId; serverTime }` | `FORBIDDEN` → `VALIDATION_FAILED`（非 UUID、`reason` 空、**找不到這筆結算**：訊息「找不到這筆結算，請重新整理頁面。」）→ `COHORT_ARCHIVED` → `CONFLICT`「這筆結算已於 {時間} 解除」（`released_at` 已有值）。**舊結算的 `settlementId` 永遠解除不到後來的新結算**：新結算是新的一列、新的 id | `operationKind='grading.release'`，`fingerprint=sha256(canonicalJson({settlementId, reason}))`；audit `grading.release` |
| `GradingQuery.settlementOf(actor, cohortId, stageKey)` | — | `Settlement | null`：`{ settlementId; stageKey; settledAt: Date; settledBy: { userId; name }; reason }`（只回**未解除**的那一筆） | `FORBIDDEN`（學生）；老師與系辦都可讀（老師頁要顯示「已結算」） | 無（查詢） |
| `GradingQuery.settlements(actor, cohortId)` | — | `readonly SettlementHistory[]`：每階段每筆（含已解除）`{ settlementId; stageKey; stageName; settledAt; settledBy; reason; releasedAt: Date | null; releasedBy: { userId; name } | null; releaseReason: string | null }`，依 `settledAt` 降冪 | `FORBIDDEN`（非系辦） | 無（AD-B1 的結算頁列歷史） |

**老師寫入受結算影響的契約**（`saveDraft`／`submitFinal`／Q79 重送）：鎖內重查該屆別×階段未解除結算 → 有就回 `CONFLICT`「{階段名}成績已結算，不能再改。」；`teacherBench`／`teacherQueue` 加 `settled: { settledAt: Date } | null`（老師頁據此唯讀）。系辦的 `returnEvaluation`／更正**不受**結算影響。

**交錯順序保證（整合案例名稱固定，見 §7 與 AC-TE-52）**：

| 案例 | 順序 | 結果 |
|---|---|---|
| `settle-then-submit` | 結算 commit → 老師重送 | 老師 `CONFLICT`；`counted` 不變 |
| `submit-then-settle` | 老師重送 commit → 結算 | 結算成功，`countedEvaluations` 含該次；之後老師再送 `CONFLICT` |
| `resubmit-two-request-ids` | 同一老師兩個 requestId 並行重送 | 兩筆都 `ok`，在指派列排隊依序完成；最後一份 `counted`、其餘 `historical` |
| `resubmit-same-request-id` | 同 requestId 重放 | 回原回執；列數不變 |
| `release-stale-settlement` | 結算 S1 → 解除 S1 → 結算 S2 → 再用 S1 解除 | 第二次解除 `CONFLICT`；S2 仍有效、老師仍被鎖 |

顆粒度 ⏸ D4：建議屆別×階段，表結構 §2 已照此；D4 若改整屆，`stageKey` 改可選並在票內調整唯一索引，介面名稱不變。
