## 觀察（不擋驗收，沒有開修補票）

1. **同意書通知的字樣比規格多「組別＋第 N 版」**：規格 AC-21／AC-23 寫「有一份同意書輪到你同意」「同意書內容已更新，請重新閱讀並同意」，實際是「G07「期中結果確認」第 1 版輪到你閱讀並同意」「G07「期中結果確認」第 2 版內容已更新，請重新閱讀並同意」。跟既有簽核通知同一種寫法，意思一樣；但 AC-22 要求頁面不顯示版本號，通知裡卻有「第 N 版」。要不要拿掉版本號，請主腦決定。**已處理（CL-2 #818，主腦 10/21 代定、Roy 可推翻）**：寄給學生與老師的同意書通知都不再寫「第 N 版」（例：「G07「期中結果確認」同意書輪到你閱讀並同意」「…同意書內容已更新，請重新閱讀並同意」）；只寄系辦的作廢通知與系辦回執仍寫版本號。
2. **`/rules` 有兩個叫「評分方式」的區塊**：示範資料第 8 章的章名是「八、評分方式」，C1-14 新加的評分比例區塊標題也是「評分方式」。用 `getByRole('region', { name: '評分方式' })` 會同時找到兩個（螢幕報讀也分不太清）。`rules-weights.spec.ts:94` 也是這樣找，它自己造的規則沒有這個章名所以沒撞到；在示範資料上會撞。可以考慮把示範第 8 章改名或把區塊標題改成「評分方式與比例」。
3. **五欄的查詢數指令有一條跑不起來**：訪客 `/files` 從 T1 起就轉登入頁，`perf:sql` 對 307 一律 exit 1。本次改成學生身分量 `/files`。之後別的票照抄這條指令會撞到。
4. **本機跑全套 e2e 要帶 `IDENTITY_CACHE_TTL_SECONDS=0`**：`web/AGENTS.md` 的範例有帶，但五欄的「`pnpm -C web verify --integration src test --e2e e2e`」沒寫；不帶會有 2 條身分快取相關的測試紅。
5. **AC-35 的「`LATEST='0021…'`、表數 71」已經被②／③後續的 0022～0024 取代**，驗收時以 migrations 整合測試的現值為準。
6. **`pg-consent-bridge.integration.test.ts:743` 的測試名稱跟內容不一致**：名稱寫「對象加組：新組建包」，但內容斷言的是「加組不會自動建包、系辦補建」（跟主腦裁定、本次回寫的 `設計方案.md` §6.4 一致）。行為沒問題，只是名稱過時；本票只改文件，沒動測試。**已處理（CL-2 #818）**：測試（現在在 :762）改名為「…；對象加組：不自動建包，系辦在看板補建」，內容不動。另外 `web/test/structure/acceptance-matrix.test.ts` 會檢查本表「AC 逐條」每列都有負責票、測試檔存在、測試名稱對得上（不比行號）。
