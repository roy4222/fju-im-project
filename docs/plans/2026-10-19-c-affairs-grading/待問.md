# C 階段規格①— 待問（給 Roy／主腦）

每題附建議答案；規格與票**先照建議答案寫**，Roy 改答案時只動標註的段落。定案表上的 ❓ 項與本份不確定事項都在這裡。

| # | 問題 | 建議答案（規格已照此寫） | 改答案要動哪裡 |
|---|---|---|---|
| Q1 | 學生「交作業」清單要不要像 TronClass 放「成績」欄？ | **不放**。既有定案「學生看不到分數」（`student-zero-visibility.spec.ts` 守著）；欄位改成「截止」。 | 設計方案 §5.1；AC-16 |
| Q2 | 老師評分台的「儲存草稿」（TE-B1 剛做的）要不要跟學生一樣拿掉？ | **留著**，放右欄次要位置。老師一組要填多個細項＋評語，中途被叫走很常見；學生那邊拿掉是因為上傳完就等於存了。 | §7.3；C1-12；指紋 `fingerprints.ts` 老師評分那列不改 |
| Q3 | `placement='requirement'`（需求表）只剩範本與示範一筆，要不要收掉？ | **收進作業**：不改 DB，既有列以作業表單載入；「需求表範本」改叫「作業範本」，新建一律 `submission`。 | §0.4、§1.1；若要真的刪 placement 則 C1-01 改 CHECK、C1-17 改示範資料 |
| Q4 | 定案表 A13「比例等收進進階設定」：作業的進階設定裡要能改評分比例嗎？ | **不能**。比例是評分規則的事（有版本與鎖定）；作業進階設定只**顯示**「評分項目『系統驗收』會看這份作業」＋連到評分規則。對應關係在評分規則那邊選。 | §2.3 進階設定列；AC-26 |
| Q5 | 「系辦可發作業給老師」的名單＝哪些老師？ | **該屆所有啟用中、具老師角色的帳號**（含沒帶組的）。指導意願調查表本來就是要問還沒帶組的老師。 | §3.1 名單定義一句 SQL；AC-7 |
| Q6 | 同意書「下載 PDF 再上傳」＝一個有檔案欄的**個人**作業？還是整組一份？ | **個人**（每人簽一份、各自上傳）。整組一份就跟站內表單的「一組一包」重疊了。 | §6.1；CHECK `consent_mode='upload' → individual` |
| Q7 | 「檔案」分頁要不要能上傳與分類？ | **只列表＋刪未引用**。檔案都是跟著公告／作業上傳的，單獨上傳沒有歸屬；要分類的話等規格④。 | §4.6；C1-16 |
| Q8 | 催繳要不要寄 Email？ | **站內必發、Email 盡力**（寄失敗不重試、不擋站內）。正式站有 Brevo；測試站 `MAIL_CAPTURE=1` 進 outbox。 | §1.5、§8；若只站內則 C1-05 拿掉 template |
| Q9 | 作業到期自動通知（`deadline_snapshot`）現在沒有 handler，所以**不會自動發**；要在本份補嗎？ | **不補**，本份只做手動催繳（A9 原話是「催繳」按鈕）。自動到期通知另開票。 | §1.5 註；拆票末「不做的事」 |
| Q10 | 成果展示分頁右上「新增」要怎麼分？ | 一顆下拉：「作品（本屆某組）」「補登歷屆作品」「榮譽」。 | §4.5；AC-14 |
| Q11 | 內容要不要支援 Markdown？ | **用 Tiptap 的輸入規則**（打 `# `、`- `、`**粗**` 自動轉）＝ Markdown 快捷，不加 markdown 套件、不加「貼 Markdown」模式；原始 HTML 模式照舊。 | §2.3 內容列 |
| Q12 | 前台直接編輯 registry 由②集中定義（②Review 裁定）；①提供的模組介面（§11.3）有沒有跟②對不上？ | **請②核對 §11.3 表**：kind 名稱（`news/resource/rules/honor/submission/showcase`）、`ItemFormProps`、`onDone` 回 `{itemId,status}`、`revision` 用 `ItemDetail.revision`、刷新與 toast 由②做。對不上以②為準，①改模組不改契約。 | §2.2、§11.3 |
| Q13 | 評分項目的「對應作業」與「說明」我放在側表（改了不建新版）；比例、細項、滿分仍走版本。這樣分對嗎？ | **對**（這是 advisor 裁決後的寫法）。另一條路是全部進 jsonb＝改一句說明都要建新版重算，不建議。 | §1.3、§7.4 |
| Q14 | 系辦改同意書內容（#161）：舊的同意一律不算、全部重投，還是讓學生「確認沿用」？ | **一律重投**。法律文件改了就是新文件；「確認沿用」多一種狀態、匯出也要多一欄。 | §6.4；AC-23 |
| Q15 | T2-1 評分細項與配分的**實際內容**（哪幾個評分項目、各幾 %）。 | 規格不寫死，系辦在評分規則頁自己調；示範資料維持 60／40 兩項。Roy 若有定案清單，只要改示範資料（C1-17），不動規格。 | C1-17 |
| Q16 | 同意書作業要不要有「截止時間」？ | **選填**（同意書通常沒有硬截止）；有填就進催繳的逾期判斷，沒填就只能手動催。發布檢查對同意書放寬「截止必填」。 | §2.3 截止列、§3.1 `publishChecks` |
