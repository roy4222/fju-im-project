**為什麼要一張表**：三種信（驗證碼、重設連結、審核結果）都要能在 e2e 與助教驗收時「看得到寄了什麼」，又不能在正式站存驗證碼與重設連結的內文。所以寄信一律先寫一列 `mail_outbox`，正式寄出的列**不存內文**；沒有 Brevo 金鑰的環境（CI、e2e、本機）把內文存進去當「擷取模式」。

- `web/src/application/mail/`（新模組）
  - `ports.ts`：`Mailer { send(message: MailMessage): Promise<Result<MailReceipt>> }`；`MailMessage = { to: string; template: MailTemplate; subject: string; text: string; html?: string }`；`MailTemplate = 'email_otp' | 'password_reset' | 'registration_result'`；`MailReceipt = { outboxId: string; status: 'sent' | 'captured' }`。
  - `templates.ts`：純函式產生三種信的 `subject`／`text`（內容 §3.9）。單元測試。
  - `index.ts` 入口匯出。
- `web/src/infrastructure/mail/brevo-mailer.ts`：讀 `BREVO_API_KEY`、`MAIL_FROM`（例 `專題管理平台 <noreply@roy422.dev>`）、`MAIL_REPLY_TO`（選配）。有金鑰 → 先 insert `mail_outbox`（`status='queued'`，`body_text=null`）→ `POST https://api.brevo.com/v3/smtp/email`（用 `fetch`，逾時 10 秒）→ 成功 `status='sent'`、記 `provider_message_id`；失敗 `status='failed'`、記 `error`（去掉金鑰），回 `err('MAIL_FAILED')`。沒金鑰 → insert `status='captured'`，`body_text` 存全文，回 ok。**Brevo 回應與錯誤訊息一律不含金鑰**（比照 #418 Review 的遮金鑰原則）。
- `web/src/composition/mail.ts`：依環境組出 `Mailer`，給 Better Auth 回呼與 worker 用。
- 資料：`mail_outbox(id uuid pk, to_email text, template text check in (3 種), subject text, body_text text null, status text check in ('queued','sent','failed','captured'), provider_message_id text null, error text null, created_at timestamptz, sent_at timestamptz null)`；索引 `(created_at desc)`。grants：`matrix.json` 加一列（app 可 `select/insert/update`，不給 delete），`generate-grants.mjs` `MIGRATION_BY_SLICE` 加 0015。保存期限見 §8 R5。
- 審核結果通知（Q68）：**沒有現成的事件可以搭**——`application/notifications/events.ts` 沒有註冊核准／退回事件，模組 01 :220 也寫「審核結果不進通知匣（2026-09-12 第六輪）」。所以不走 worker：`web/src/infrastructure/accounts/registration-command.ts` 的 `approve`（:438）、`approveMany`（:682）、`reject`（:760）在交易 **commit 之後** 呼叫 `Mailer.send(templates.registrationResult(...))`（收件人＝申請人的登入 Email）；寄失敗只記 `mail_outbox.status='failed'`、不回滾核准、不回錯給系辦（R6 問 Roy 要不要重試）。站內通知維持不進通知匣（規格不變，只加 Email）。
- 三種信都**同步寄**（使用者或系辦在等），不走 worker；worker 不用改。
- 環境（三組鍵——寄信、Turnstile、GA4——的 `ops/README.md`、`.env.example`、`docker-compose.vm.yml` 改動都由 VB-1 一次加齊，VB-7、VB-8 不碰這三個檔）：Doppler stg／prd 都加 `BREVO_API_KEY`、`MAIL_FROM`；`ops/lib/site.sh:39-45` 的必要鍵**不加**（沒金鑰就是擷取模式，不能讓站起不來），但 `ops/README.md` §7 的表格加兩列並註明「正式站必填，少了就寄不出去」；`docker-compose.vm.yml:47-58` `&app-secrets` 加兩個鍵（app 與 worker 都要）；`.env.example` app 組加兩個名稱並改掉「Turnstile…都不用」那行註解；`web/test/compose/compose.integration.test.ts:154` 目前斷言 compose **沒有** `TURNSTILE_*` 鍵——見 §3.8。

## 7. 效能

依據：效能基準量測 `~/work/perf-out/perf-baseline-2026-10-16.md`（Mac mini，origin/main 5b68058，正式建置；摘要同 `/tmp/eng-lead/perf-audit.out`）。本節只引用與訪客頁有關的數字；後台固定 21 句身分驗證（`_ui/guard.ts` 每頁 3 次）由共用規格處理，本批不改。

**本批頁面要守的預算**（基準報告 §3，共用規格之後若另發預算以其為準）

- LCP 本機 CPU×4 ≤ 1.0 s、測試站 p75 ≤ 2.5 s；載入時 CPU×1 長任務 0。
- 動畫：`prefers-reduced-motion` 自動關；連續動畫主執行緒 ≤ 20%（原型卡頓的來源是 Pixel Trail 每幀 `createRadialGradient`＋`texImage2D`，基準報告 §5；共用若把 Pixel Trail 放進登入／註冊左圖，條件由共用規格定，本批只在桌機且非 reduced-motion 時掛載）。
