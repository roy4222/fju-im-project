### 訪1 需登入的頁面直接導到登入頁

現況：六個前台頁面在匿名時自己渲染 `NeedLogin`（403 畫面）：

做法：這些分支全部改成 `await requireSignedIn(pathname)`（`web/src/app/_ui/guard.ts:51-61`，現成函式）。它已經處理三種人：匿名 → `/login?next=<原路徑>`；待審核 → `/register/pending`；要改密碼 → `/account/change-password`。順便解掉驗收報告 UX-8（待審核帳號在 `/files` 被要求登入）。內文頁只在 `need_login` 時導向；`not_found` 仍走 `notFound()`，`forbidden`（登入後仍無權）仍回 403 畫面。

`pathname` 要帶**含 id 的實際路徑**（例如 `/news/${id}`），登入後才會回到原頁。

拿掉 `NeedLogin` 元件（`web/src/app/_ui/public-content.tsx:386-407`）與它的 `data-testid="need-login"`；改完後 grep 確認沒人再引用。`CodeNotice`（同檔 357-381）留著，訪2 要用。

## 3. 每 IP 跨帳號登入限速（資安票）

### 現況

`web/src/shared/rate-limit.ts` 的 `sharedRateLimiter(name, {max, windowMs})` 是掛在 `globalThis` 的固定視窗記憶體計數器；`web/src/infrastructure/auth/sign-in-rate-limit.ts` 的 `signInKey(ip, email)` 以 **IP＋帳號** 為鍵，`RATE_LIMITS.signIn` 10 次／10 分鐘（`rate-limit.ts:90-117`）。所以同一 IP 換帳號打就繞過了。

### 做法

1. `rate-limit.ts` 的 `RATE_LIMITS` 加 `signInFailuresPerIp: { max: 30, windowMs: 10 * 60_000 }`。
2. `sign-in-rate-limit.ts` 加 `checkIpFailures(ip)`（只看不計）與 `recordIpFailure(ip)`（計一次），鍵只用 IP；`resetSignInLimiter()` 要連這個桶一起清（CI 與整合測試靠它）。
3. `web/src/infrastructure/auth/auth-instance.ts`：
   - `hooks.before` 的 `/sign-in/email` 分支（328-341）在既有帳號桶檢查**之前**先 `checkIpFailures`，超過就丟 `APIError('TOO_MANY_REQUESTS', { message: '這個網路的登入失敗次數過多，請稍後再試。' })`。即使密碼正確也擋。
   - `hooks.after`（435-472）：`/sign-in/email` 且 `returned instanceof APIError` 且狀態是 401（帳密錯），`recordIpFailure(ip)`。429 不計，避免重複累計。既有 468-471「成功登入重置帳號桶」保持；**成功不重置 IP 桶**，否則穿插一次正確登入就能清計數。

**只算失敗、不算嘗試**：校內 NAT 幾十人正常登入不會耗桶，門檻可以收緊。門檻建議 **30 次失敗／10 分鐘／IP**（替代 100／15 分鐘，列待 Roy 決定）。

選用備註：日後若開 Cloudflare proxy，`X-Real-IP` 會全部變成 Cloudflare 位址，每 IP 限速要改讀 `CF-Connecting-IP`（並只信任 Cloudflare 來源的請求才採用這個標頭）。

### 記憶體重啟歸零可接受

與現有帳號桶一樣（契約 03 §6 寫明「app 記憶體」）；重啟一次只讓攻擊者多得一個視窗，和第二段才做的持久化無關。單一容器、沒有多副本，所以不需要 Redis。

### 校內 NAT 誤擋

同一 NAT 出口 10 分鐘內 30 次「密碼錯」才會擋，擋 10 分鐘；正常登入不計。開學週要是真的撞到，調整 `RATE_LIMITS` 一行即可。`clientIpFrom` 沒標頭時回 `'unknown'`：Caddy 有設 `X-Real-IP`（`ops/Caddyfile.vm`），正式環境不會落到這桶；CI 的 Playwright 沒帶標頭會共用 `unknown` 桶，已 grep 全部 e2e 故意打錯密碼只有 4 次（`a1-first-login.spec.ts:110`、`teachers.spec.ts:111,217`、`acceptance/station-1.spec.ts:72`），遠低於 30。

### 測試

新檔 `web/src/infrastructure/auth/ip-sign-in-rate-limit.integration.test.ts`：同 IP 用 31 個不同帳號打錯 → 第 31 次回 429 與中文訊息；之後正確帳密也 429；換 IP 不受影響；成功登入不清 IP 桶；`resetSignInLimiter()` 清光。既有 `sign-in-rate-limit` 相關測試不動。

## 4. 兩站網路拆分

### 現況

`docker-compose.vm.yml:59-61,94-97` 讓 app 同時掛 `default` 與 external `fju-edge`；`docker-compose.edge.yml` 的 Caddy 也在 `fju-edge`。測試站與正式站 app 在同一個網路，彼此可直接連 `fju-prod-app:3000`。

### 做法

- `docker-compose.vm.yml`：external 網路名改成 `fju-edge-${FJU_SITE}`（`name: fju-edge-${FJU_SITE:?}`），其餘不動。
- `docker-compose.edge.yml`：Caddy 掛兩個 external 網路 `fju-edge-test`、`fju-edge-prod`（兩個都要先存在）。
- `ops/vm-setup.sh` 第 5 步（221-227）改成建立兩個網路（冪等），不再建立 `fju-edge`；第 8 步 fake_env 檢查（277-282）與演練檢查 grep（331）改看新名字。
- `ops/Caddyfile.vm` 不用改（`fju-prod-app`、`fju-test-app` 容器名不變，DNS 解析各走自己的網路）。
- `ops/README.md` 網路說明、同步步驟補一行。

### 上線步驟（測試站在跑、正式站未部署）

`ops/deploy.sh` 沒有「同版就跳過」的提早結束（整檔 grep 過，只有回滾的 skipped），而且 `docker compose up -d` 看到網路或環境變數變了就會重建容器，所以**重部署目前的 SHA 就能把測試站 app 換到新網路**。`FJU_SITE` 已由 `ops/lib/site.sh:63` export，compose 檔裡的 `${FJU_SITE:?}` 拿得到，`lib/site.sh` 不用改。

採零停機順序：Caddy 先同時掛舊網路＋兩個新網路，測試站換好後 Caddy 再拿掉舊網路（多一次 Caddy 重建，每次閃斷數秒）。需要 Roy 親自（sudo）：

```bash
# Mac：同步 compose 與 ops 到 VM（ops/README.md:520-533 的既有程序）
rsync -a docker-compose*.yml ops/ gtuser@140.136.155.167:/tmp/fju-app/
# VM
sudo rsync -a --delete --chown=deploy:deploy /tmp/fju-app/ /srv/fju/app/
sudo bash /srv/fju/app/ops/vm-setup.sh          # 建 fju-edge-test、fju-edge-prod（舊 fju-edge 先留著）
# 過渡：edge.yml 這一版讓 Caddy 掛 fju-edge＋fju-edge-test＋fju-edge-prod
docker compose -p fju-edge -f /srv/fju/app/docker-compose.edge.yml up -d            # Caddy 重建，兩站閃斷數秒
sudo -u deploy /srv/fju/app/ops/deploy.sh --site test <目前測試站部署的 SHA> --execute   # 測試站 app 重建進 fju-edge-test
# 收尾：把 edge.yml 的 fju-edge 拿掉（T4 的最終版），再重建一次 Caddy，然後刪舊網路
docker compose -p fju-edge -f /srv/fju/app/docker-compose.edge.yml up -d
docker network rm fju-edge
```

T4 的 PR 要同時附過渡版與最終版的 `docker-compose.edge.yml`（最終版進 main，過渡版放 `ops/README.md` 的步驟說明裡），或由 Roy 在 VM 上手動多加一行 `fju-edge` 再刪掉。

停機：Caddy 重建兩次各閃斷數秒；測試站 app 重建期間（拉映像已快取，約 30–60 秒）舊容器會先被停掉，這段測試站 502；正式站本來就未部署，無影響。若接受測試站停 1–3 分鐘，可省略過渡版，直接 Caddy 換新網路再重部署測試站。排在驗收試跑之後做，避免與「鎖版本」衝突。

驗證：`docker network inspect fju-edge-test` 只有 caddy＋fju-test-app；`docker exec fju-test-app getent hosts fju-prod-app` 必須查不到。

### 測試

`vm-setup.sh` 的 fake_env `docker compose config` 檢查就是它的測試；本機 `docker compose -f docker-compose.yml -f docker-compose.vm.yml config` 用假環境跑一次。

## 5. 註冊開關（資安票）

### 放哪裡：環境變數（建議）vs 系辦後台設定

| | 環境變數（Doppler → compose） | 資料庫設定＋系辦後台開關 |
|---|---|---|
| 改動 | 一個變數、一個讀取函式 | 新資料表／欄位、migration、後台頁、權限、操作紀錄 |
| 切換 | 改 Doppler 再重部署（分鐘級） | 系辦即時切 |
| 誰切 | Roy | 系辦 |
| 風險 | 忘了同步兩個 config | 多一個可被誤按的開關 |

第一段只翻一次（正式站關、第二段開），**選環境變數**。變數名 `REGISTRATION_OPEN`，值 `true`／`false`；stg＝`true`、prd＝`false`。**未設定時視為開放**，所以 CI／本機 e2e（`web/e2e/session.ts:57` 靠 `/api/auth/sign-up/email` 註冊）不用改。

陷阱：若照專案慣例寫 `${REGISTRATION_OPEN:?}` 並加進 `FJU_REQUIRED_SECRETS`（`ops/lib/site.sh:39-45`），Roy 沒先在 Doppler stg／prd 加鍵，測試站下一次部署就會失敗。所以這張票排第二波，而且 **Roy 要先在 Doppler 加鍵**（agent 寫 Doppler 會被擋）。


兩個 job 共用的檢查（寫成 workflow 的 `env.CHECK` 或複製兩份都可以）：

```bash
url=$1
code=$(curl -s -o body.json -w '%{http_code}' --retry 3 --retry-delay 30 --retry-all-errors "$url")  # 近似「連續 3 次」
echo "$url -> HTTP $code"; cat body.json
[ "$code" = 200 ] || exit 1
jq -e '.ok == true and .commit != null
       and .worker.lastTickAt != null
       and ((now - (.worker.lastTickAt | sub("\\.[0-9]+Z$"; "Z") | fromdateiso8601)) < 300)' body.json
```

`fromdateiso8601` 不吃小數秒，`lastTickAt` 是 `toISOString()` 格式會帶 `.123Z`，所以先 `sub` 掉；`lastTickAt` 為 null 先擋，不然 jq 直接 error（`web/src/shared/health.ts:27-32`：本機沒 worker 時可能是 null，正式環境有 worker 不應為 null）。

- 檢查欄位：HTTP 200、`ok === true`、`commit` 非空、`worker.lastTickAt` 在 5 分鐘內（`web/src/shared/health.ts` 的 `WORKER_STALE_AFTER_MS`）。
- 通知：GitHub Actions 失敗會寄信給 workflow 檔最後一次 commit 的人；Roy 要確認 GitHub 通知設定開著「Actions: failed workflows only」。不另接 email 服務。
- 正式站開站前避免誤報：prod job 由 repository variable `HEALTH_PROD_ENABLED` 控制，預設不存在＝整個 job skipped（Actions 列表看得到）；開站當天 Roy 在 GitHub Settings → Variables 設 `true`。測試站一直跑。
- 「還沒開站」vs「掛了」：prod 被變數關掉時 job 直接 skip（綠），開站後才會因 502 變紅；log 第一行印 URL 與 HTTP 碼。
- 風險：GitHub 在 repo 60 天沒 commit 時會自動停用排程 workflow；每 10 分鐘一次每月約 4,300 分鐘 Actions 額度（公開 repo 免費）。

### 14-1 附件網址回 403／401 JSON（N-21、N-26）→ 新票 T13（資安票）

**現況**：`web/src/app/api/files/[id]/route.ts` 是下載用的 Route Handler，授權失敗一律回 JSON（沒登入 401 `UNAUTHENTICATED`、沒權限／已下架／不存在 403 `FORBIDDEN`、500 `INTERNAL`）。瀏覽器網址列直接開（訪客收到分享的附件連結、下架公告的舊附件連結）就看到一行 JSON，沒有登入入口也沒有中文說明（story-2 第 30 步、story-4 第 28 步截圖）。

**要分清兩種客戶**：

| 客戶 | 怎麼認 | 失敗時回什麼 |
|---|---|---|
| 瀏覽器**導覽**（網址列、點 `<a href>`） | `sec-fetch-dest: document`；沒有這個標頭的舊瀏覽器看 `accept` 含 `text/html` | **導向頁面**（下表） |
| 程式抓取（`fetch`、Playwright `request.get`、curl）、`<img src>`（`sec-fetch-dest: image`） | 以上皆非 | **維持今天的 JSON 與狀態碼，一個位元都不改** |

導向對應（只在「瀏覽器導覽」時）：

| `result.code` | 導向 | 為什麼 |
|---|---|---|
| `UNAUTHENTICATED` | `/login?next=%2Fapi%2Ffiles%2F<id>`（`encodeURIComponent`） | 與 T1 的 `requireSignedIn` 同一條路；`safeNextPath` 接受站內相對路徑，登入成功後 `login/page.tsx:33` 會 `redirect(next)`，瀏覽器直接拿到下載 |
| `FORBIDDEN`（不是你的、已下架、不存在三者**同一個碼**） | `/403` | 保住 route 註解的不變量「沒有這個檔跟不是你的回一模一樣」；`/403` 已是中文、有「回到自己的首頁」「回前台首頁」（T11 只改標題，T13 不碰那個檔）。訪客不會落到這裡：匿名一律是 `UNAUTHENTICATED`（`roster-import.spec.ts:121` 連不存在的 id 也 401） |
| `INTERNAL` | 不導向，維持 500 JSON | 罕見，導去哪裡都不對 |

**做法**（只動 route.ts）：

```ts
// 瀏覽器直接開（網址列、點連結）才導頁；程式抓取與 <img> 維持 JSON，e2e 與封面預覽不受影響。
function isDocumentNavigation(headers: Headers): boolean {
  const dest = headers.get('sec-fetch-dest')
  if (dest) return dest === 'document'
  return (headers.get('accept') ?? '').includes('text/html')
}

if (!result.ok) {
  if (result.code !== 'INTERNAL' && isDocumentNavigation(request.headers)) {
    const location = result.code === 'UNAUTHENTICATED' ? `/login?next=${encodeURIComponent(`/api/files/${id}`)}` : '/403'
    return new Response(null, { status: 303, headers: { ...PRIVATE, location } })
  }
  // 以下原樣
}
```

- **不用** `next/navigation` 的 `redirect()`：它不能帶標頭，而這條導向**必須**有 `cache-control: private, no-store`（`PRIVATE` 已有），否則匿名時快取住的導向會在登入後把人彈回登入頁。相對路徑 `Location` 合法（RFC 9110 §10.2.2），不要用 `request.url` 組絕對網址（容器內是 `http://app:3000`，會導錯主機）。狀態碼 303（GET 導 GET）。
- 文件依據：`web/node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route.md` §Redirects 只示範 `redirect()`；手組 `Response` 是 Route Handler 的基本能力，不需要新 API。
- `sec-fetch-dest` 經 Cloudflare proxy 與 Caddy 都原樣轉送（一般請求標頭）。

**既有測試不受影響的理由**：`affairs.spec.ts:214-220`、`public-pages.spec.ts:307-314,423,439`、`group-submit.spec.ts:309,380-395`、`history-matrix.spec.ts:176-179,289-342`、`roster-import.spec.ts:121`、`admin-daily-ui.spec.ts:116` 全部用 `page.request.get` 或 `request.newContext().get()`（Node 端 fetch：`Accept: */*`、沒有 `sec-fetch-*`），走 JSON 分支。repo 裡沒有 `page.goto('/api/files/…')`。
