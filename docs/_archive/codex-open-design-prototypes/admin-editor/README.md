# 管理員統一專題事務編輯器 — Throwaway UI Prototype

> **PROTOTYPE ONLY**：自包含假資料互動稿，不是 production code，不含後端、登入或真實學生資料。

## 開啟方式

直接雙擊 `index.html` 即可在瀏覽器開啟，不需安裝套件或啟動伺服器。

也可直接指定版本：

- `index.html?variant=A`：左元件／中 canvas／右設定
- `index.html?variant=B`：頂部發布位置／全寬 canvas
- `index.html?variant=C`：項目列表／右側 quick-edit drawer

畫面底部固定的「原型切換器」、左右按鈕，以及鍵盤 `←`／`→` 都能切換版本。游標在輸入欄位時，方向鍵不會切換版本。

## 共用假資料模型

三版不是三套資料；它們共用同一組 in-memory `專題事務項目`：

1. 公告：`114 學年度專題分組說明會`
2. 含附件資源：`專題企劃書格式與範例`
3. 整組文件繳交：`第一次專題企劃書繳交`
4. 專題需求：`專題方向與設備需求調查`

每筆資料只有一個 `primaryLocation`。Dashboard、截止日元件、首頁摘要與站內搜尋以「自動曝光」表示，並不建立第二筆內容。

## 可以真的操作的部分

- 用元件庫或 quick add 新增內容區塊／填寫欄位。
- 用每個區塊旁的 `↑`／`↓` 重排。
- 修改主要發布位置、發布對象、標題、摘要、截止時間與選取元件設定。
- 在「編輯／訪客／學生」之間切換前台視角；私有內容在訪客視角會顯示權限閘門。
- 發布項目並取得包含回執編號、位置、對象與時間的完成回執。
- 展開頁面下方「狀態檢視」查看目前資料的 JSON 摘要與最後操作。
- Variant C 的「＋ 新項目」會建立一筆新的 in-memory 公告。

所有變更只存在記憶體；重新載入頁面會重設。Autosave 狀態刻意模擬「儲存中… → 已儲存」。

## 行動版

在約 390px 寬度：

- A 改為「元件 → 內容 → 設定」三步驟流程。
- B 保留全寬 canvas，項目設定改由 bottom sheet 開啟。
- C 先顯示可閱讀的項目卡片列表，選取後由 bottom drawer 快速編輯。

## 原型邊界

- 無 backend、auth、資料庫、上傳服務或持久化。
- 無任意 JavaScript／SQL／公式或條件流程編程能力。
- 不包含營收、訂閱、轉換率等不相關 KPI。
- 搜尋框與下載／上傳按鈕只呈現資訊架構，會明確維持停用或展示狀態。

## Smoke check

本原型可用 Node.js 對 inline JavaScript 做語法檢查，並檢查 HTML 中三個 variant、必要互動與 390px breakpoint 是否存在；不需要任何第三方套件。
