# 公開前台 UI prototype

> **PROTOTYPE ONLY** — 拋棄式、唯讀、全是假資料；不是 production 前台，也沒有登入、資料庫或檔案下載。

這份單頁原型用同一批內容比較三種真正不同的首頁資訊層級，回答：系網品牌 editorial、消息／近期截止優先、歷屆專題 showcase，哪一種最能讓舊站的重要資訊變得好找？

## 開啟方式

直接雙擊 `index.html` 即可，不需安裝套件或啟動伺服器。

- `?variant=A`：系網品牌 Editorial。品牌敘事與主題消息為首屏，截止日放在編輯式側欄。
- `?variant=B`：消息／近期截止優先。第一屏直接呈現三個時程，再接公告工作區。
- `?variant=C`：歷屆專題 Showcase。先進入作品展間，再串回時程、公告與規則。

可以用固定底部的「原型切換器」、左右箭頭按鈕，或鍵盤 `←` / `→` 循環切換。切換結果會寫回 URL 的 `variant` query，方便分享同一版；若個別瀏覽器限制 `file://` 的 History API，畫面仍會正常切換，只是不更新網址。

## 可操作範圍

- 公告分類：全部、專題事務、競賽、活動、規則。
- 專題年度：全部屆別、2025、2024、2023。
- 手機導覽：在窄螢幕展開／收合單層選單。
- 登入／註冊入口：只開啟流程說明，不接受帳密也不送出資料。
- 規則摘要：A 版可展開目前版本的示意重點。

每次操作都會更新固定的「狀態檢視」面板；重新載入後篩選狀態可以重設。公告、近期截止、產學合作、歷屆／優秀專題、榮譽、規則與登入入口在三版都保留。

## 評估方式

請至少以 1440px 桌機與 390px 手機寬度各看一次，並記錄：

1. 五秒內最先注意到什麼？
2. 能不能一次找到公告、下一個截止、作品與登入？
3. 想保留哪一版的首頁 hierarchy、導覽、卡片密度與色票？

原型 winner 選定後，應把決策重寫進正式 app；不要直接把這份 throwaway HTML 當成 production code。

## Smoke check（2026-08-17）

- HTML：`tidy -errors -quiet -utf8` 通過。
- JavaScript：inline script 可成功編譯，沒有語法錯誤。
- Runtime：A 版以 390×844、B／C 版以 1440×1000 在 headless Chrome 直接開啟 `file://`，三版皆渲染成功，必要內容區塊與切換器皆存在，未偵測到 runtime exception。

這是基本執行驗證，不代表三個視覺方向已被產品決策接受。
